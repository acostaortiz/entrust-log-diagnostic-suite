IdentityGuard Server 13.0 Administration Guide

RBA case study

This section provides a case study that demonstrates some of the RBA tests, and how to troubleshoot problems.

In this case study:

●       You have set up an RBA Authenticate User test with the settings shown in the following screen capture:

With the settings show above, the IP Blacklist, Country Blacklist, Location History, and Velocity tests must all pass in order to authenticate the user.

●       You have added the US as a country in your expected IP list.

After this setup, Entrust IdentityGuard attempts to authenticate a user with a public IP from the US, but the authentication fails. The debug logs contain the following message:

[2009-12-18 09:28:37,918] [http-8080-Processor23] [DEBUG] [IG.SYSTEM.RBAuthentication.API] IP: IP Blacklist=null, Country Blacklist=null, Velocity=true, Location History=null

Notice that three of the tests return a null value—IP Blacklist, Country Blacklist, and Location History—indicating they were not run. Only the Velocity test returns true, indicating it was run and passed.

Because only one test passed (the Velocity test), and your RBA policy required all four tests to pass in order for Test 1 to be satisfied, the user is not authenticated.

Note: As an alternative, you could enable the IP Authentication check box at the root level. With this configuration, if any one of the underlying tests passes, then the overall test passes, and the user is authenticated. Another alternative is to use does not fail option, which ensures that a null result does not cause the overall test to fail.)

The reason the Velocity test was run is because the user had a public IP address, and the Velocity test is always run when a user has a public IP address.

The reason the other tests were not run is because:

●       The IP blacklist test is only run if the IP address does not match one of the expected locations. In the above case, the user had an IP address from the US, which was on the expected IP list. Consequently the IP Blacklist test was not run and returned a null.

●       The Country blacklist test is only run if the user’s IP address does not match one of the expected locations, and the IP address is a public IP address (since only public IPs can belong to a country). In the above case, the user’s IP was on the expected locations list, so the test was not run and returned a null.

●       For details on preliminary checks, see Preliminary checks and how they affect subsequent tests.
