IdentityGuard Server 13.0 Administration Guide

Step 23: Add users

User accounts must be created in two systems:

●       Entrust IdentityGuard*

●       Security Manager CA (if you are using a Microsoft CA, there is no need to add users to this CA)

* These accounts must include email addresses for users who want secure email digital IDs.

There are two approaches to adding users (and email addresses):

●       Have users add themselves (and their email addresses), on an as-needed basis.

●       Bulk-load them.

You can use a combination of these methods. For example, you can bulk-load user accounts, but have users add their email addresses themselves.

See the following sections for instructions:

●       To have users add themselves to Entrust IdentityGuard

●       To bulk-load users into Entrust IdentityGuard

●       To have users add themselves to Security Manager

●       To bulk-load users into Security Manager

To have users add themselves to Entrust IdentityGuard

1.      Configure registration through Self-Service, and enable the Create Entrust IdentityGuard User property. This property is available in the Self-Service Configuration interface, under Properties > Generic JAAS Login Configuration.

2.      If you are deploying secure email digital IDs, perform these additional tasks:

a.      Configure registration to ask for an email address. You can configure this through the Self-Service Configuration interface, under Registration > Personal Information. See the Self-Service Installation and Configuration Guide for details on these properties and settings.

b.      Ensure that users’ email addresses match what is in the Email Domains field in Self-Service. For example, if users’ email address look like this...

alice@company.com

alice@example.com

 

...then company.com and example.com must be listed in the Email Domains field. For details on this field, see To configure general digital ID properties.

To bulk-load users into Entrust IdentityGuard

1.      Bulk load the user accounts using the Create users bulk operation.

2.      If you are deploying secure email digital IDs, do these additional tasks:

a.      Bulk load email addresses using the Create contact information for users bulk operation. For detailed instructions, see Performing bulk operations in the Administration interface.

b.      Ensure that users email addresses match what is in the Email Domains field in Self-Service. For example, if users’ email address look like this:

alice@company.com

alice@example.com

 

...then company.com and example.com must be listed in the Email Domains field. For details on this field, see To configure general digital ID properties.

Note: You can use one data file for both operations. The file would contain columns for user account and contact information. The chosen bulk operation ignores any columns that it does not need to use.

To have users add themselves to Security Manager

1.      Enable Create User If Not Exists in the digital ID configuration. See Step 10: Add a digital ID configuration for details.

When Create User If Not Exists is enabled, when users click the I’d like to request a digital ID link in Self-Service, a user account is created for them in Security Manager if one does not exist yet. The user and corresponding digital ID are created using the building blocks specified in the digital ID configuration.

To bulk-load users into Security Manager

1.      Bulk-load users using Security Manager Administration. For details, see the bulk operations section of the Entrust Authority Security Manager Administration User Guide.
