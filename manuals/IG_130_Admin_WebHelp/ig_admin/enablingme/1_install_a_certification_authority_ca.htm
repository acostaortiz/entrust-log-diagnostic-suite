IdentityGuard Server 13.0 Administration Guide

1: Install a Certification Authority (CA)

The CA is the component that generates certificates (digital IDs).

Entrust IdentityGuard supports the following CAs:

●       Entrust Authority Security Manager

●       Microsoft CA, on Microsoft Windows Server, Enterprise edition

●       CAs integrated through Entrust CA Gateway. This support is introduced in Entrust IdentityGuard Release 13.0. At the time of this release, only the integration of Microsoft CA through CA Gateway has been certified.

To install Entrust Authority Security Manager

1.      Install the software according to the instructions in the Entrust Authority Security Manager Installation Guide. This guide can be found at https://trustedcare.entrust.com.

The guide steps you through the installation of Security Manager, as well as its supporting components, including a database and LDAP directory.

If you are using Security Manager, users must have a user account in Security Manager for mobile enrollment, however, there is no need to pre-load them if they do not already exist. Instead, you can have user accounts created in Security Manager when users request their digital IDs. This is explained in detail later in this guide.

To install Microsoft CA

1.      Before installing Microsoft CA, read the following restrictions:

Restrictions when using a Microsoft CA

●       Only the enterprise version of the Microsoft CA can be used. The stand-alone version is not supported

●       The Microsoft Certificate Services CA must be installed on Windows Server 2008 R2 server or later.

●       Entrust IdentityGuard and the Microsoft PKI must be located in the same domain.

●       Any user running an Entrust IdentityGuard service must have an account in the domain where the Entrust IdentityGuard server is located, and have the following permissions at the CA: Issue and Manage Certificates, and Request Certificates.

●       For Entrust IdentityGuard to support multiple Microsoft CAs, the CAs must all be in the same domain or in a subdomain.

●       Key archiving and key recovery are not supported.

Note: These restrictions apply to the mobile enrollment feature, even though they are listed in a smart credentials-related section.

2.      Enable the CA, according to the instructions in http://technet.microsoft.com/en-us/library/cc731183.aspx.

For a Microsoft CA, there is no need to have user entries in Active Directory prior to issuing mobile digital IDs.

To install Entrust CA Gateway

1.      Install the software according to the instructions in the Entrust CA Gateway 2.0.1 Operations Guide. Information about using CA Gateway for smart credentials can be found in the Entrust IdentityGuard Smart Credentials Guide for Release 13.0. or newer.
