IdentityGuard Server 13.0 Administration Guide

Configure lockout policies

A user becomes locked out when they enter incorrect login information too many times. For a detailed discussion on lockouts, see IP/Geolocation policies.

Through the Administration interface, you can set lockout policies, which determine the behavior of the lockouts.

To configure lockout policies

1.      Log in to the Entrust IdentityGuard Administration interface as the administrator.

On the Windows computer where Entrust IdentityGuard is installed

●       Select Start and expand Entrust  IdentityGuard in the list of applications. Select Administration Interface. For other login scenarios, see Log in and out of the Administration interface.

On Linux or from a remote client

●       Enter the URL of your Administration interface web application in a Web browser. It has this form:

https://<hostname>:<port>/IdentityGuardAdmin

Where:

<hostname> is the host name you selected during configuration

<port> is the administration port you selected during configuration

If you cannot find the correct URL, see Locate your Administration interface URL.

For other login scenarios, see Log in and out of the Administration interface.

2.      In the main menu, click Policies.

A list of all policies appears on the List Policies tab.

3.      Click any policy name to view its policy information.

The View Policy page appears and lists all policy settings.

4.      From the Policy Category drop-down list, select Lockout .

Lockout Mode

A lockout mode is the logic that Entrust IdentityGuard uses to calculate whether to  prevent further authentication attempts after a user has made a configured number of unsuccessful attempts. There are three lockout modes:

•  Lock Authenticator (Authenticator Counter)

With this option, Entrust IdentityGuard tracks incorrect authentication attempts using individual lockout counters for each authenticator (for example, grid, Q&A, and so on). With each failed authentication attempt with a specific authenticator, the number of remaining attempts that are allowed with it is reduced by one. If the counter reaches zero, the user is locked out and cannot attempt further authentications with that authenticator.

•  (Default) Lock User (Authenticator Counter)

With this option, as with the previous option, there are individual counters for each authenticator and each password type. If any one of the individual counters reaches zero, then the user is locked out of all authenticators.

•  Lock User (Global Counter)

With this option, there is a single, global, lockout counter that tallies up all incorrect authentication attempts using any authenticator. If the global counter reaches zero, the user is locked out of all authenticators.

For details about these options, see Lockout modes and examples.

See also Switching lockout modes for the ramifications of switching between modes.

Lockout Period

Determines how long the lockout lasts. There are two options:

•  Until Unlocked By An Administrator (default)

The lockout remains in effect until an administrator unlocks the user. For details on unlocking the user see Unlocking accounts

•  Number of minutes

The lockout remains in effect for a specified number of minutes. There is one lockout period for all authenticators. For example, you cannot set the lockout period to 15 minutes for grid and 20 hours for OTP.

Despite having a single lockout period, it is possible to have staggered lockouts if you set your Lockout Mode (see previous table cell) to Lock Authenticator (Authenticator Counter). With this lockout mode, separate timers are kept for each authenticator, and staggered unlocks will occur as a result. For example, if you set the Lockout Period to 10 minutes, and you lock yourself out of grid at 2 pm and token at 2:05 pm, the grid will become unlocked at 2:10 pm while the token will become unlocked at 2:15 pm.

For the Lock User (Authenticator Counter) lockout mode, there are individual timers for each authenticator; however, the behavior of this lockout mode is such that the first locked out authenticator locks the user out of all authenticators. Thus only the timer for the first authenticator will ever be set, so there is no staggered unlocking.

For the Lock User (Global Authenticator) lockout mode, a single timer is kept for all authenticators, so there is no staggered unlocking.

Each of the remaining policy settings specifies the lockout counter for failed login attempts with a specific authentication method. The counter is decremented on each consecutive failed authentication attempt with the same authentication method. When the counter reaches zero, the user is prevented from a making further authentication attempts with that authenticator (locked out). Depending on the lockout mode you selected, the user might also be locked out of all other authentication methods (default), or able to attempt to login with another authentication method.

For details on each setting, see Lockout policies.
