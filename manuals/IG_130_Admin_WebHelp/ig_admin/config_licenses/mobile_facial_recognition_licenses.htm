IdentityGuard Server 13.0 Administration Guide

Mobile Facial Recognition licenses

Currently, this feature is supported only in the Android and iOS versions of the Entrust IdentityGuard mobile apps.

This license is not required for Face ID on iPhone X and later models of iPhone.

Entrust IdentityGuard keeps track of the number of users licensed to use facial recognition biometrics with mobile soft tokens and mobile smart credentials. The feature is used as an alternative to a PIN.

For mobile soft tokens, one license makes the feature available for all of the user's soft tokens. If any of the soft tokens requires a PIN, the same protection (PIN, or one of the PIN alternatives, face recognition or fingerprint recognition) is used for all of the tokens in the app. Face recognition is used to unlock the app for use.

Note: A user can enable only one biometric PIN alternative at a time. That means that a user can enable either face recognition or fingerprint recognition (Fingerprint ID in the Android app, Touch ID in the iOS app), but not both.

For mobile smart credentials, one license makes the feature available for all of the user's smart credentials, however, it is up to the identity provider policy settings to dictate whether face recognition is permitted in place of a PIN to enable use of the smart credential. For users, this means that to authenticate with some smart credential identities they must enter a PIN and for others they might be able to use face recognition.

Notes:
A user can enable only one biometric PIN alternative at a time. That means that a user can enable either face recognition or fingerprint recognition (Fingerprint ID in the Android app, Touch ID in the iOS app), but not both .

iPhone X does not support Touch ID and the Entrust IdentityGuard Mobile Smart Credential app uses the iPhone X native Face ID feature. Use of Face ID on iPhone X does not require a Mobile Facial Recognition license. Due to the requirements of the underlying technology, use of iPhone X Face ID is controlled by the Smart Credential policy, Mobile Smart Credential Allow Fingerprint Authentication. For iOS devices that support both touch ID and facial recognition (pre-iPhone X), the facial recognition feature is enabled using the Smart Credential policy Mobile Smart Credential Allow Facial Authentication and does require a license   

The tracking is performed as follows:

●       When a user who already has an active mobile soft token or mobile smart credential enables the Use Face Recognition setting in the app, a license is consumed. If a user has both a soft token app and a smart credential app, one license is consumed for each app with the feature enabled.

●       If a user creates additional soft tokens or registers additional smart credentials, there is no change to the license count. The feature is available for all soft tokens or smart credentials held in the app.

●       When all of a user's mobile soft tokens are deleted from Entrust IdentityGuard, the Mobile Facial Recognition license count decreases by one for the license associated with the soft token app. The same is true for smart credentials and the smart credential app.

●       When a user who had mobile soft tokens or mobile smart credentials in an app protected with facial recognition is deleted from Entrust IdentityGuard, the Mobile Facial Recognition license count is decreased by one.

●       Canceling all soft tokens or smart credentials for a user does not decrease the license count. To decrease the license count, all of the user's mobile soft tokens or mobile smart credentials must be deleted, or the user who is licensed to use the facial recognition feature of the mobile app must be deleted from the system.

Note: Once a user has been licensed to use the mobile facial recognition feature, the user can continue to use the feature even if 1) the policy that governs that user is edited to disallow use of facial recognition, or 2) the user is moved to a group whose policy does not allow facial recognition. However, after the last of the user's soft tokens or mobile smart credentials has been deleted and the license returned, any new soft tokens or smart credentials created are governed by the user's current group policy settings
