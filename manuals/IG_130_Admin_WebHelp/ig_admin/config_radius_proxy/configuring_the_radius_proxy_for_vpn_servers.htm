IdentityGuard Server 13.0 Administration Guide

Configuring the Radius proxy for VPN servers

You can configure one or more VPN connections for use with the Entrust IdentityGuard Radius proxy.

Depending on your policy settings for authentication and your client application, you can use a Radius server, an external authentication resource, or an Entrust IdentityGuard password for first-factor authentication. You can also set the Radius proxy to bypass first-factor authentication, or to bypass second-factor authentication if users do not yet exist in Entrust IdentityGuard, or if users belong to a configurable set of LDAP or Entrust IdentityGuard groups.

You can also associate specific predefined VPN group names with existing Entrust IdentityGuard group names. If this is something you are considering, read Configuring the Radius proxy for groups before you begin to configure the Radius proxy.

Attention: Entrust IdentityGuard rejects any VPN server configuration that creates an explicit or implied duplicate VPN server and port combination. An explicit duplicate occurs when you specify the same port more than once for the same VPN server. An implied duplicate occurs if you use the default port more than once for the same VPN server.

Use the Properties Editor to set up and modify any VPN connections used by the Radius proxy.

Use the following procedures:

●       To configure VPN connections

●       To modify a VPN connection

●       To remove a VPN connection

To configure VPN connections

1.      Log in to the Entrust IdentityGuard Properties Editor.

2.      On the Table of Contents, click VPN Server Configuration.

3.      In the empty field below Configuration Instances, type a unique instance name and click Add.

This provides a unique label used by Entrust IdentityGuard to refer to this server. The label can be anything you choose, such as the name of your VPN server or the name of a VPN user group.

The pane expands to reveal available VPN properties. Most properties include default settings. Only the VPN Host and VPN Shared Secret properties are required. Others are required depending on which first-factor authentication method you intend to use.

4.      In the VPN Host field, enter a host name using a VPN server host name or IP address, or a range of IP addresses in a CIDR. You can specify multiple hosts in a space-separated list. All hosts specified in a single configuration instance share the same configuration details, for example, the same VPN Shared Secret, and the same port number, if specified

For more information about specifying multiple VPN hosts, including using ranges of IP addresses, see VPN Server Configuration.

5.      In the Radius Proxy Port Used By VPN field, type the Entrust IdentityGuard Radius port to be used by all the VPN servers defined in this instance.

The default is the port you set in the Radius Proxy Port field of the Radius Proxy Configuration pane (see Configuring the Radius proxy configuration). If you enter a specific port here, any communication from this VPN server uses that port only. Enter a specific port if you want the current VPN configuration and port to apply to an Entrust IdentityGuard group, as determined by the Entrust IdentityGuard User Group property.

6.      If you are using Radius attributes to differentiate VPN instances, configure the following settings:

●       Radius Attribute ID Used to Identify the VPN – Specify the numerical Radius attribute ID (for example, 30 for CALLER-STATION-ID) used in the initial request to identify the VPN Server associated with this configuration. If this setting is specified, the associated attribute type and expression properties should also be configured.

●       The Type of the Radius Attribute ID Used to Identify the VPN – Specify the type of Radius attribute comparison to perform to identify the VPN Server associated with this configuration. There are 2 options: STRING and HEX. HEX should be used if the values from the Radius request message are sent in binary form. The default is STRING.

●       The Value of the Radius Attribute ID Used to Identify the VPN – Specify the value for the Radius attribute ID above. The value can be a wildcard-based expression that allows pattern matching (for example, *test* or A0*D4). This value should be represented as a string or using hexadecimal characters (for example, A0B1C2D3). All expressions are case insensitive.

For more information about these properties, see VPN Server Configuration.

Entrust IdentityGuard Radius proxy identifies a VPN server by its host name, the Radius port to which it sends messages, and the Radius Attribute ID value supplied by the initial Radius message.

For all those VPN server configurations that match the host name, Entrust IdentityGuard Radius Proxy goes through the following selection process, and the first matching VPN server configuration that is found is used for the request.

–  If a port and Radius Attribute ID value are specified in the VPN server configuration, a check for a match is performed on both.

–  If a port is specified in the VPN server configuration and a Radius Attribute ID value is not, a check for a match is performed on the port.

–  If a Radius Attribute ID value is specified in the VPN server configuration and a port is not, a check for a match is performed on the Radius Attribute ID value

–  If a port and Radius Attribute ID value are not specified in the configuration, a match is found.

7.      If you have already defined Entrust IdentityGuard user groups, you can set a specific Entrust IdentityGuard group for use with the current VPN server in the Entrust IdentityGuard User Group field.

Group names are useful if you want to associate different first-factor authentication methods with specific groups.

You do not need to enter a group name if the names of users are unique in your system; Entrust IdentityGuard determines the correct group. See Matching a group to a user for an explanation.

8.      In the VPN Shared Secret field, type the VPN server secret. This secret must match the server secret already set for the VPN server. Leave the Encrypted option selected so that Entrust IdentityGuard stores an encrypted version of the secret.

9.      In the VPN Application Name field, specify the application name sent to Entrust IdentityGuard in authentication requests. If no name is specified, the default name is used (Entrust IdentityGuard Radius/<vpnname> where <vpnname> is the name of this VPN definition).

10.  In the VPN Character Set field, select the character set used to decode user names sent by the VPN server and to encode messages sent back to the server. Select one of the options: UTF-8 or ISO-8859-1.

11.  Set Radius Proxy Converts Backslash to True if you need to conform VPN user names that include a backslash to work with Entrust IdentityGuard. When enabled, it converts group and user name pairs in the form “group\name” coming through the Radius proxy into the form “group/name.”

12.  Set Radius Proxy Converts At Sign to True if you need to conform VPN user names that include the @ character to work with Entrust IdentityGuard. When enabled, converts group and user name pairs in the form “name@group” coming through the Radius proxy into the form “group/name.”

13.  Set Radius Proxy Removes Group for 3rd-party Radius to True to have the group stripped out of the user ID before the request is forwarded to a third-party Radius server for first-factor authentication.

Note: If Radius Proxy Removes Group for IdentityGuard is set to True, the VPN server must use the PAP protocol, and user names in Entrust IdentityGuard must be unique across all Entrust IdentityGuard groups.

Note: If set to True, this property works as intended only if group names do not include a backslash (\) or at-sign (@) character.

14.  Set Radius Proxy Removes Group for IdentityGuard to True to have the group stripped out of the user ID before the request is forwarded to Entrust IdentityGuard.

Set this property to True only if your domain group names and Entrust IdentityGuard group names do not match.

Note: If set to True, this property works as intended only if group names do not include a backslash (\) or at-sign (@) character.

15.  Set Skip Second-Factor Authentication for Non-existent Users to True if you want users who do not yet exist in Entrust IdentityGuard to log in without being prompted for Entrust IdentityGuard authentication. The default setting is false, and generates an error is a user tries to log in without an Entrust IdentityGuard second-factor authenticator.

16.  Set Skip Second-Factor Authentication for Users Without Active Grids or Tokens to True if you expect delays between the time you create the users in Entrust IdentityGuard, and the time they receive or activate the grids or tokens. When set to True, users who have accounts but who do not have an active grid, token, or other authenticator are allowed to log in.

17.  Use VPN Timeout to set the number of seconds that the Radius proxy waits for a response from the VPN server.

18.  Use Maximum Number of VPN Outstanding Requests to set the size of the VPN state table.

19.  Set VPN Request Timeout to specify how many seconds the Entrust IdentityGuard Radius proxy should queue responses for previous requests. Responses are queued to handle any VPN requests that are retransmitted by the VPN server. This value should be larger than the retransmit interval set in the VPN server. The default value is 10 seconds.

20.  Set Incoming Messages from VPN Server Require Message-Authenticator to True if you want incoming messages from the VPN server to include the Message-Authenticator attribute.

21.  Set Outgoing Messages to VPN Server Require Message-Authenticator to False if the VPN server does not understand the Message-Authenticator attribute and rejects messages as a result.

22.  Set Allow ACL Download Requests from VPN Server to True if you want to allow the passthrough of access control list (ACL) requests from the VPN Server to the respective Radius server. The resulting ACL produced by the Radius server is sent to the VPN server.

23.  Set Use IP Risk Based Authentication to True, if you want the Radius proxy to apply risk-based authentication to users accessing Entrust IdentityGuard through a VPN server.

24.  When risk-based authentication is in effect, IP Risk Based Authentication Security Level sets the security level. Choose Normal or Enhanced. See Risk-based authentication overview for more information about risk-based authentication.

25.  In IP Address Radius Attribute ID, select the Radius attribute ID to use to read the client IP address in Radius Access-Request and Access-Response messages. The client IP address is used for risk-based authentication. For more information about risk-based authentication, see Configuring and using risk-based authentication.

The IP address encapsulated in the Radius attribute must be a dot notation value encoded as a string. The default selection for this property is TUNNEL-CLIENT-ENDPOINT (66).

26.  Under First-Factor Authentication Method, select the method of first-factor authentication applied to your VPN users through the Entrust IdentityGuard Radius proxy.

●       Radius

To authenticate users through a Radius server, select Radius. This is the default setting.

●       External

To use external authentication (either an LDAP directory or domain controller), select External. See External authentication overview.

●       Entrust IdentityGuard Password

To use Entrust IdentityGuard password authentication, select Entrust IdentityGuard Password. See Password authentication overview.

Password authentication through Radius supports the PAP, CHAP, and MSCHAP (v1 and v2) protocols when passwords are stored encrypted, not hashed. See Configuring password authentication policies.

Note: When using EAP-MSCHAPv2 protocol, only response-only token authentication (TOKENRO) is allowed, and it must be allowed in Entrust IdentityGuard. See IP/Geolocation policies for more information.

●       Entrust IdentityGuard Token

To use token authentication, select Entrust IdentityGuard Token. See Token authentication overview. Mobile soft tokens cannot be used for first-factor authentication.

●       Entrust IdentityGuard One-Time Password

To use Entrust IdentityGuard OTP authentication, select Entrust IdentityGuard One-Time Password. See Out-of-band one-time password overview for more information about OTP authentication.

Note: When using Radius first-factor authentication with OTPs, the OTP Dynamic Refresh Enabled policy must be set to True to ensure that new OTPs can be delivered. In this scenario, however, new OTPs cannot be delivered to replenish expired OTPs before authentication, so you must ensure that users have an OTP assigned before their first attempt to authenticate with an OTP. This also applies to newly created users.

Note: If you use OTP for first-factor authentication, you cannot set OTP as a second-factor authenticator.

●       No First-Factor Authentication

To bypass first-factor authentication (which assumes users are already authenticated), select No First-Factor Authentication.

In this case, users must authenticate with a second-factor authentication method of some kind. This includes users who are not yet registered or activated, or who do not yet have their grid card or token.

27.  If you have already configured Radius server, it appears in the Radius Server drop-down list. If users will authenticate using a Radius server (First-Factor Authentication Method is set to Radius), select the Radius server from the drop-down list.

If you select User’s Group is Radius Server, the group name from the user’s user ID is used as the name of the Radius server to be used for first-factor authentication.

If you have not yet configured a Radius server, see To configure a Radius server.

28.  Set the Convert Group to Lower Case property to True to convert the user’s group name to lower case before using it to select the third-party Radius server to use for first-factor authentication. The default setting is False.

Radius server names are case-sensitive and group names are not, so this features ensures that the group name can match the Radius server name.

29.  Use the Displaced Server property to specify an existing Radius authentication server that you are planning to eventually remove from your system after all users have migrated to Entrust IdentityGuard.

It is against this server that non-Entrust IdentityGuard users continue to authenticate during the transition to Entrust IdentityGuard.

If you select a server in this property, authentication is forwarded to the old Radius server when a user does not yet exist in Entrust IdentityGuard.

30.  Set Only Perform First-factor Authentication to True if you want users to be authenticated after successfully answering the first-factor challenge. This option must be set to False if No First Factor Authentication is specified. Also, this option must be set to False if Entrust IdentityGuard Token is specified and you want users to authenticate with MST TVS token authentication online mode (which can be used only for second-factor authentication). For more information, see VPN Server Configuration for details.

31.  Under Allowable Entrust IdentityGuard Second-Factor Authentication Methods, select which second-factor authentication methods are valid through the Radius proxy. The authentication methods you select must be allowed by Entrust IdentityGuard policy to be available. See IP/Geolocation policies for more information.

It can be one of the following, or you can select them all (this is the default):

●       Grid 

●       Token (including mobile soft tokens (using the Entrust IdentityGuard Mobile ST app)

●       OTP 

Out-of-band delivery must be configured and available.

●       Q&A 

If you are using Q&A, only one question is used, and Entrust IdentityGuard policy must be set to allow authentication using a single question.

32.  Set PVN Required to True if you want users to enter a PVN to access their first-factor authenticator. Soft tokens can be protected with a PIN, making a PVN unnecessary.

33.  If your users will perform second-factor authentication using mobile soft tokens in online mode (which uses the Mobile Transaction Verification Service), configure the following settings: 

●       Use MST TVS for Token Authentication – Set to True to allow mobile soft token-based authentication using online mode (with an option to fallback to classic mode).

Online mode is used when a user has an Internet connection. It allows the user to select the Confirm button in the Entrust IdentityGuard Mobile ST app to respond to the authentication challenge. Classic mode is used when the user’s device does not have an Internet connection and times out or if the user does not respond to the online request before it expires. Classic mode is also used when a user does not have any mobile soft tokens that can perform online authentication.

Note: To perform authentication transactions, mobile soft tokens require a Transaction Verification with Soft Tokens license (in addition to the Soft Tokens license). For more information, see Managing licenses.

●       MST TVS Online Fallback – Set to True to allow users to manually enter the OTP if they do not have an Internet connection (to use online mode) or if the user does not respond to the online request before it expires. If this property is set to False, no fallback authentication method is offered and the user must authenticate using online authentication.

●       Default MST TVS Online Token Challenge Summary Message – Enter the message you want users to see when presented with a soft token authentication challenge. The default message is "User {0} wants to authenticate", where the Entrust IdentityGuard user ID is substituted for {0}.

●       TVS Callback Response Timeout – Specify the time, in seconds, that Entrust IdentityGuard Radius waits for a response from Entrust IdentityGuard. This value should be less than the overall VPN timeout for a request to complete processing. If the challenge lifetime policy defined by Entrust IdentityGuard is less than this value, this value is set to the value in the policy. The default is 60 seconds.

To configure this property you need to consider the overall VPN request timeout derived from constraints imposed by the type of VPN server you are using.

Example:

You have a VPN server that fails an authentication request after 50 seconds, you might change this property from the default 60 seconds to 35 seconds.

The VPN request timeout is 10 seconds.

The VPN makes a maximum of 5 request attempts.

The overall VPN request timeout is 50 seconds.

You need to allow the user time to try authenticating with the fallback method (enter an OTP response manually). Set this value to 35 seconds so this timeout value plus the Callback Queue Check Interval (which can be configured to be between 2 and 10 seconds), is a few seconds less than the 50 second limit imposed by the VPN server.

34.  Set Use EAP for Authentication to True and pick an option under Type of EAP Protocol Supported to use the EAP protocol supported with the VPN server.

Note: When using EAP-MSCHAPv2 protocol, only TOKENRO authentication is allowed, and it must be allowed in Entrust IdentityGuard. See IP/Geolocation policies for more information.

35.  The Type of EAP Protocol Supported specifies which EAP protocol is supported by the VPN server. The choices are PEAPv0 with MSCHAPV2 and PEAPv1 with EAP-GTC.

The Type of EAP Protocol Supported property is available only if you set the Use EAP for Authentication property to True.

Note: PEAP is Protected EAP.

When using PEAPv1 with EAP-GTC, the authentication type used is determined by the Allowable Entrust IdentityGuard Second-Factor Authentication Methods property.

EAP-MSCHAPv2 supports only response-only tokens. For support of challenge-response tokens and all other second-factor authentication methods, use EAP-GTC.

The Allowable Entrust IdentityGuard Second-Factor Authentication Methods property is not used when you select EAP-MSCHAPv2.

36.  The Include MPPE Keys Flag property determines whether both the mppe recv and mppe send keys are included in the Access-Accept returned during a successful eap authentication. The default is False.

37.  The Use PEAP V1 Flag determines whether to user the PEAP V1 Label when calculating the mppe recv and mppse send keys. The default is False.

38.  Use the following properties to customize the authentication challenge messages that are displayed to users. The messages must follow a set syntax. For information about the syntax and construction of challenge messages, see Customizing VPN challenge strings.

Note: All of the default challenge and retry messages must use fewer than 250 characters.

●       Default Grid Challenge Message sets the challenge message presented to VPN users when they must authenticate with a grid.

●       Default Token Challenge Message sets the challenge message presented to VPN users when they must authenticate with a token.

●       Default One-Time Password Challenge Message sets the challenge message presented to VPN users when they must authenticate with an OTP.

●       Default Q&A Challenge Message sets the challenge message presented to VPN users when they must authenticate with questions.

39.  The Single Challenge for Password Update property sets whether the user will be challenged once for the new password or twice. If this property is True, the user is challenged just once, and must enter the new password twice in the same response, for example, newpasswordnewpassword.

If this property is set to False, the user is prompted twice, once to enter the new password, and again to confirm the new password.

40.  Use the following properties to customize the messages that are displayed to users when they update their passwords.

Note: All of the default messages must use fewer than 250 characters.

●       Default Password Update Message sets the message to display if the user needs to update their password.

●       Default Password Update Verify Message sets the message to display when prompting the user for confirmation of their new password.

●       Default Password Failure Message sets the message to display if the user’s password change fails.

41.  If you set Separate Challenge for PVN Update to True,  users are prompted for the new PVN and confirmation in separate challenges. The default is False, which means that Entrust IdentityGuard expects the challenge response, the new PVN, and confirmation of the new PVN all in one string. See VPN Server Configuration Separate Challenge for PVN Update for details.

Note: All of the default challenge and retry messages must use fewer than 250 characters.

42.  Use the following properties to customize the messages that are displayed to users when they update their PVNs:

Note: These messages must use fewer than 250 characters.

●       Default PVN Update Message is the default message to display when prompting the user to change their PVN.

●       Default PVN Update Verify Message is the default message to display when prompting the user to confirm their new PVN. This string is only used if Separate Challenge for PVN Update is set to True.

●       Default PVN Failure Message is the default message to display when the user’s two PVNs do not match.

43.  Use the following properties to customize these messages that are displayed to users. These messages an be any free-form string.:

Note: All of the default challenge and retry messages must use fewer than 250 characters.

●       Default Grid Retry Message sets the message to display if the user enters an invalid response to the grid challenge.

●       Default Token Retry Message sets the message to display if the user enters an invalid response to the token challenge. Default One-Time Password Retry Message sets the message to display if the user enters an invalid response to the OTP challenge.

●       Default Q&A Retry Message sets the message to display if the user enters an invalid response to the question-and-answer challenge.

44.  Custom Error Message is the string to display with the new challenge when a user enters an invalid response.

45.  Use the Custom Error Messages Properties File property to specify a file with customized error messages that will replace the default ones for this VPN server instance. With this property you can update or localize error messages so users will see them in a language other than the default, English. To support several languages, create multiple properties files, and associate each one with its own VPN server configuration instance. For more information, see Customizing error messages.

Note: Customization of error messages is set for each server configuration instance. Users cannot select the language of the messages they see.

46.  Use Additional Radius Response Attributes to define mappings for the Radius response attributes to include in the Radius message upon successful authentication.

In Radius Response Attribute Group, make a selection from the drop-down list. The list contains the attributes you configured using the Radius Response Attribute Configuration properties.

Choose a mapping value from the next drop-down list. If you are using an LDAP repository, you can include LDAP attributes found at user entries by selecting Custom and entering the LDAP attribute name.

For more information about using the Radius response attributes, see Configuring the Radius response attributes.

47.  Use Authorization expression to define a set of LDAP or Entrust IdentityGuard groups to which the user must belong in order to be granted access to the requested resource. Entrust IdentityGuard performs this authorization check immediately after first-factor authentication (if second-factor authentication is disabled), or second-factor authentication (if second-factor authentication is enabled). For syntax and examples, see "Authorization expression syntax and examples" in VPN Server Configuration.

48.  Use Skip Second-Factor Authentication for Users That Have Been Authorized in conjunction with Authorization expression. If True, users who have been successfully authorized against your authorization expression skip second-factor authentication. If False, users who are successfully authorized cannot skip second-factor authentication.

Note: If Skip Second-Factor [...] setting is disabled, it is because a) the First-Factor Authentication Method property is set to Radius, or b) the Authorization Expression has not been set.

49.  Click Validate & Save.

50.  Log out of the Properties Editor.

51.  Restart Entrust IdentityGuard and the Radius proxy.

To modify a VPN connection

1.      Start the Entrust IdentityGuard Properties Editor.

2.      On the Table of Contents, click VPN Server Configuration.

3.      Select the name of a VPN server from the Configuration Instances, drop-down list.

The VPN server settings appear in the property fields.

4.      Change the property settings as required. For a complete list of properties, see VPN Server Configuration.

5.      Click Validate & Save.

To remove a VPN connection

1.      Start the Entrust IdentityGuard Properties Editor.

2.      On the Table of Contents, click VPN Server Configuration.

3.      Select the name of a VPN server from the Configuration Instances, drop-down list.

4.      Click Remove.

5.      Click OK on the prompt dialog box.
