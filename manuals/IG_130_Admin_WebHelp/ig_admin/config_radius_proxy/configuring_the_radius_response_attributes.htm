Configuring the Radius response attributes

You can configure the Radius proxy to return Active Directory and LDAP attributes such as user group in VPN responses upon successful authentication.

In this scenario:

1.      A user authenticates to Entrust IdentityGuard Radius proxy using either external authentication (with an Active Directory or LDAP repository) or an Entrust IdentityGuard-specific authentication type (Entrust IdentityGuard password or token-based authentication with an Active Directory or LDAP repository) as their first-factor authentication method.

2.      Entrust IdentityGuard Radius proxy sends the user’s authentication request using either their LDAP or Kerberos login, or their Entrust IdentityGuard token or password credentials. The authentication request also includes a list of attributes to return from the Active Directory or LDAP repository, and some predefined Entrust IdentityGuard user information—specifically the Entrust IdentityGuard group name—if the authentication is successful.

3.      If the authentication request is successful Entrust IdentityGuard Radius proxy extracts and returns attributes from the authentication result and includes these values within one or more Radius Attributes, including Vendor-specific attributes. These attributes are returned in the response of a successful first-factor authentication.

If first-factor authentication is disabled or is using an authentication method that does not access the Entrust IdentityGuard repository (a third-party Radius implementation, for example), the attributes are returned in the response of a successful second-factor authentication. The resultant Radius message (Response Type) is returned to the VPN that requested the authentication.

To configure the Radius proxy to return attributes in Radius responses

1.      Start the Entrust IdentityGuard Properties Editor. (See Log in or out of the Properties Editor.)

2.      Configure a VPN connection if you do not already have one. See To configure VPN connections. Skip the following properties:

●       IP Address Radius Attribute ID

●       Additional Radius Response Attributes

3.      Configure a Radius server, if you do not already have one set up. See To configure a Radius server.

4.      Configure the Radius response attributes. See the property definitions in To configure the Radius response attributes.

5.      Save the changes and restart the Entrust IdentityGuard server and Radius Proxy services.

To configure the Radius response attributes

1.      On the Properties Editor Table of Contents, click Radius Response Attribute Configuration.

2.      In the Configuration Instances property, enter a unique name for this Radius response attribute configuration. Click Add.

3.      In Radius Attribute ID, select the type of Radius attribute you are specifying in this configuration instance.

4.      In Radius Attribute Value Type, select the Radius attribute value type from the list. Set this property based on the Radius Attribute ID you set. The default is STRING. The choices are:

●       STRING (character sequence, must be no more than 253 bytes; not necessarily null terminated)

●       IP (V4) ADDRESS (a 4-byte IP address in network-byte order; for example, 10.4.160.61)

●       INTEGER (a 4-byte value in big-endian order)

●       DATE (a 4-byte value in big-endian order; the number of seconds since 00:00:00 GMT - January 1st, 1970)

●       BINARY (a byte sequence of length less than 253 bytes — used for VSA’s that do not conform to FRC 2865)

If the expected attribute does not match one of the formats described (IP address, integer, date, or binary), select STRING.

5.      Use the Radius Attribute Format property to specify the format of the values that are returned.

The value of this property is interpreted using the Java MessageFormat class where {0} represents the value to format (the data object Entrust IdentityGuard is searching for). This can be the Entrust IdentityGuard Group Name or any predefined LDAP attribute name. Static (hard-coded) values may be included by removing any reference to {0}. The default value is {0}.

The following rules apply to static and non-static values. Examples of both types of values are shown.

●       If the value type is a string, the format encoder expects a string value.

–  non-static = ‘CN={0}’

–  static = ‘This is a string’ 

●       If the value type is an IP address, the format encoder expects a dot notation string value representing an IP address.

–  non-static = '{0}'

–  static = '10.4.123.23'

●       If the value type is an integer, the format encoder expects a string value representing the integer.

–  non-static = '{0}' 

–  static = '3423'

●       If the value type is a date, the format encoder expects a string value representing the date expressed as an integer.

–  non-static = '{0}'

–  static = '132456323'

●       If the value type is binary, the format encoder will expect a hexadecimal string value representing the actual binary data.

–  non-static = '{0}'

–  static = 'A2ED341E5D'

6.      The Radius Attribute Return as Multiple Attributes Flag property specifies a flag that determines whether attributes with multiple values are returned in the same Radius attribute, or a separate Radius attribute for each value.

Set this property to True if you want the attributes to be returned in separate Radius attributes rather than being concatenated and sent in one Radius attribute.

7.      The Radius Attribute Multi-Value Delimiter property specifies the delimiter to use when returning multi-valued attributes in one Radius attribute.

If the Radius Attribute Return as Multiple Attributes Flag property is True, this property is ignored.

8.      The Radius Vendor-Specific Attribute Vendor Code property is required if the Radius Attribute ID property is set to VENDOR-SPECIFIC.

This property is the vendor code as specified in IETF RFC 1007. See www.iana.org for the up-to-date list of SMI Network Management Private Enterprise Codes. Enter the code that corresponds to the equipment vendor you are using.

9.      The Radius Vendor-Specific Attribute Conforms to RFC2138 Flag is also required if the Radius Attribute ID property is set to VENDOR-SPECIFIC (26).

This property specifies whether the Vendor-Specific Attribute conforms to the format recommended in RFC 2138. RFC 2138 format contains a specific vendor attribute number, its length, and the value.

If this property is set to False, then the Radius Attribute Value Type property must be set to BINARY, and the Radius Attribute Format property then represents the value specified for the Vendor-Specific Attribute. This must be a hexadecimal value (of the format 12AB34...) up to a maximum of 249 bytes.

10.  The Radius Vendor-Specific Attribute Number property is required if the Radius Attribute ID property is set to VENDOR-SPECIFIC (26), and Radius Vendor-Specific Attribute Conforms to RFC2138 Flag is set to True.

This property represents the vendor attribute number (a value between 0 and 255). This value is set by the vendor. Check the equipment documentation for this attribute number.

11.  Click Validate, and correct any errors.

12.  Click Table of Contents.

13.  Click VPN Server Configuration.

14.  Scroll to the bottom of this property grouping, to the Additional Radius Response Attributes property.

15.  Use Additional Radius Response Attributes to define mappings for the Radius response attributes to include in the Radius message upon successful authentication.

In Radius Attribute Instance, make a selection from the drop-down list. The list contains the attributes you configured using the Radius Response Attribute Configuration properties.

Choose a mapping value from the next drop-down list. If you are using an LDAP repository, you can also choose Custom to define a custom mapping.

16.  Click Validate & Save.

17.  Restart Entrust IdentityGuard service and the Radius proxy.
