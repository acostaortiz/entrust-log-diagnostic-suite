IdentityGuard Server 13.0 Administration Guide

Configure Entrust IdentityGuard authentication methods for the Radius proxy

The following procedures describe the steps required to configure the Entrust IdentityGuard authentication methods that are supported by the Entrust IdentityGuard Radius proxy.

To configure password authentication

1.      In Entrust IdentityGuard policy, configure the password policies.

Configure how the password is stored, based on whether you are using the PAP protocol, or the CHAP or MS-CHAP protocols.

2.      Create passwords for each user.

To configure one-time password authentication

1.      Configure a default out-of-band delivery mechanism.

2.      In Entrust IdentityGuard policy, configure the one-time password policies.

Enable user accounts to receive one-time passwords.

3.      Create contact information for each user, and assign the default out-of-band delivery method to that contact information.

To configure knowledge-based authentication

1.      In Entrust IdentityGuard policy, configure the knowledge-based policies. Set the minimum Q&A challenge size to 1.

2.      If applicable, edit the word map file.

To configure risk-based IP/Geolocation authentication

1.      Configure the VPN to transmit the client IP address within the Radius attribute, 66-Tunnel Client Endpoint.

2.      In Entrust IdentityGuard policy, disable machine authentication from the risk-based authentication policies.

3.      Set the Entrust IdentityGuard properties to enable IP risk-based authentication. Set the IP Address Radius Attribute ID property.

Note: With 10.2 FP1 Patch 194848 and later, Entrust IdentityGuard checks IP address against the IP blacklist (if one is defined) even when Entrust IdentityGuard is configured for first factor authentication only.

To configure one-step multi-factor (password and token OTP) authentication

Note: This Radius authentication method is SWIFT-compliant.

1.      Configure token authentication.

2.      Enable users to enter both their Entrust IdentityGuard password or external authentication password and their token OTP in the same step, configure the following settings in the Properties Editor, VPN Configuration Settings category:

Required setting

First-Factor Authentication Method

identityguard.igradius.vpn.{}.firstfactortype

Determines which type of first-factor authentication to use through the Radius proxy. The choices are Radius, External, Entrust IdentityGuard Password, Entrust IdentityGuard Token or No First-Factor Authentication where:

•  Radius – Users are authenticated using a Radius server.

•  External – Users are authenticated using an LDAP directory or a Windows domain controller. (See External First-Factor Authentication, and External authentication overview.)

•  Entrust IdentityGuard Password – Users are authenticated using an Entrust IdentityGuard password. (Also see Password authentication overview)

•  Entrust IdentityGuard Token – Users are authenticated with a valid token response from any hardware or software token supported by Entrust IdentityGuard. If you choose this option, you cannot add any second-factor authentication. This is also called “one-step token authentication.” (Also see Overview of token authentication.)

•  Entrust IdentityGuard One-Time Password – First-factor authentication will be performed using OTPs delivered out-of-band. (Also see Out-of-band one-time password overview.)

Note: When using Radius first-factor authentication with OTPs, the OTP Dynamic Refresh Enabled policy must be set to True to ensure that new OTPs can be delivered.

Note: If you use OTP for first-factor authentication, you cannot set OTP as a second-factor authenticator.

•  Mobile Smart Credential – Users are authenticated through push authentication using the Entrust IdentityGuard Mobile Smart Credential app. When mobile smart credential push authentication is used for first-factor authentication, second-factor authentication is not used.

•  No First-Factor Authentication – First-factor authentication has already occurred outside of Entrust IdentityGuard and the user is ready for second-factor authentication. (In this case, second-factor authentication by some means is required. This includes cases where a user is not yet registered or activated, or does not have a card or token.)

Do not select No First-Factor Authentication if you want the Radius proxy to perform risk-based authentication (Use IP Risk-Based Authentication= True). For risk-based authentication to occur through the Radius proxy, first-factor authentication must be enabled.

Entrust IdentityGuard password or External

If Entrust IdentityGuard password is used, this configuration also supports the password change workflow if a user's password requires updating.

Only Perform First-Factor Authentication

identityguard.igradius.vpn.{}.firstfactoronly

If this property is set to True, the user is authenticated after successful first-factor authentication and is not shown a second-factor challenge.

If First-Factor Authentication Method is set to No First Factor Authentication this property must be set to False.

If First-Factor Authentication Method is set to Entrust IdentityGuardToken, this property must be set to True. Users must enter the token response manually, Use of MST TVS token authentication (by which a user of the Entrust IdentityGuard Mobile Soft Token app selects Confirm to authenticate) is not supported for first-factor authentication.

MST TVS token authentication can be used only as a second-factor authentication method.

If this property is set to True, the Allowable Entrust IdentityGuard Second-Factor Authentication Methods property is disabled.

Default: False

False

Allowable Entrust IdentityGuard Second-Factor Authentication Methods

identityguard.igradius.vpn.{0}.allowedsecondfactortype

This property specifies which second-factor authentication methods are valid through the Entrust IdentityGuard Radius proxy; that is, Entrust IdentityGuard chooses the second-factor authentication based on this property.

Select one or more of the following:

•  Grid

•  Token – If Token is used for first-factor authentication, second-factor authentication is disabled. This option supports authentication with mobile soft tokens (using the Entrust IdentityGuard Mobile Soft Token app).

•  OTP – OTP is not allowed for second-factor authentication if it is used for first-factor authentication.

•  Mobile Smart Credential – If Mobile Smart Credential is used for first-factor authentication, second-factor authentication is disabled. This option support push authentication using the Entrust IdentityGuard Mobile Smart Credential app.

•  Q&A (Question and Answer)

Default: Any authentication method can be used for second factor, considering the constraints described above.

Note: If you are setting up multiple VPNs, each can have different second-factor authentication methods. That is, you can set up VPN1 with Grid, for example, and VPN2 with Token.

PVN Required

identityguard.igradius.vpn.{}.pvnrequired

This property can override PVN policy set by the Authentication Types Requiring a PVN policy attribute (see Personal Verification Number policies).

When set to True, a PVN is required during Radius authentication through VPN for any authentication method that supports PVN, regardless of how the policy is set.

When set to False (the default), the PVN policy setting determines if a PVN is required.

Enable One-Step Multi-Factor Authentication

identityguard.igradius.vpn.{}.onestepmfa.enabled

This property allows a VPN to send both factors of a multi-factor authentication in the same password field. If enabled, the External and Entrust IdentityGuard password first-factor authentication types are allowed, second-factor authentication must be enabled, and the only type of second-factor authentication that is allowed is TOKEN.

Default: False

True

OTP Length for One-Step Multi-Factor Authentication

identityguard.igradius.vpn.{}.onestepmfa.otplen

This property specifies the number of digits in the OTPs that are received as the second part of a one-step multi-factor authentication request from a VPN. The value for this field is only meaningful if the One-Step Multi-Factor Authentication property is enabled. The value is typically 6 or 8. The same number of digits applies to all token OTPs that use this VPN Server Configuration instance.

6 or 8 (characters). The OTP length must be the same for all tokens that will use this configuration instance.
