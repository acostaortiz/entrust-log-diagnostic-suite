IdentityGuard Server 13.0 Administration Guide

First-factor authentication options

During configuration of the Radius proxy, you can choose between a Radius server, an external authentication resource, or password for first-factor authentication. You can also choose to have no first-factor authentication. This section explains the differences.

Regardless of your choice, the VPN server still believes it is communicating with a Radius server. It is actually communicating with the Entrust IdentityGuard Radius proxy.

If you plan to use a Radius server for first-factor authentication, follow these general steps to configure the Radius server to communicate with the Entrust IdentityGuard Radius proxy. The interface details will vary depending on your platform and the interface tool you use.

To configure your Radius server for first-factor authentication

1.      Log in to the Radius server as administrator.

2.      For the Radius client address, change the IP address from the VPN server to that of the Entrust IdentityGuard Radius proxy.

3.      For the server secret, enter a value that matches the value known to Entrust IdentityGuard.

4.      Save your settings.

In a typical VPN implementation, the VPN server communicates with a VPN client and a Radius server. When you integrate with Entrust IdentityGuard, the Entrust IdentityGuard Radius proxy intercepts messages between the VPN server and a first-factor authentication resource. That resource can be one of the following:

●       Radius server

●       Windows domain controller

●       LDAP directory

●       Entrust IdentityGuard password authentication

●       Entrust IdentityGuard token

●       Entrust IdentityGuard one-time password

You can configure different VPN servers to use different first-factor authentication resources. For example, you can configure one VPN server to use a Radius server, and another VPN server to use an LDAP directory.

You can take advantage of the Entrust IdentityGuard groups feature to organize users into different groups for authentication purposes. This way you can direct the users of some groups to one first-factor authentication resource, and other users to other resources. For details, see Configuring the Radius proxy for groups.
