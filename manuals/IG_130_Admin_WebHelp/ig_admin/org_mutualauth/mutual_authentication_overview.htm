IdentityGuard Server 13.0 Administration Guide

Mutual authentication overview

Users must be confident that they are interacting with their organization or intended online site, and not a fraudulent organization or spoofed site. Likewise, you need to have confidence in the identity of the users accessing your applications.

Entrust IdentityGuard provides several methods of user authentication and organization authentication that let you configure ways for both parties to authenticate each other. This two-way check is called mutual authentication.

Scenario 1 and Scenario 2, below, illustrate how mutual authentication works:

Scenario 1:

●       The user completes first-factor authentication successfully.

●       Entrust IdentityGuard presents the user with a challenge based on the authentication method being used, including an image or information that only a valid site could have.

●       The user recognizes the image or information, and responds to the challenge.

●       Entrust IdentityGuard validates the entered values and authenticates the user.

Scenario 2:

●       The user completes first-factor authentication successfully.

●       Entrust IdentityGuard presents the user with a challenge based on the authentication method being used.

●       Entrust IdentityGuard validates the response.

●       The client application presents an image or information that only a valid site could have and presents a second challenge.

●       The user recognizes the image or information, and responds to the challenge.

●       Entrust IdentityGuard authenticates the user.

Mutual authentication has the following benefits:

●       It provides stronger authentication than just user authentication, as it requires an attacker to gather specific information both about your organization and the user.

●       It gives your users peace of mind because they know they are accessing a valid site.

To configure Entrust IdentityGuard for mutual authentication:

●       Determine whether to use grid data, serial numbers, or images for mutual authentication. See Grid serial number or grid location display and Image and message display.

●       For image and message replay, create a list of images and/or messages to display to your users. Entrust IdentityGuard is shipped with a set of stock images you can use, or you can create your own.

●       Ensure that administrators have the required permissions to set policy and manage mutual authentication (see User one-time password permissions).

●       Use the Policies pages of the Administration interface to set the policies that control authentication secrets (see Configuring mutual authentication policies).

●       Create an application that does the following:

–  for serial number display authentication, gets the card or token’s serial number and displays it to the user after authentication

–  for grid location display authentication, creates a challenge and displays it to the user after second-factor authentication with Entrust IdentityGuard

–  for image and message replay, sets the message or image authentication secrets when the user registers

–  for image and message replay, authenticates the user, and displays the message and/or image after first-factor authentication, and usually before second-factor authentication

For more information about configuring your client application, see the Entrust IdentityGuard Programming Guide.
