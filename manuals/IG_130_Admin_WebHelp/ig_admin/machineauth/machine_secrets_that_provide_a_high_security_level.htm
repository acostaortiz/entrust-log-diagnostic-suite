Machine secrets that provide a high security level

In this scenario, the client machine stores an updated machine secret after each authentication, and returns it during the next authentication.

Enable the policy attributes for creating a machine nonce and sequence nonce. For the highest level of security, have the application supply at least one set of application data. The following table shows the machine secret settings for this level of security.

Machine Secret Policy

Value

Sequence Nonce Required

Set to Yes

Machine Nonce Required

Set

Application Data Elements Required

at least 1

With these settings, this is what happens:

●       When a user first registers for machine authentication, the application generates and passes the application data to Entrust IdentityGuard as part of a machine authentication request. Entrust IdentityGuard generates a machine nonce and a sequence nonce to create the machine secret. It stores the machine secret and application data in the repository and returns a copy of the machine secret (machine nonce and sequence nonce) to the application. The application stores the machine secret on the client computer.

●       The next time the user logs in, the application passes the stored machine secret and regenerated application data to Entrust IdentityGuard as part of a machine authentication request. Entrust IdentityGuard compares them to those stored in the repository. If they match, machine authentication succeeds. Entrust IdentityGuard then generates a new sequence nonce, uses it to update the machine secret in the repository, and returns a copy of the new machine secret to the application. The application stores the new machine secret on the client computer.

During authentication, Entrust IdentityGuard expects the application to provide a machine nonce and a sequence nonce. If Application Data Elements Required is a number other than zero, it also expects application data. Failure to provide any of these causes an error.
