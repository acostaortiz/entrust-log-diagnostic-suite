IdentityGuard Server 13.0 Administration Guide

Creating a machine secret

To establish the device identity, Entrust IdentityGuard first creates a machine secret for the user’s device. Depending on policy settings, Entrust IdentityGuard builds the machine secret using the following data:

●       Machine nonce — This is a random number generated by Entrust IdentityGuard during machine registration. The requirement to include this nonce in the machine secret is determined by the Machine Nonce Required policy.

●       Sequence nonce — Entrust IdentityGuard generates and changes the sequence nonce each time authentication occurs. When a sequence nonce is required, the machine secret is only valid until the next login attempt. This increases security by reducing the validity period for the machine information, and by making it more difficult for an attacker to steal a machine secret without being detected. The requirement to include this nonce in the machine secret is determined by the Sequence Nonce Required policy.

●       Application data — This is a list of name and value pairs specified by your client application and set when Entrust IdentityGuard first creates the machine secret. A client application can provide Entrust IdentityGuard with any application data specific to the user’s computer. This can include operating system and browser data gathered through the use of client-side or server-side software. The requirement to include this data in the machine secret is determined by the Application Data Elements Required policy and allowance for a small number of mismatches can be made using the Bad Application Data Elements Allowed policy.

●       Device fingerprint — This is a value calculated from a set of device-specific attributes that are collected by your client application. (To collect these attributes, design your client application using the Entrust IdentityGuard Device Fingerprint SDK introduced in Entrust IdentityGuard release 11.0.) In the Policies pages of the Administration interface, you can edit the list of attributes used in the calculation, and assign them relative weights based on your perception of the amount of risk they represent. For more information, see Configure the device fingerprint policies.

Note: Entrust IdentityGuard 11.0 introduced the device fingerprint capability. For new installations, consider using Device fingerprint instead of Application data. For upgraded installations, Application data is still supported, however, if you enable the more comprehensive Device fingerprint policy, Device fingerprint information is stored as part of the machine secret and Application data is no longer used after each user's machine secret is updated with Device fingerprint information. A user's machine secret is updated after successful machine authentication or successful completion of a second-factor challenge.

Entrust IdentityGuard copies the machine secrets into the repository. The machine secret library (part of the Entrust IdentityGuard Device Fingerprint SDK) can be used to store the machine nonce (and optional sequence nonce) across multiple storage mechanisms including cookies, Flash objects, and HTML 5 local storage. When a user attempts to authenticate again, the values are checked against those in persistent storage.

Attention: For security reasons, ensure your application does not store machine secrets on a public or shared computer.

Attention: For security reasons, ensure that machine secrets are transmitted to or from the end user’s computer only over a secure connection.
