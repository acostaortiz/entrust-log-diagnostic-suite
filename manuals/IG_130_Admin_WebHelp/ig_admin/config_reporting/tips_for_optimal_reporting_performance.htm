Tips for optimal reporting performance

Reporting performance is affected by many factors such as repository performance, server memory, disk space, CPU speed, and the current level of authentication traffic on the server running the report. Reporting has been designed to run at the same time as authentication.

The following features help ensure that reporting does not interfere with the performance of your Entrust IdentityGuard deployment:

●       Reports run one at a time. Additional report requests are queued, and executed on a first-come, first-served basis.

●       By default, reports are constrained to fetch a maximum of 50,000 records from the audit database, or 10,000 records from all other data sources.

●       Report execution is limited to a maximum of 60 minutes to prevent a single report from blocking all other reports.

●       Reports can be run from any Entrust IdentityGuard servers that shares the same repository, so you can run reports on replica servers that are not handling as much authentication traffic.

●       You can store 25 executions (outputs) for each of type of report. After this, the oldest reports are removed as new ones are created.

Use the following strategies to further optimize system performance when generating reports:

●       On busy systems, choose a low-traffic time to run reports. You can use the Master user shell reporting commands to create a script to generate the reports at low-traffic times. However, be aware that unattended runs of Master user shell commands require that the master user password be available to the script, which is a security concern.

●       Use search criteria or a personal query to constrain the report content. These techniques can limit the number of records returned in the report, thus improving performance.

●       Use the summary report option, where available, to produce all the report graphs and summary tables without including each detailed record.
