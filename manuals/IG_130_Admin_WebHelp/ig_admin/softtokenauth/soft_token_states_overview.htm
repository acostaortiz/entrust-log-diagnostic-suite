Soft token states overview

Soft tokens have two types of states associated with them:

Activation states

The soft token passes through these states during its creation and activation:

●       Created

When a soft token is in this state:

–  the serial number has been generated

–  the soft token has been assigned to a user

–  the Soft Tokens license count is increased by one. For more information, see How license counting works.

–  The soft token grace period begins, if it is enabled. See Setting soft token activation policies (enabling a grace period) for details.

●       Activation code generated

When a soft token is in this state:

–  Entrust IdentityGuard has generated activation codes for a soft token

–  the user has not yet activated the token

●       Activated

When a soft token is in this state:

–   the user has successfully activated the soft token by supplying a registration number generated by the token

If the Transaction component is enabled, the registration code may be communicated automatically to Entrust IdentityGuard;

If the Transaction component is disabled, the registration code must be entered manually in Self-Service or the Administration interface.

–  the token can be used for authentication

Authentication states

These token authentication states are independent of activation states, and take effect after activation. Authentication states are the same for grid cards, hardware tokens, and software tokens, and follow the same state transition rules.

●       Pending

●       Hold-pending

●       Current

●       Hold

●       Canceled
