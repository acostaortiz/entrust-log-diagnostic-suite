IdentityGuard Server 13.0 Administration Guide

PVNs and OTPs

You can require any user to enter a PVN as part of their OTP challenge. The user enters the PVN first, followed by the OTP challenge response.

If OTP authentication requires a PVN, and the user does not have a PVN yet, the user is forced to assign themselves a new PVN. The new PVN is accepted when the user successfully authenticates with the OTP (assuming the new PVN is numeric and the correct length).

When using Authentify to deliver a one-time password (OTP), users need to provide their PVN as a confirmation number to obtain the OTP. If your policy also requires a user to enter a PVN as part of the OTP challenge, the user must enter the PVN twice. Ideally, the user should enter the PVN just once. There are two ways to deal with this:

●       Use JavaMail to deliver an OTP because no confirmation number is required. So, if the policy requires a user to enter a PVN as part of an OTP challenge, the user enters the PVN just once.

●       Continue using Authentify, and change the PVN policy to not require a PVN with an OTP. This way, the PVN is optional.

For information about OTP delivery, see Configuring delivery mechanisms for one-time passwords .
