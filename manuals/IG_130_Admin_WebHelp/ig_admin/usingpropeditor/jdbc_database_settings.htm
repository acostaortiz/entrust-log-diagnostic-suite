IdentityGuard Server 13.0 Administration Guide

JDBC Database Settings

These properties set up the configuration for one or more database repositories. You can store your Entrust IdentityGuard user data across more than one repository, and the repositories can be of different types (LDAP directories and databases). This allows you complete flexibility in how you organize data. For example, you could have normal users of a group in an LDAP repository and all administrators of that group in a database repository. See Setting up user, grid card, and token repositories for more details and to view a snapshot of the properties.

If you make changes to any of these properties, you must restart the Entrust IdentityGuard Server service to pick up the changes.

Note: Where the default property values are given in the property descriptions, these are the defaults that apply to the default database Configuration Instance at installation. You can change the settings in the default instance and those settings are used for the defaults for subsequent instances that you create.

Configuration Instances

Lists all current JDBC database configurations. Initially, a default configuration exists if you selected a database repository during installation.

To create a new instance, enter a unique name in the empty field and click Add.

When you create a second or subsequent JDBC repository, it inherits the property values defined for the default JDBC repository.

Note: The default database Configuration Instance is always named database.

To delete an instance, select it in the list and click Remove.

JDBC Driver URL

identityguard.jdbc.url

Provides the URL used to connect to the database server. You can enter multiple URLs separated by spaces as part of a high-availability setup. Any timeout and credential settings apply to all URLs in the list. For the default instance, the initial value is set during configuration.

Database Description

identityguard.jdbc.description

Provides a description of the repository. The text is used by the Administration interface. The description must be unique for all repositories, including both database and directory server.

Default: the instance name

Database Type

identityguard.jdbc.type

Specifies the type of database to be use with Entrust IdentityGuard. Set this property to enable setting of database-specific option.

Choose from the database types: Not specified, DB2, MySQL, Oracle, PostreSQL, SQLServer, Custom...

Default: PostgreSQL

JDBC Driver Class Name

identityguard.jdbc.driverClass

Provides the name of the JDBC driver class. The value for the default database is set if you selected a database repository during installation.

This value is vendor-dependent.

Default: If you are setting up a custom Configuration Instance and you do not specify this property, it defaults to the value used by the default Configuration Instance.

Database User Name

identityguard.jdbc.user

Provides the ID of the user used to access the database. The value for the default database is set if you selected a database repository during configuration. Changing this may disrupt access to the database.

Default: If you are setting up a custom Configuration Instance and you do not specify this property, it defaults to the value used by the default Configuration Instance.

Database User Name Password

identityguard.jdbc.password

Provides the password of the database user entered during configuration. By default, the password is encrypted. Changing this may disrupt access to the database.

Default: If you are setting up a custom Configuration Instance and you do not specify this property, it defaults to the value used by the default Configuration Instance.

Database Schema Name

identityguard.jdbc.schema

Provides the name of the database schema used to store Entrust IdentityGuard data. The value for the default database Configuration Instance is set if you selected a database repository during configuration. Changing this may disrupt access to the database.

Primary Database Maximum Reconnect Interval

identityguard.jdbc.ha.maxrestoretimeout

Sets the maximum time in hours between attempts to connect to the primary database (the first database URL defined). Use this as part of a high-availability setup.

Default: 24

Table For Testing Database Connections

identityguard.jdbc.ha.testTable

All pooled connections are tested prior to being returned to a connection pool to ensure they are still valid. This identifies the table to use for testing the connection. The value for the default database is set if you selected a database repository during configuration.

Select Custom to enter a table name that is different than those associated with each Entrust IdentityGuard- supported database.

Run Database Connection Test When Failover is not Enabled

identityguard.jdbc.ha.runConnectionTest

Set this property to true to enable database connection testing to be run even when only a single database driver URL is provided.

Providing a single URL means failover in Entrust IdentityGuard is not enabled (although it may still be provided by the database driver outside the direct control of Entrust IdentityGuard) and connection testing is not required.

Connection testing is always performed if multiple database driver URLs are provided, regardless of this setting. Setting this property to true improves the ability of Entrust IdentityGuard to re-connect to a database after a connection failure, but it does reduce performance. To reduce the performance penalty, you can reduce the value of the Database Connection Test Interval property so the test is run less frequently.

Default: True

Database Connection Test Interval

identityguard.jdbc.ha.testInterval

In a high-availability setup where database connections are pooled or when Run Database Connection Test is True, this sets the time in seconds to wait between tests to see if a database connection is still valid. A setting of means the database is tested each time it is pulled from the pool.

Default: 50

Connection Pool Maximum Size

identityguard.jdbc.connectionpool.max

Sets the maximum number of connections that can be kept in the database connection pool. An Entrust IdentityGuard service does not open more connections than this value. In an enterprise environment, increase the setting to suit your needs (for example, to 2 or more).

If the database server cannot accept this number of connections, Entrust IdentityGuard may return errors when trying to open some of its connections.

Default: 10

Connection Pool Maximum Wait Time

identityguard.jdbc.connectionpool.maxWait

Sets the maximum time in milliseconds to wait when attempting to get a database connection from the pool.

Default: 30000 (30 seconds)

Idle Connection Minimum Close Time

identityguard.ldap.connectionpool.minIdleCloseTime

Sets the minimum number of milliseconds a pooled connection can be idle before being closed. This property works closely with the Idle Connections Check Time property.

Default: 180000 (3 minutes)

Idle Connections Check Time

identityguard.ldap.connectionpool.closeSchedule

Sets the number of milliseconds between each check for idle LDAP directory connections. Connections idle longer than the value set by the Idle Connection Minimum Close Time property are closed at each check.

A setting of means connections are never closed when idle.

Default: 180000 (3 minutes)

Database Login Timeout

identityguard.jdbc.logintimeout

Sets the number of seconds to wait for a database login operation to complete before returning an error.

Default: 30

Database Query Timeout

identityguard.jdbc.querytimeout

Sets the number of seconds that Entrust IdentityGuard waits for the database to perform an operation. A value of means that the connection never times out.

Default: 0

Database Fetch Size

identityguard.jdbc.fetchsize

Specifies the number of user records retrieved from the database and cached when listing users. When fetching potentially large objects like smart credentials, set this property to a smaller value. If set to 0, there is no limit to the fetch size.

Default: 20

Database BLOB Access

identityguard.jdbc.blobAccess

Sets BLOB access. Set this to False for Microsoft SQL Server, and to True for all other database types.

Default: True

Remove Abandoned Timeout

identityguard.jdbc.connectionpool.removeAbandonedTimeout

This property specifies the period of time, in seconds, after which abandoned objects will be removed when pool maintenance runs. The default value is 300 seconds.

SQL WHERE Clause Escaping

identityguard.jdbc.needsEscape

Indicates if Entrust IdentityGuard should use escape characters in an SQL Where clause. Set this to False for PostgreSQL and MySQL, and to True for all other database types.

Default: True

SQL SELECT Lock Syntax

identityguard.jdbc.selectLock

Sets what SQL syntax to use to lock a policy when it is updated. The value is set during configuration.

Default: varies with the database type

SQL TIMESTAMP Data Type

identityguard.jdbc.timestampDataType

Determines how timestamp expressions are formatted in an SQL Where clause. If you set this property to True, the SQL Where clause includes the TIMESTAMP datatype. Set this to True for an Oracle database, MySQL, and PostgreSQL, and to False for DB2 and Microsoft SQL Server.

Default: True

SQL INSERT Clause Requires SEQUENCE

identityguard.jdbc.includeSequence

This property is used when a database is configured to store the audit data generated by Entrust IdentityGuard. It accounts for the different ways database vendors support auto-numbering columns that Entrust IdentityGuard uses for the audit sequence numbers.

Set to True for Oracle databases, and False for all other database vendors.

If you do not specify True for Oracle, you see the following error in the identityguard_system.log:

[IG Audit Writer] [ERROR] [IG.SYSTEM.AuditDBLogger.API] Error logging audit.java.sql.SQLException: ORA-14: cannot insert NULL into ("IDGUARD"."AUDITS"."AUDIT_SEQNO")

Default: False

SQL Search Includes NOLOCK

identityguard.jdbc.noLock

Determines whether Entrust IdentityGuard includes the NOLOCK clause in SQL search statements. For Microsoft SQL Server, set this property to True. For all other databases, set this property to False.

Skip Repository During Search if not Available

identityguard.ldap.skipOnSearchIfNotAvailable

If set to True for a particular repository, this property allows users on other repositories to authenticate to the Entrust IdentityGuard Authentication Service while the repository is unavailable. This allows services to continue to operate, with limited functionality, until the underlying issue with the searchbase or repository is addressed. Note that if the repository that contains policy information in not available, no operations can proceed.

This property works in conjunction with a timeout property. When a repository is unavailable, user operations slow down as the system polls available repositories and waits for a response from the one that is unavailable. Specify a low timeout value after which to skip the repository. The property to use to specify the timeout value depends on the type of repository you are using. For more information, see Mitigate performance degradation when a secondary repository is unavailable.

Note: This property is not used for the Active Directory synchronization feature.

Default: False

LDAP Sync Directory

identityguard.jdbc.ldapsyncdirectory

If set, this property specifies the name of the LDAP Sync Directory instance to be used with this database. Only one directory instance can be selected from the drop-down list. The value must be one of the configured LDAP Sync directories in this environment. The LDAP Sync directories that appear in the list are the LDAP Directory Server instances that have the LDAP Directory Specific Usage property set to SYNC.
