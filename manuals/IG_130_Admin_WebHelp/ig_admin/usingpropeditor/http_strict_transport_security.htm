IdentityGuard Server 13.0 Administration Guide

HTTP Strict Transport Security

This properties group provides an option to enable HTTP Strict Transport Security (HSTS), a web security technique that offers protection against TLS downgrade attacks. TLS downgrade attacks (also known as SSL stripping attacks) are a form of man-in-the-middle attack in which the attacker tricks the victim's browser into communicating with Entrust IdentityGuard over HTTP rather than the more secure HTTPS protocol.

HSTS prevents attacks by including a header in HTTP responses that tells the browser to require HTTPS on future connections to this server. A web browser ignores the HTTP Strict-Transport-Security header directive if the current TLS connection has any warnings or errors, or if it used a self-signed certificate. HSTS is a "trust-on-first-use" or "ratcheting" mechanism, meaning that a browser is still vulnerable during its first connection to a site, but subsequent connections are protected. For more information, see RFC 6797.

Entrust Datacard recommends enabling HSTS, but has chosen to have the HSTS properties disabled by default. Enabling HSTS introduces some risk that the service becomes unusable, and therefore requires extra care and attention while administering the site's TLS configuration. For example, if the server's TLS certificate expires, or if revocation information cannot be fetched, when users attempt to access the Administration interface, their browsers will display a message stating that the page is untrusted and they cannot proceed.

When the Enable HTTP Strict Transport Security property is set to True, the specified HTTP Strict-Transport-Security header with selected values is applied to the Properties Editor and the Administration Interface.

Enable HTTP Strict Transport Security

igsss.hsts.enabled

This property specifies whether the Entrust IdentityGuard Properties Editor and Administration interface should set the Strict-Transport-Security HTTP header when delivering content to a browser.

Default: False

HTTP Strict-Transport-Security Max Age

igsss.hsts.maxage

The time, in seconds, that the browser should remember that a site is only to be accessed using HTTPS. The default value is 31536000 seconds (365 days).

HTTP Strict-Transport-Security Include Sub Domains

igsss.hsts.includesubdomains

If the optional Enable HTTP Strict Transport Security setting is enabled, this property specifies whether HSTS should apply to all of the site's sub-domains.

HTTP Strict-Transport-Security preload

igsss.hsts.preload

Google maintains an HSTS preload service. By following the guidelines and successfully submitting a request to the domain where the Entrust IdentityGuard server is hosted, browsers never connect to the same domain using an insecure connection. While the service is hosted by Google, all browsers have stated an intent to use (or actually started using) the preload list. Note that this functionality is not part of the HSTS specification.
