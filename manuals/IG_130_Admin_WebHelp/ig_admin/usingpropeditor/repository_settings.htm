IdentityGuard Server 13.0 Administration Guide

Repository Settings

These properties control where Entrust IdentityGuard stores different types of data; in an LDAP directory, a JDBC database, a file-based repository, or possibly some combination of these.

If you add another repository after installation that has a different type (that is, you add a database when you originally specified an LDAP directory as your repository, or vice versa), then you can adjust these properties to make use of the additional repository. You can also change the default settings for your unassigned token and preproduced card file-based repositories when using LDAP as your repository type.

For an explanation of repositories and to view a snapshot of the properties, see Specifying multiple repositories. For instructions on changing from a file-based repository to a database, see Configuring token and grid card repositories.

Card/User Repository Implementation Classes

identityguard.cardRepository.impl

Specifies the type of storage location to be used for users and their assigned cards on the primary system. The Properties Editor sets the correct class name (or names) based on your selection of repository type.

Your user and associated card information can be stored in a database, a directory, or both. If you specify both, you are forced to choose one as the default, either database or directory.

Select Custom to specify your own repository class name. (Used only in highly advanced deployments.)

Policy Repository Implementation Class

identityguard.policyRepository.impl

Specifies the type of storage location to be used for the policies on the primary system. Pick a repository option from the drop-down list. The Properties Editor sets the correct class name based on your choice.

Select Custom to specify your own repository class name. (Used only in highly advanced deployments.)

Policy Repository Cache Timeout

identityguard.policyRepository.cacheTimeout

Sets the time in milliseconds that a policy is cached before the repository is checked for new policy definitions. Setting the value to disables policy caching and forces the policy to be accessed from the repository on every operation. This can slow performance.

Default: 30,000 (30 seconds)

Preproduced Card Repository File Name

identityguard.preproducedCardRepository.file.name

For a file-based repository, specifies the base name of the file on the primary server used to store preproduced cards.

Default:

•  On Linux $IG_HOME/etc/fpcr/fpcr.pcr

•  On Windows <$IG_HOME>\etc\fpcr\fpcr.pcr

Note: Leave this setting blank for a replica server or if unassigned cards are stored in a database.

Preproduced Card Repository Maximum Number Of Cards Per File

identityguard.preproducedCardRepository.file.maxsize

Sets the maximum number of cards each component of the file-based repository can store, when using a file-based repository for preproduced cards.

Default: 200

If you deploy cards for over 100,000 users in a directory, and you still want to use file-based card preproduction, set this property to a value higher than 200. The value should be the (approximate) number of cards, divided by 500. For example 100,000 cards divided by 500 equals 200.

Note: The preproduced card repository needs approximately 0.5 KB of memory per card. Therefore, 100,000 cards use about 50 MB of memory.

Note: Leave this blank for a replica server.

Token Repository Implementation Class

identityguard.tokenRepository.impl

Specifies the type of storage location to be used for unassigned tokens on the primary system. When using a directory, the default is a file-based repository but you can switch to a database if you configure one after installation.

Pick a repository option from the drop-down list. The Properties Editor sets the correct class name based on your choice.

Select Custom to specify a custom repository class name. (Used only in highly advanced deployments.)

Note: For a replica server, select None.

Token Repository File Name

identityguard.tokenRepository.file.name

For a file-based repository, specifies the base name of the file on the primary server used to store unassigned tokens.

Default:

•  On Linux $IG_HOME/etc/ftkr/ftkr.pcr

•  On Windows <$IG_HOME>\etc\ftkr\ftkr.pcr

Note: Leave this setting blank for a replica server or if unassigned tokens are stored in a database.

Token Repository Maximum Number of Tokens Per File

identityguard.tokenRepository.file.maxsize

Sets the maximum number of tokens each component of the file-based repository can store, when using a file-based repository for unassigned tokens.

Default: 200

Note: Leave this blank for a replica server.

Smart Credential Repository Implementation Class

identityguard.smartCredentialRepository.impl

Sets the location or locations where unassigned smart credentials are stored. Select a repository option from the drop-down list. Entrust IdentityGuard sets the correct Java class name based on your selection.

When using a directory with your primary Entrust IdentityGuard server, the default is a file-based repository, but you can switch to a database. If the Entrust IdentityGuard server is a replica server and the primary server is using a file-based repository, select None (Replica Nodes). Select Custom to specify your own repository class name.

Default: Database (JDBC)

Smart Credential Repository File Name

identityguard.smartCredentialRepository.file.name

If unassigned smart credentials are stored in a file-based repository, then this property specifies the location of the file used to store unassigned smart credentials. If this repository is a replica server, or if unassigned smart credentials are stored in a database, do not specify a location.

Default: $identityguard.home/etc/fscr/fscr.pcr

Smart Credential Repository Maximum Number of Smart Credentials per File

identityguard.smartCredentialRepository.file.maxsize

If unassigned smart credentials are stored in a file-based repository, then this property specifies the maximum number of smart credentials each component of the file-based repository can store. If the repository is a replica server, do not specify a value.

Default: 200

Sync Repository Implementation Class

identityguard.syncRepository.impl

Specifies whether external user information should be synchronized when using an Entrust IdentityGuard database. Select a repository option from the drop-down list depending on whether this is an Entrust IdentityGuard server that supports synchronization into an Entrust IdentityGuard database repository or not. If it does, then an LDAP directory with synchronization is required to be configured.

At least one LDAP directory configuration must be configured.

Options are

•  None

•  Directory Synchronization with IdentityGuard Databases – Select this option if you are using the LDAP directory synchronization feature.

•  Custom – Select this option only if directed by Entrust Datacard.

Default: None

Anonymous Challenge Repository Implementation Class

identityguard.anonymousCertChallengeRepository.impl

This property sets the Java classes used for the anonymous security challenge repository. Select a repository option from the drop-down list. Entrust IdentityGuard sets the correct class names based on your selection. Select Custom to specify your own repository class name.
