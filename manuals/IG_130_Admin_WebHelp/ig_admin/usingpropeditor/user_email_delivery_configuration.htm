IdentityGuard Server 13.0 Administration Guide

User Email Delivery Configuration

Your application can automate email delivery of many kinds of information. For example, you can set up delivery of passwords, one-time passwords, smart credential PINs and unblock responses, eGrids, soft token activation information, and more. Additional information can be found in the chapters for each authentication type for which this configuration is relevant.

Email delivery template best practices

These best practices apply to any type of authentication method that supports sending information to users by email.

Entrust IdentityGuard provides TXT and HTML format message templates to simplify your work of communicating with users about their Entrust IdentityGuard authenticators.

You can find the template files in the following location:

●       on Windows

<$IG_HOME>\etc\templates\<authenticator type>\

●       on Linux

$IG_HOME/etc/templates/<authenticator type>/

The names of the templates describe the scenario each can be used for.

 

All email messages use the template named in the Email Delivery Template File property.

Customize the templates

You can modify the templates to meet your needs. You can customize the contents to add branding and standard messages or disclaimers, or to delete parts of the message that are not relevant to your use case.

Make a copy of any template file you want to customize so you you can revert to the original if required. Give your new templates descriptive names so they are easy to match to their use case.

Entrust IdentityGuard provides .txt and .html format message templates. Customize both the .txt and .html versions of the template, but specify the .txt file in the Email Delivery Template File property. This ensures that the message can be displayed by any type of email client. The .txt template is used by email clients that display only plain text content. When there is a corresponding template of the same name but with the .html extension, Entrust IdentityGuard creates a MIME multi-part alternative message using the .txt template and the .html template so that any email clients that can display HTML display the HTML version.

The .txt and .html versions of the templates must be located in the same directory.

You must use UTF-8 as the character-encoding format for the email template.

All of the templates use Apache Velocity syntax. For information about this syntax, see http://velocity.apache.org/engine/2.2/user-guide.html.

Configuration Instances

Provides a list of email configurations.

To create a new instance, enter a unique service name in the empty field and click Add. The other properties appear. The name replaces the {0} placeholder.

To delete an instance, select it in the list and click Remove.

There is no default configuration.

Email Delivery Class Name

identityguard.user.delivery.smtp.{0}.impl

Sets the Entrust IdentityGuard Java class used for email. When you select Email, this sets this class:

com.entrust.identityGuard.common.smartCredentialDelivery.email.SmartCredentialEmailDelivery

If you select Custom, enter a valid Java class name in the field that appears. (Used only in highly advanced deployments.)

Email Delivery Configuration Display Name

identityguard.user.delivery.smtp.{0}.displayname

The name you use to identify this delivery mechanism.

This is the name you see in the Administration interface when associating the user contact information to the delivery method.

Default: the instance name

Email Delivery Configuration Type

identityguard.user.delivery.smtp.{0}.type

The content of the delivery email. Options include:

•  Grid – Used to deliver a grid to a user.

•  Password – Used to deliver a password.

•  PVN – Used to deliver a PVN.

•  Token – Used to deliver soft token information.

•  Token Activate – Used to deliver a mobile soft token QR code and password to a user.

•  User – Used to deliver

•  User Temporary PIN – Used to deliver a temporary PIN.

•  Smart Credential Activate – Used to deliver smart credential information.

•  Smart Credential PIN – Used to deliver the smart card PIN to the user.

•  Smart Credential Unblock – Used to deliver the unblock code to the user.

•  Smart Credential – Used to deliver any details about the smart credential to the end user or administrator. For instance, it can be used to send an email with the building access number to the facility manager.

Email Delivery SMTP Server

identityguard.user.delivery.smtp.{0}.smtp

Select the SMTP Server from the drop-down list.

This list of servers is defined using the SMTP Server properties. See SMTP Server Configuration (22).

Email Delivery Template File

identityguard.user.delivery.smtp.{0}.template

Provides the location of the email template to be used for delivering information to users. Entrust IdentityGuard provides sample templates for email (and SMS messages) relating to several types of Entrust IdentityGuard authenticators. They are located in the following directories:

•  $identityguard.home/etc/templates/grids/

•  $identityguard.home/etc/templates/oob/

•  $identityguard.home/etc/templates/passwords/

•  $identityguard.home/etc/templates/pvn/

•  $identityguard.home/etc/templates/smartCredentials/

•  $identityguard.home/etc/templates/temporaryPIN/

•  $identityguard.home/etc/templates/tokens/

•  $identityguard.home/etc/templates/user/

For this property, enter

 $identityguard.home/etc/templates/<template_dir>/<template>

where

<template_dir> is the name of the directory or folder that contains the templates related to the type of authenticator you are configuring.

<template> is the name of the template to use.

Entrust IdentityGuard automatically replaces $identityguard.home with the correct value.

Example:

$identityguard.home/etc/templates/smartCredential/igsample_email_cardpin_template.txt

You can configure the templates as required in a text editor. The template is used by Entrust IdentityGuard to create each message sent to a user. For more information, see the chapters for specific types of Entrust IdentityGuard authenticators.

Email Delivery EGrid

identityguard.user.delivery.smtp.{0}.egrid

Specifies the EGrid to be emailed to the user.

Default: No EGrid

Email Delivery Enable QR Code Attachment

identityguard.user.delivery.smtp.egrid.qrCodeAttachment

This property specifies whether the QR Code attachment is included for token activation delivery emails.

Email Delivery Subject

identityguard.user.delivery.smtp.{0}.subject

Provides the text for the subject field of the email.

Email Delivery To Address Type

identityguard.user.delivery.smtp.{0}.totype

The type of email address you want to use. Options include:

•  Variable – The email address is pulled from an enrollment attribute. For example, the Enterprise sample definition includes emailaddressas an enrollment attribute for email. During enrollment, that user’s email address is collected and stored under the emailaddress enrollment attribute for their smart credential.

•  Constant – This is a “hard coded” email address that is used for all emails of this type. For example, facilitymanager@company.com. You must define that specific email address in the Email Delivery To Address setting.

Email Delivery From Address

identityguard.user.delivery.smtp.{0}.fromaddress

Provides the sender’s email address. Typically, this is an address within your organization.

Default: the server’s SMTP address

Email Delivery To Address

identityguard.user.delivery.smtp.{0}.to

Provides the destination of the email. This is dependent on your selection of the Email Delivery To Address Type setting above.

If you selected:

•  Variable – The value of this property is a variable name of one of the smart credential enrollment values. The value of that variable is used as the destination address.

For example, the Enterprise.xml sample definition includes emailaddress as a variable for email.

•  Constant – The value specified for this property is used as the destination address. For example, facilitymanager@company.com.

Email BCC Address

identityguard.user.delivery.smtp.{}.bcc

If supplied, all out-of-band emails are copied to this email address. The recipient does not see this address. Typically, this is an address within your organization.

Include Registration Password

identityguard.user.delivery.smtp.{0}.registrationPassword

If set to true, a registration password is created and included in the email notification when it is delivered.

Default: False

Registration Password Type

identityguard.user.delivery.smtp.egrid.registrationPasswordType

This property specifies the type of registration password that is created when the Include Registration Password value is set to true. The type value must match the type used by the application that will authenticate the registration password.
