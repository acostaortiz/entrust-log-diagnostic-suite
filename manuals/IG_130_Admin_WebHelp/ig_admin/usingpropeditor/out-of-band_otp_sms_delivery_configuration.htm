IdentityGuard Server 13.0 Administration Guide

Out-of-Band OTP SMS Delivery Configuration

Your application can automate the delivery of one-time passwords using a text (SMS) message to a cell phone. Using the following properties, you can set up delivery of the OTP by SMS messages through the Clickatell™, TeleSign® or a custom SMS delivery service. For more details, see Configure the SMS delivery mechanism.

Configuration Instances

Provides a list of SMS configurations.

To create a new instance, enter a unique name in the empty field and click Add. The other properties appear. The name replaces the {0} placeholder.

To delete an instance, select it in the list and click Remove.

There is no default configuration.

SMS Delivery Class Name

identityguard.oobdelivery.smsgateway.{0}.impl
Sets the Entrust IdentityGuard Java class used for communicating with the SMS delivery provider. Select Clickatell, TeleSign, or Custom.
If you choose Custom, you must program your own SMS delivery implementation.
Default: none

SMS Delivery Configuration Display Name

identityguard.oobdelivery.smsgateway.{0}.displayname

The name you use to identify this delivery mechanism.

This is the name you see in the Administration interface when associating the user contact information to the delivery method.

Default: none

SMS Gateway URL

identityguard.oobdelivery.smsgateway.{0}.url

The URL used as an API to deliver SMS messages through the use of an SMS gateway.

Examples:

https://api.clickatell.com/http/sendmsg?user=USERNAME&password=PASSWORD&api_id=API_ID&to=TO_PHONE&text=MSG_TEXT&from=FROM_ID

https://api.telesign.com/http/sendmsg?user=USERNAME&password=PASSWORD&api_id=API_ID&to=TO_PHONE&text=MSG_TEXT&from=FROM_ID

Note: If you are sending a one-time-password through a proxy that requires basic authentication, specify the user name and password in the gateway URL. For example:
https://myuser:mypass@example.com/http/sendmsg?user=USERNAME&password=PASSWORD&api_id=API_ID&to=TO_PHONE&text=MSG_TEXT&from=FROM_ID

User Name

identityguard.oobdelivery.smsgateway.{0}.userid

Specifies the Clickatell user name, TeleSign customer ID, or custom user ID to use when logging in to the service. The user name and password are provided by the SMS delivery provider when you register for their services.

Default: none

Password

identityguard.oobdelivery.smsgateway.{0}.password

Specifies the password to use when logging in to the service. The user name or customer ID and password are provided by the SMS delivery provider when you register for their services.

Select Encrypt to encrypt the password.

Default: none

Clickatell API ID

identityguard.oobdelivery.smsgateway.{0}.apiid

Specifies the API Identification obtained from Clickatell. (It is listed under the API Connections on Clickatell Central.)

Default: none

From Label in the SMS Message

identityguard.oobdelivery.smsgateway.{0}.from

Sets the From label in the SMS message sent by Entrust IdentityGuard.

For Clickatell: The From label is the Sender ID registered with Clickatell.

Note: If the contents of the From field is invalid, the message is still delivered. No error message is generated, but your Clickatell account manager may receive an email notice, as an anti-spam precaution, indicating that messages are coming from an invalid sender.

For TeleSign, the From label is not used.

Default: none

Separate Message Per One-Time Password

identityguard.oobdelivery.smsgateway.{0}.separatemessageperotp

When sending multiple one-time passwords over SMS, the delivery mechanism can separate them into several messages, rather than grouping all of the OTPs into one message.

Default: True

Include Transaction Details

identityguard.oobdelivery.smsgateway.{0}.includetransactiondetails

Specifies how transaction details will be sent.

The options are:

•  First – The first message contains the transaction details, along with a one-time password. The following messages each contain only an OTP.

•  Separate – The first message contains the transaction details, and the following messages each contain an OTP.

•  All – The transaction details are included in each message sent, along with an OTP.

Default: First

SMS Delivery Template File

identityguard.oobdelivery.smsgateway.{0}.template

Specifies the location of the SMS message template file.

The template file provides the body of the SMS message sent to the user.

The default template is in the following location:

$IG_HOME/etc/templates/oob/igsample_sms_template.txt

For TeleSign, consider editing the default template wording to accommodate the TeleSign limitation of one OTP per message.

Example of the modified file:

#if ($otp)

One-time password is $otp[0]

#end

#if ($expiryDate)

Expires: $expiryDate

#else

Never Expires

#end

Prepend Digits for SMS Recipients

identityguard.sms.{0}.prependdigit

SMS service providers require that all SMS recipients follow a universal numbering standard (E.164).

This property defines a digit (country code) to add to the beginning of all contact numbers using this configured out-of-band delivery mechanism. Use this property if the user contact information does not include the country code.

Default: none

SMS Unicode Encoding

identityguard.oobdelivery.smsgateway.{0}.unicode

If the SMS message contains any characters outside of the Basic Latin character set (Unicode Latin-1 Supplement characters, for example), set this property to True.

This imposes a shorter limit on SMS messages: messages containing more than 70 characters might be divided and sent as several messages.

Attention: Sending Unicode messages to a network that does not support such messages will not generate an error: the message will be lost, without any notifications that the message has not been delivered. You must verify with Clickatell that Unicode is supported for the end user before enabling this feature.

Default: False

SMS Message Fragmentation

identityguard.oobdelivery.smsgateway.{0}.fragmentation

For Clickatell, set this property to True to allow long SMS messages to be divided into separate messages. By default, the message is split at 160 characters (or 70 characters if the SMS Unicode Encoding property is true). This limit is configurable through the SMS Message Fragmentation Character Limit property.

Set this property to False to prevent long SMS messages from being divided into separate messages.

If this property is set to False, and the message is too long to be sent as a single message, no message is sent, and an error is written to the log file.

Attention: TeleSign SMS messages cannot be fragmented. Only one OTP can be sent in a message, so if a user requires multiple OTPs, they are sent in multiple messages. The message length cannot exceed 140 characters. If the message exceeds this length, the excess characters are discarded. They are not sent in additional messages. No error message is logged.

Default: False

SMS Message Fragmentation Limit

identityguard.oobdelivery.smsgateway.{0}.fragmentationlimit

Sets the maximum number of messages that will be sent when a long SMS message is split.

This property is used only when SMS Message Fragmentation is set to True.

Default: 5

SMS Message Fragmentation Character Limit

identityguard.oobdelivery.smsgateway.{0}.fragmentationcharlimit

Sets the number of characters after which a message is split. The default is 160 characters, unless the SMS Unicode Encoding property is True, in which case the limit is 70.

For example, if an SMS message is 250 characters in total, and the SMS Message Fragmentation Character Limit is 100, then the message is split into 3 messages: the first two containing 100 characters each, and the last one containing 50 characters.

This property is used only when SMS Message Fragmentation is set to True.

SMS Message Fragmentation Split Characters

identityguard.sms.SMS Server.splitchars

Sets which characters are used to decide where a message is split. To specify more than one split character, separate each with a space. The following special characters are supported:

\s (space)

\t (tab)

\n (new line)

The default is to split at whitespace characters (spaces, tabs, and new lines). If the message does not contain a split character, the message is split at the maximum message size.

This property is used only when SMS Message Maximum Fragmentation is set to True.
