IdentityGuard Server 13.0 Administration Guide

LDAP Directory Server Settings

These properties set up the configuration for one or more LDAP repositories. You can store your Entrust IdentityGuard user data across more than one repository, and the repositories can be of different types (LDAP directory or database). This allows you complete flexibility in how you organize data. For example, you could have normal users of a group in an LDAP repository and all administrators for that group in a database repository. Also see Setting up user, grid card, and token repositories for more details and to view a snapshot of the properties.

Note: Where the default property values are given in the property descriptions, these are the defaults that apply to the default directory Configuration Instance at installation. You can change the settings in the default instance and those settings are used for the defaults for subsequent instances that you create.

Configuration Instances

Lists all current LDAP directory configurations. Initially, a default configuration exists if you selected a directory repository during installation.

To create a new instance, enter a unique name in the empty field and click Add.

When you create a second or subsequent LDAP repository, it inherits the property values defined for the default LDAP repository.

To delete an instance, select it in the list and click Remove.

LDAP URL

identityguard.ldap.url

Provides the URL used to connect to the LDAP directory server. This can include a port number and initial context prefix to bind to. Encode spaces in the URL as %20. All lookups are relative to the given context prefix.

Syntax:

<ldap_server_URL>:<port>/<search_base>

Where:

<ldap_server_URL> is the URL to your LDAP directory, including the ldap:// or ldaps:// prefix

<port> is the LDAP port. The port is optional if you are using the default port (389 for LDAP; 636 for LDAPS)

<search_base> is the searchbase to connect to. For more information, see Using a searchbase.

For example

ldap://myldaphost.com:389/ou=People, dc=AnyCorp,dc=com

binds to port 389 on the computer myldaphost, with ou=People,dc=AnyCorp,dc=com as the context prefix.

You can enter multiple URLs separated by spaces as part of a high-availability setup. For the default instance, the initial value is set during configuration.

Directory Server Description

identityguard.ldap.description

Provides a description of the repository. The text is used by the Administration interface. The description must be unique for all repositories, both LDAP and database.

Default: the instance name

LDAP Vendor

identityguard.ldap.vendor

Sets the type of LDAP repository being used to store users. This setting is required if users that are disabled in the LDAP repository are to be automatically suspended in Entrust IdentityGuard. The LDAP directory vendor is also required if you want to be able to automatically extract user contact information directly from the repository.

Note: When you select an LDAP vendor, you enable features that let you manage disabled and expired user accounts (if supported by the selected vendor). To explicitly disable the these features, you must set the Repository Data policies to False. For more information, see Repository Data policies.

Note: If you are using LDAP synchronization with an Entrust database (which means that the LDAP Directory Specific Usage property is set to SYNC), Active Directory and Red Hat are the officially supported vendors.

The choices are:

•  Not specified

•  Active Directory

•  AD LDS

•  CA Directory

•  eDirectory

•  OpenLDAP

•  Oracle

•  Red Hat

•  Oracle Unified Directory

•  Sun ONE

•  Tivoli

•  UnboundID

•  Custom

Default: Not specified

Primary Directory Server Maximum Reconnect Interval

identityguard.ldap.ha.maxrestoretimeout

Sets the maximum time in hours between attempts to reconnect to the primary directory (the first directory URL defined) when the current in-use directory is not the primary. Use this as part of a high-availability setup.

Default: 24

Directory Server Connection Test Interval

identityguard.ldap.ha.testInterval

In a high-availability setup where directory connections are pooled, this sets the time in seconds to wait between tests to see if a directory connection is still valid. A setting of means the directory is tested each time it is pulled from the pool.

Default: 0

SSL LDAP Connection

identityguard.ldap.sslEnabled

Specifies if you are using a secure (SSL) connection to the directory. If set to True, make sure the URL in the LDAP URL property refers to a secure port (such as 636).

Default: False

Disable SSL Host Name Verification

identityguard.ldap.disableSslHostnameVerification

If you are using a secure (SSL) connection to the directory, set this to False. This should be True only for debugging purposes because True creates a security risk.

Default: False

Enable SSL Block Ciphers

identityguard.ldap.enableSslBlockCiphers

Determines whether or not to use SSL block ciphers. If False, SSL connects to LDAP using stream ciphers. Set this property to True if your directory server doesn't support stream ciphers for SSL.

Default: False

Directory Administrator

identityguard.ldap.principal

Names the user entity binding to the LDAP directory set during configuration, for example:

cn=Directory Manager

Required access to the LDAP directory server:

Read access only: If you are setting up LDAP synchronization, this administrator account needs read access to the LDAP directory server to enroll users in Entrust IdentityGuard. The administrator does not require write access because communication is one way, with LDAP data being copied to the Entrust IdentityGuard database.

Read and write access:  Read and write access are required in the following scenarios:

•  If your organization uses Entrust IdentityGuard External authentication and you want users to be able to change expired LDAP passwords when authenticating, this administrator account must have write access to the LDAP directory (in addition to read access) to write the new passwords to the LDAP directory. In this case, if you are using Active Directory, an SSL connection is also required to be able to change passwords. For more information, see "Expired Password Allows Change (LDAP)" in External First-Factor Authentication.

•  If you host Entrust IdentityGuard user data in your organization's LDAP directory, this administrator account must be able to add and remove object classes and attributes from all entries in the LDAP directory.

Default: If you are setting up an additional Configuration Instance and you do not specify this property, it defaults to the value used by the default Configuration Instance.

Directory Administrator Password

identityguard.ldap.credentials

Provides the password of the directory administrator entered during configuration. By default, the password is encrypted.

Depending on your directory password policies, this password might expire and need to be updated. See Update the directory password.

Default: If you are setting up an additional Configuration Instance and you do not specify this property, it defaults to the value used by the default Configuration Instance.

User ID Attribute

identityguard.ldap.useridattribute

Sets the LDAP directory attribute that contains the unique user identifier.

Default: cn

Disabled Account Attribute

identityguard.ldap.accountDisabledAttribute

Sets the LDAP directory attribute and value to interpret as meaning the user account is disabled.

Choose one of the following options. See Suspend disabled and expired LDAP users for more information about how these options are interpreted.

•  Vendor Default, use the default mapping for the directory specified in LDAP Vendor, if a default exists.

•  ds-pwp-account-disabled (Unbound ID), use the Unbound ID way of determining if a user account is disabled.

•  dxPwdLocked (CA Directory), use the IBM Tivoli way of determining if a user account is disabled.

•  ibm-pwdAccountLocked (Tivoli), use the IBM Tivoli way of determining if a user account is disabled.

•  loginDisabled (eDirectory), use the eDirectory way of determining if a user account is disabled.

•  msDS-UserAccountDisabled (AD LDS), use the AD LDS way of determining if a user account is disabled.

•  nsAccountLock (Sun ONE/Red Hat), use the Sun ONE way of determining if a user account is disabled.

•  orclIsEnabled (Oracle Internet/Oracle Unified), use the Oracle way of determining if a user account is disabled.

•  userAccountControl (Active Directory), use the Active Directory way of determining if a user account is disabled.

•  Custom, specify an attribute and value to interpret as meaning the user account is disabled. This field contains an attribute and value in the following form: attribute;value_meaning_disabled

Where:

attribute is the name of the LDAP directory attribute to check to find out if the user account is disabled. The attribute name is not case sensitive.

value_meaning_disabled is optional. If provided, it is the value of the attribute that means the user account is disabled. If the attribute is multi-valued, the first value returned is checked for a match. If this value matches the <value_meaning_disabled> parameter in this property, the user account is treated as disabled.

Also, if value_meaning_disabled is not provided, the existence of the named attribute is interpreted as the user account being disabled.

Default: Vendor Default

Expired Account Attribute

identityguard.ldap.accountExpiredAttribute

Sets the LDAP directory attribute and value to interpret as meaning the user account has expired.

Choose one of the following options. See Suspend disabled and expired LDAP users for more information about how these options are interpreted.

•  Vendor Default, use the default mapping for the directory specified in LDAP Vendor, if a default exists.

•  accountExpires (AD/AD LDS), use the AD/AD LDS way of determining if a user account has expired.

•  loginExpirationTime (eDirectory), use the eDirectory way of determining if a user account has expired.

•  orclActiveEndDate (Oracle Internet/Oracle Unified), use the Oracle way of determining if a user account has expired.

•  Custom, specify an attribute to interpret as meaning the user account has expired.

When you select Custom, you must enter an attribute, which is the name of the LDAP directory attribute to check to find out if the user account has expired. The attribute name is not case sensitive, but it must have a GeneralizedTime syntax.

Note: If this property is not used, and the directory vendor configured for the searchbase has no rules for determining whether user accounts have expired, then all users accounts are treated as not being expired.

Full Name Attribute

identityguard.ldap.fullNameAttribute

Indicates an attribute in a user's entry in the directory that contains the user’s full name. This attribute is mapped to the Entrust IdentityGuard user full name whether user enrollment is enabled or not. However, user enrollment and the LDAP synchronization variation of the enrollment feature both make use of this attribute if it is set.

If the Full Name Attribute property is not set, then no full name mapping is applied.

Many directory servers us the attribute displayName to specify a user's full name.

Apply Contact Info Mappings

identityguard.ldap.applyContactInfoMappings

Specifies a comma-separated list of LDAP contact information mappings to apply to this LDAP instance.

If user enrollment is enabled, including the LDAP synchronization variation of this feature, this attribute is used, if set.

The mappings are case-sensitive.

The mappings are applied in the order in which they are listed in the property, so choose their order carefully.

For example, if multiple contact information mappings map to the same contact information label, only the first mapping is applied. Contact information mappings are defined in the LDAP Contact Info Mapping Settings properties group.

Note: It is recommended that you configure the mail and telephoneNumber property group instance names. When they are configured, you can map contact information to them.

For more information, see Map contact info from an LDAP directory.

LDAP Connection Timeout

identityguard.ldap.connecttimeout

Sets the time in milliseconds to wait for a directory connection operation to complete before returning an error.

Default: 3000 (3 seconds)

LDAP Search Timeout

identityguard.ldap.searchtimeout

Sets the time in milliseconds to wait for a directory search operation to complete before returning an error. A setting of means no timeout occurs.

Default: 3000 (3 seconds)

LDAP Maximum Search Limit

identityguard.ldap.sizelimit

Sets the maximum number of LDAP entries to return in a single search operation.

Set this property to a value that is less than or equal to your Server Administrative Size Limit.

Default: 1000

Offset to the LDAP Maximum Search Limit

identityguard.ldap.sizelimitoffset

This property specifies the offset to the maximum number of entries to return in a single search operation. This is used in cases where internal user numbers are duplicated between users and user searches result in LDAP size

limit errors. If the value is zero, an offset is not used. If the value is greater than or equal to the LDAP Maximum Search Limit, then this value will be one less than that value. The default is 50.

Use Offset to the LDAP Maximum Search Limit Immediately

identityguard.ldap.sizelimitoffsetimmediately

This property specifies whether the LDAP Maximum Search Limit Offset value should be used immediately when searching for users. If set to false, a full size search is attempted first. If a full size search cannot be performed, a search using the offset will be used. If set to true, the offset is used immediately. The default is False.

Connection Pool Maximum Size

identityguard.ldap.connectionpool.max

In a high-availability setup, sets the maximum number of connections that can be kept in the LDAP directory connection pool.

An Entrust IdentityGuard service does not open more connections to the directory than this value.

Default: 50

Connection Pool Maximum Wait Time

identityguard.ldap.connectionpool.maxWait

Sets the maximum time in milliseconds to wait when attempting to get a directory connection from the pool.

Default: 30000 (30 seconds)

Idle Connection Minimum Close Time

identityguard.ldap.connectionpool.minIdleCloseTime

Sets the minimum number of milliseconds a pooled connection can be idle before being closed. This property works closely with the Idle Connections Check Time property.

Default: 180000 (3 minutes)

Idle Connections Check Time

identityguard.ldap.connectionpool.closeSchedule

Sets the number of milliseconds between each check for idle LDAP directory connections. Connections idle longer than the value set by the Idle Connection Minimum Close Time property are closed at each check.

A setting of means connections are never closed when idle.

Default: 180000 (3 minutes)

Remove Abandoned Timeout

identityguard.ldap.connectionpool.removeAbandonedTimeout

This property specifies the period of time, in seconds, after which abandoned objects will be removed when pool maintenance runs. The default value is 300 seconds.

Include Subseconds with Generalized Time

identityguard.ldap.GeneralizedTimeWithSubSecs

Some LDAP directories do not support generalized time attributes that contain subseconds (1ths of a second), while other directories require them. If this value is set to True, generalized time is formatted with subseconds. Make sure this to False for a Novell eDirectory. The correct setting is made during installation.

Default: True

LDAP Directory Specific Usage

identityguard.ldap.subtype

Identifies a special usage for this LDAP directory.

Options are:

•  NONE – Use for all cases except when this LDAP directory is used for synchronizing users with an Entrust IdentityGuard database.

•  SYNC – Use this option when the LDAP directory is used for synchronization of an LDAP repository with an Entrust IdentityGuard database.

Note: Currently, Microsoft  Active Directory and Red Hat Directory Server are officially supported.

Note: If this property is set to SYNC, then the Repository setting Sync Repository Implementation Class  must be set to Directory Synchronization with IdentityGuard Databases. The directory can be used only for synchronization and not any other purpose.

Default: NONE

User ID Case Sensitivity

identityguard.ldap.useridcasesensitive

Specifies whether the user ID attribute is case-sensitive.

Default: False

Policy Directory Entry

identityguard.ldap.policyentry

Sets the LDAP directory entry that stores policy information. The value is relative to the context prefix in the LDAP URL.

Default: If you are setting up a custom Configuration Instance and you do not specify this property, it defaults to the value used by the default Configuration Instance.

User Object Class

identityguard.ldap.userObjectClass

Specifies the directory object class used to allow user attributes to be added to an entry.

Note: This property is not used for the Active Directory synchronization feature.

Default: entrustIGUser

Add User Object Class

identityguard.ldap.addUserObjectClass

Indicates whether the Entrust IdentityGuard server should add the user object class when setting up an Entrust IdentityGuard user, or if it is expected to already be present. The object class must be present for Active Directory.

Set it to False for Active Directory and to True for any other LDAP directory.

Note: This property is not used for the Active Directory synchronization feature.

Default: True

Policy Object Class

identityguard.ldap.policyObjectClass

Specifies the directory object class used to allow policy attributes to be added to an entry.

Note: This property is not used for the Active Directory synchronization feature.

Default: entrustIGPolicy

Add Policy Object Class

identityguard.ldap.addPolicyObjectClass

Indicates whether the Entrust IdentityGuard server should add the policy object class when setting up the Entrust IdentityGuard policy, or if it is expected to already be present. The object class must be present for Active Directory.

Set it to False for Active Directory and to True for any other LDAP directory.

Note: This property is not used for the Active Directory synchronization feature.

Default: True

Entrust IdentityGuard User Entry Object Class

identityguard.ldap.IGUserEntryObjectClass

Specifies the object class (a string) that allows the user object class to be included in searches. It is especially useful when creating a new user.

Note: If this property is used, all Entrust IdentityGuard users must have this object class in their user records for searches to work.

Note: This property is not used for the Active Directory synchronization feature.

Default: The default is to omit this search filter; and there is no impact if it is not specified.

Use Optimized Filter

identityguard.ldap.useOptimizedFilter

When this property is set to True, Entrust IdentityGuard reformats the search filter used when searching for a user in the LDAP repository. For some directories, this results in faster search performance.

Set this property to False if your upgrade path has continued from Entrust IdentityGuard 7.x, and there is still user data that was not used for authentication (and therefore not updated in the Administration interface) while you were running Entrust IdentityGuard 8.1.

Note: This property is not used for the Active Directory synchronization feature.

Default: True

Follow Referrals Returned by the Repository

identityguard.ldap.followreferrals

Indicates whether or not the Entrust IdentityGuard server should follow referrals returned by your LDAP repository. Setting this to True may lead to connection timeouts, if the directory returns referrals that cannot be followed.

Note: This property is not used for the Active Directory synchronization feature.

Default: False

Skip Repository During Search if not Available

identityguard.ldap.skipOnSearchIfNotAvailable

If set to True for a particular repository, this property allows users on other repositories to authenticate to the Entrust IdentityGuard Authentication Service while the repository is unavailable. This allows services to continue to operate, with limited functionality, until the underlying issue with the searchbase or repository is addressed. Note that if the repository that contains policy information in not available, no operations can proceed.

This property works in conjunction with a timeout property. When a repository is unavailable, user operations slow down as the system polls available repositories and waits for a response from the one that is unavailable. Specify a low timeout value after which to skip the repository. The property to use to specify the timeout value depends on the type of repository you are using. For more information, see Mitigate performance degradation when a secondary repository is unavailable.

Note: This property is not used for the Active Directory synchronization feature.

Default: False

Paging Supported

identityguard.ldap.supportsPaging

Some LDAP directories support viewing of search results by pages, with each page displaying a certain number of results. Search results paging is required for the user enrollment feature to find all users in a directory instead of just the maximum number of search results that can be shown on a single page (1000). Currently, paging is known to work with Microsoft Active Directory, Microsoft Active Lightweight Directory Services, and Red Hat Directory Server (version 8.2 and newer). If you are using the user enrollment feature to find all users in a directory and you are using a directory that supports paging, set this property to True. Otherwise, leave the default setting, False, because setting it to True on a directory that does not support paging can result in errors.

Note: Some directories, for example, IBM Tivoli, support a form of search results paging in which all searches must be performed using the same connection to the directory. Entrust IdentityGuard does not support this form of paging.

Default: False

User Enrollment

identityguard.ldap.enroll.enabled

This property determines whether Entrust IdentityGuard allows user enrollment from the LDAP repository specified in this configuration instance. Set to True to allow Entrust IdentityGuard to search for non-user accounts in the LDAP directory.

Note: This property affects only the operations to create multiple users or create selected users. You can always create or synchronize single users, provided the user exists in the LDAP repository.

If the directory specified in this configuration instance is used with the LDAP synchronization feature, the property is set to True automatically and cannot be changed as long as the directory is used for LDAP synchronization..

Default: False

User Enrollment Search Attributes

If user enrollment is enabled, this property can be used to search for users in the current directory who are candidate Entrust IdentityGuard users. This property contains a comma-separated list of user attributes that should be searched for in combination with an administrator-provided search value. This is applicable both when an Entrust IdentityGuard account is being created within the current directory, and when it is being synchronized into a database. An example of search attributes would be cn,sAMAccountName,mail. When searching for a user to enroll, an administrator provides a value that is tested against each of the attributes specified. A match against any of them means that the given user is a candidate for enrollment. If the administrator does not provide a value, then the value of the User ID Attribute property is used

User Enrollment Search Filter

identityguard.ldap.enroll.filter

This setting is optional.

If user enrollment is enabled when Entrust IdentityGuard users are stored in the LDAP directory defined by this instance, this filter defines which LDAP users are potential Entrust IdentityGuard users.

The default is to not use this search filter, in which case all objects in the searchbase defined by the instance's LDAP URL are eligible for Entrust IdentityGuard enrollment.

If the Add User Object Class property is True, the base filter used by Entrust IdentityGuard is:

(&(<useridattribute>=*) (!(objectclass=entrustIG*)))

If the Add User Object Class property is False, the base filter used by Entrust IdentityGuard is:

(&(<useridattribute>=*) (!(entrustIGUserInfoMac=*))(!(entrustIGGlobalPolicy=*))(!(objectclass=group)))

Your filter, which is combined with the base Entrust IdentityGuard filter, could be something like:

objectclass=inetOrgPerson

For details about creating filters, see Create a user synchronization custom static filter .

Note: This property is not used for the LDAP synchronization feature.

Default: no value

LDAP Sync User Enrollment Search Filter

identityguard.ldap.sync.filter

When user enrollment is used in conjunction with synchronizing users in an Entrust IdentityGuard database, this property is used to locate potential user entries in the LDAP directory.

The default is to not use a search filter, in which case all objects in the searchbase defined by this instance's LDAP URL are eligible for enrollment.

To make sure that the set of LDAP users eligible for enrollment matches the set of users for which background synchronization notifications are received (assuming that the background synchronization feature is enabled by setting the LDAP Sync Background Thread Enabled to True), it is recommended that this setting reference the same set of LDAP containers as the LDAP Sync Apply Container Mappings property. Failure to do this can result in the enrollment of users who will not receive background synchronization notifications, or background notifications for users who can never be enrolled.

This setting is optional.

Your filter, which is combined with the base Entrust IdentityGuard filter, could be something like the following:

objectclass=inetOrgPerson

This filter would allow enrollment of LDAP objects that are of the type InetOrgPerson (people) only.

For details about creating filters, see Create a user synchronization custom static filter.

Note: If there is a syntax error in this filter, it cannot be used for user enrollment (user enrollment becomes disabled). However, if users were enrolled before use of this filter, their synchronization continues. The filter is not used for synchronization.

Default: filter not used

LDAP Sync Unique User ID

identityguard.ldap.sync.uuid

Specifies the LDAP user attribute used to uniquely identify the user being synchronized from this LDAP directory. Active Directory uses the default setting. Red Hat directory server uses nsUniqueId;string.

The value of this attribute stays the same regardless of changes to the user's common name (cn) or user ID (uid)..

Other values can be used, but they are not officially supported. To specify another value, enter the value followed by an optional semi-colon type (binary or string), for example: sAMAccountName;string or someBinaryAttr;binary.

Note: This property is used only with the LDAP directory synchronization feature.

Default: objectGUID

LDAP Sync Audit Successful Notifications

identityguard.ldap.sync.audit.success

Sets whether Entrust IdentityGuard generates audit messages when a successful LDAP sync notification with a user occurs. Set to True (recommended) to have the system generate these audit messages.

Note: This property is used only with the LDAP synchronization feature.

Default: False

LDAP Sync Background Thread Enabled

identityguard.ldap.sync.notifications.enabled

Specifies whether to propagate updates automatically from this LDAP directory to the associated Entrust IdentityGuard users using a background thread. This feature requires that the LDAP server support persistent search or the Microsoft variation that is implemented by Microsoft Active Directory (AD Notify).

For more information about persistent search, see https://tools.ietf.org/html/draft-ietf-ldapext-psearch-03.

Note: Enable this property on the primary Entrust IdentityGuard server to allow background synchronization. Do not enable it on replica servers or duplicate notifications will be generated.

Note: If this property is not enabled, user synchronization occurs only when users are created and on-demand by an administrator.

Default: False

LDAP Sync Apply Container Mappings

identityguard.ldap.sync.applyContainerMappings

Specifies a comma-separated list of property group instance names that reference the LDAP container mappings that should be applied to this directory server. The instance names for the mappings are case-sensitive. They reference the LDAP containers that will receive background notification updates for this LDAP directory instance if the LDAP Sync Background Thread Enabled property is set to True.

The LDAP sync container mappings referenced by the provided instance names are defined in LDAP Sync Container Mapping Settings property group. Notification updates from the LDAP directory are sent only for entries within the specified containers, not for all entries in this LDAP directory.

An Entrust IdentityGuard background thread is used to process the notification updates for each container.

The default is an empty setting, which means that a container mapping is not specified and therefore the root container of this LDAP directory configuration is used. If the root container of this LDAP directory configuration requires notification updates (in addition to other containers within root), the built-in container mapping name ROOT should be included as an entry in the comma-separated list.

Note: This property is used only with the LDAP directory synchronization feature.

Default: no value

LDAP Sync Number of Worker Threads

identityguard.ldap.sync.numthreads

Specifies the number of worker threads that handle LDAP sync updates during background synchronization from this LDAP directory.

Note: This property is used only with the LDAP synchronization feature.

Default: 5

LDAP Sync Maximum Updates Queue Size

identityguard.ldap.sync.maxupdatesqueuesize

Specifies the maximum number of LDAP sync updates that can be queued during background synchronization from this LDAP directory. When the queue is full, the oldest updates are deleted.

Note: This property is used only with the LDAP synchronization feature.

Default: 10000
