Secure the LDAP connection with SSL

During installation, if you chose not to use an SSL connection to the LDAP repository, you can reconfigure the connection to use SSL later. First, you update the Entrust IdentityGuard key store, and then use the Properties Editor to change applicable properties.

Before you begin, ensure that you have:

●       an LDAP repository that supports SSL

●       an SSL certificate for your LDAP server

This certificate must include a host name (not IP address) in the subject or subjectAltName fields. If you try to use an IP address, host name validation of the LDAP server is not performed properly.

●       permissions to update Entrust IdentityGuard properties

There are two ways to reconfigure the connection to use SSL: Choose one.

Method 1: Import the LDAP server's SSL certificate into the Entrust IdentityGuard key store.

Do this so that Entrust IdentityGuard can communicate with the LDAP server. Entrust IdentityGuard uses this certificate when establishing a connection to verify the identity of the LDAP server. Use one of the following procedures:

If your installation uses the embedded Tomcat Java application server, see Import a trusted certificate.

OR

Method 2: Import the certificate of the CA that issued your LDAP server's SSL certificate.

Complete the following steps:

1.      Use the Key Store Management interface to import the CA certificate that issued the directory server’s certificate.. See Import a trusted certificate.

2.      Edit the properties so that Entrust IdentityGuard connects to the LDAP server using SSL. See "To update the Entrust IdentityGuard properties file for LDAP SSL" below.

 

To import the LDAP SSL certificate (or the CA certificate that signed the LDAP SSL certificate) using the keytool utility

1.      Copy the LDAP server certificate (or the CA certificate) to the server hosting Entrust IdentityGuard.

3.      From a command line on the server, change to the directory that contains the keytool utility. The keytool utility is located in <$IG_HOME>\jdk<version>\bin (Windows) and $IG_HOME/jdk<version>/bin (Linux).

4.      Enter the following command:

keytool -importcert -alias ldapssl -keystore <path_to_keystore> -file <path_to_ldap_ssl_cert_file> -storepass entrust

Where:

●       <path_to_keystore> is:

–  for Linux, $IG_HOME/etc/keystore

–  for Microsoft Windows, <$IG_HOME>\etc\keystore

Note: For versions of Entrust IdentityGuard installed using an existing application server, this is the path to the trust store you entered during installation.

●       <path_to_ldap_ssl_cert_file> is the file in which you stored the directory server’s certificate.

This variable could also be used as <path_to_cert_file> for importing the CA certificate.

The certificate file must be in a format supported by the keytool you are using. The keytool shipped with Entrust IdentityGuard supports binary and base-64 PEM encoded certificates.

5.      When prompted to answer whether or not you trust the certificate, review the displayed details, and if they are correct, answer yes.

To update the Entrust IdentityGuard properties file for LDAP SSL

1.      Start the Entrust IdentityGuard Properties Editor. (See Log in or out of the Properties Editor.)

2.      On the Table of Contents, click LDAP Directory Server Settings.

3.      In the LDAP directory pane, modify the URL in the LDAP URL field to add an SSL port, for example 636 below:

identityguard.ldap.url=ldap://myldapserver:636/ou=users,dc=myserver,dc=com

4.      Under SSL LDAP Connection, select True.

5.      Click Validate & Save.

6.      Restart the Entrust IdentityGuard server service.

You now have a secure SSL connection between Entrust IdentityGuard and your LDAP repository.

For information about SSL certificates, see Managing certificates in the key store.
