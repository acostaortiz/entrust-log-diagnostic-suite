IdentityGuard Server 13.0 Administration Guide

Repository configuration

To avoid problems, imagine that an Entrust IdentityGuard server in Toronto and another Entrust IdentityGuard in Dallas have the same repository naming conventions. That is, the default database configuration that is named “database” internally point to the same replicated data set in both Toronto and Dallas.

Problems could arise if, for example, the Entrust IdentityGuard Toronto has the following configuration:

# URL to connect to the Primary DB server for Toronto user data.

identityguard.jdbc.url=jdbc:db2://torontouser.toronto.com:50000/IG

# URL to connect to the replicas of the dallas information

identityguard.jdbc.url.Dallas=jdbc:db2://dallasdata.toronto.com:50000/IG

 

While Entrust IdentityGuard Dallas has this configuration:

# URL to connect to the Dallas DB server for Dallas user data.

identityguard.jdbc.url=jdbc:db2://dallasusers.dallas.com:50000/IG

# URL to connect to the replicas of the Toronto information

identityguard.jdbc.url.toronto=jdbc:db2://torontodata.losangeles.com:50000/IG

 

In this scenario, group XYZ could be defined to point to user repository “database”. In Toronto, a user created in group A would be placed in the Toronto database. In Dallas, a user created in group XYZ would be placed in the Dallas database. A search for users in group XYZ performed in Toronto would not find the user created in Dallas, and a search for users in group XYZ performed in Dallas would not find the user created in Toronto.
