IdentityGuard Server 13.0 Administration Guide

Add a new LDAP repository

You can add a new LDAP repository at any time, even if you already have database repositories configured.

The first LDAP repository added, whether during Entrust IdentityGuard installation or using this procedure, becomes the Default instance. The properties you set for the Default instance become the defaults for any subsequent LDAP repository you add.

To add a new LDAP repository

1.      If your LDAP directory is not already set up for Entrust IdentityGuard, load the Entrust IdentityGuard directory LDIF files and configure the directory accordingly. For instructions, see the Entrust IdentityGuard Directory Configuration Guide.

Attention: Choose the name for the repository carefully; you cannot change the name after you have assigned it to a group. If you do, the user data in that repository cannot be found. The first directory you define is always called Default.

2.      Start the Entrust IdentityGuard Properties Editor. (See Log in or out of the Properties Editor)

3.      On the Table of Contents, click LDAP Directory Server Settings.

4.      From the Configuration Instances drop-down list, do one of the following:

●       Select Default to configure LDAP repository settings that will apply to all repositories in your implementation (if you have multiple repositories) or your only LDAP repository.

●       Enter a configuration name in the empty field and select Add to configure an LDAP repository that will have settings that are different from the default.

5.      Configure the following properties for the LDAP directory server:

LDAP URL

identityguard.ldap.url

Provides the URL used to connect to the LDAP directory server. This can include a port number and initial context prefix to bind to. Encode spaces in the URL as %20. All lookups are relative to the given context prefix.

Syntax:

<ldap_server_URL>:<port>/<search_base>

Where:

<ldap_server_URL> is the URL to your LDAP directory, including the ldap:// or ldaps:// prefix

<port> is the LDAP port. The port is optional if you are using the default port (389 for LDAP; 636 for LDAPS)

<search_base> is the searchbase to connect to. For more information, see Using a searchbase.

For example

ldap://myldaphost.com:389/ou=People, dc=AnyCorp,dc=com

binds to port 389 on the computer myldaphost, with ou=People,dc=AnyCorp,dc=com as the context prefix.

You can enter multiple URLs separated by spaces as part of a high-availability setup. For the default instance, the initial value is set during configuration.

Guidelines for specifying the LDAP URL:

●       Replace spaces in the URL with %20.

●       To specify more than one searchbase for failover purposes, use the full URL and separate each URL with a space. For example:

ldap://ldap.svr.com:389/ou=users,c=ca ldap://ldap.svr.com:389/ou=admins,c=ca

Note: To specify multiple searchbases so you can store users in multiple search bases, create and configure a separate LDAP Configuration Instance for each searchbase.

●       If you are specifying a searchbase in Active Directory, it is highly recommended that you do not use a top-level container such as dc=mycompany,dc=com. Instead, use one or several lower-level containers such as cn=users,dc=mycompany,dc=com and cn=admins,dc=mycompany,dc=com. If you must use a top-level container, ensure that referrals are disabled in Entrust IdentityGuard or else errors may occur. For more information about referrals, see the property Follow Referrals Returned by the Repository.

Directory Server Description

identityguard.ldap.description

Provides a description of the repository. The text is used by the Administration interface. The description must be unique for all repositories, both LDAP and database.

Default: the instance name

LDAP Vendor

identityguard.ldap.vendor

Sets the type of LDAP repository being used to store users. This setting is required if users that are disabled in the LDAP repository are to be automatically suspended in Entrust IdentityGuard. The LDAP directory vendor is also required if you want to be able to automatically extract user contact information directly from the repository.

Note: When you select an LDAP vendor, you enable features that let you manage disabled and expired user accounts (if supported by the selected vendor). To explicitly disable the these features, you must set the Repository Data policies to False. For more information, see Repository Data policies.

Note: If you are using LDAP synchronization with an Entrust database (which means that the LDAP Directory Specific Usage property is set to SYNC), Active Directory and Red Hat are the officially supported vendors.

The choices are:

•  Not specified

•  Active Directory

•  AD LDS

•  CA Directory

•  eDirectory

•  OpenLDAP

•  Oracle

•  Red Hat

•  Oracle Unified Directory

•  Sun ONE

•  Tivoli

•  UnboundID

•  Custom

Default: Not specified

●       Primary Directory Server Maximum Reconnect Interval — In a high-availability environment, the property specifies the maximum time, in hours, between attempts to connect to the primary directory. The default is 24 hours.

●       Directory Server Connection Test Interval — In a high-availability environment with pooled connections, this property specifies the time, in seconds, between tests to check if the connections are still valid.

If this property is set to 0 (zero), the connection is tested only when Entrust IdentityGuard attempts to connect to the directory. The default value is 0.

●       SSL LDAP Connection — Set to True if you are using an SSL connection to the directory. The default value is False.

Before setting this property to True, ensure that the URL in the LDAP URL property refers to a secure port (636, for example) and that the directory has a trusted certificate.

Attention: If you do not specify a secure port when this property is set to True, the server could hang indefinitely when it attempts to connect to the directory.

●       Disable SSL Host Name Verification — Set to True only for testing or debugging your Entrust IdentityGuard system. The default value is False.

●        Directory Administrator — Ensure that the administrator specified in this property has permission to add and remove object classes and attributes from all entries in the new repository, for example:

cn=administrator,cn=users,dc=myldapserver,dc=entrust,dc=com

Note: If you are configuring an Active Directory repository, the add/remove permissions are not necessary.

●        Directory Administrator Password — Enter a valid password for the administrator.

Depending on your directory password policies, this password may expire from time to time and must be updated. See Updating the directory password.

●       User ID Attribute — Specify the user ID. Typically this is sAMAccountName for Active Directory, and usually uid or cn for other LDAP repositories. (See the Entrust IdentityGuard Directory Configuration Guide for details about supported directories.)

●       User ID Case-Sensitivity — Set to True to make the user ID in the directory case sensitive. The default value is False.

●       Policy Directory Entry — Specify the DN of the special user created in the directory to hold Entrust IdentityGuard policy. This DN must be specified relative to the base DN entered in the LDAP URL. For example, if the LDAP URL is

ldap://ldap.host.com/dc=users,dc=mycompany,dc=com

In this example, the full DN of the policy entry is:

uid=IGPolicy,dc=users,dc=mycompany,dc=com

Then set Policy Directory Entry to:

uid=IGPolicy

●       User Object Class — Specify the directory object class that allows the addition of the Entrust IdentityGuard attributes. If you do not set it, it defaults to entrustIGUser.

●       Add User Object Class — To configure an Active Directory repository, set the property to False. For any other LDAP directory, set this property to True.

●       Policy Object Class — Specify the directory object class to be used to allow policy attributes to be added to an entry. If you do not set it, it defaults to entrustIGPolicy.

●       Add Policy Object Class  — For an Active Directory repository, set to False. For any other LDAP directory, set this property to True.

●       Entrust IdentityGuard User Entry Object Class — To restrict your Entrust IdentityGuard users to directory entries that already have a particular object class, enter the appropriate object class. If you choose to add this property, all Entrust IdentityGuard users must have this object class. If you do not set this property, this search filter is not set.

●       Use Optimized Filter — The LDAP optimization filter is set to True by default to optimize LDAP search performance.

The next group of LDAP properties is used when configuring failover. If you are not enabling failover, you can leave all of these properties at their defaults. To enable failover and set these properties appropriately, see Configuring failover and high availability.

●       LDAP Connection Timeout

●       LDAP Search Timeout

●       LDAP Maximum Search Limit

●       Connection Pool Maximum Size

●       Connection Pool Maximum Wait Time

●       Idle Connection Minimum Close Time

●       Idle Connections Check TIme

●       Include Subseconds with Generalized Time — Set this property to True (default) if your directory requires generalized time attributes that contain subseconds. Set this property to False for Novell eDirectory.

●       Follow Referrals Returned by the Repository — Set to True, to have Entrust IdentityGuard follows referrals. This may result in connection timeouts if your directory returns referrals that cannot be followed.

●       Skip Repository During Search if not Available

●       User Enrollment — Set to True if you plan to create Entrust IdentityGuard users by enrolling them from this repository.

●       User Enrollment Search Filter — (Optional) If you set User Enrollment to True, you can add a filter expression. See Create a user synchronization custom static filter.

●       If you are configuring an Active Directory repository and you are enabling User Enrollment, set Paging Supported to True.

●       Disabled Account Attribute — If you are using the user account disabled indicator in the LDAP directory to determine the user account status in Entrust IdentityGuard, use this property to set which directory attribute should be interpreted as meaning the user account is disabled. For more detailed information, see also Suspend disabled and expired LDAP users.

–  Vendor Default (default) — When this option is used, Entrust IdentityGuard uses the value that applies to the specific directory being used, as defined in the LDAP Vendor property. In each case, this is the most commonly used attribute to indicate a disabled user in the named directory

–  ibm-pwdAccountLocked (Tivoli)

–  loginDisabled (eDirectory)

–  msDS-UserAcountDisabled  (ADLDS)

–  nsAccountLock (Sun ONE/Red Hat)

–  orcllsEnabled (Oracle)

–  userAccountControl (Active Directory)

–  Custom

If you are using one of the directories listed, but you are not using the default attribute, select Custom. Selecting Custom reveals another field. Use this field to enter the disabled account attribute for your directory.

Enter the attribute and the value that indicates the user is disabled in the following form:

<attribute_name>;<value_meaning_disabled>

Where:

<attribute_name> is the name of the LDAP directory attribute to check to find out if the user is disabled. The attribute name is not case sensitive.

<value_meaning_disabled> is optional. When used, it contains the value of the attribute that means the user is disabled. When it is not used, the presence of the attribute means that the user is treated as being disabled.

(If you do not include this value, leave off the semi-colon (;), too.)

Some examples:

userIsDisabled

The user is treated as being disabled if they have the attribute userIsDisabled.

userIsDisabled;true

The user is treated as being disabled if they have the attribute userIsDisabled and it is set to the value true.

Note: Only one attribute/value pair is allowed in this field.

Note: To explicitly disable the LDAP disabled user features, you must set the Repository data policies to False. See Repository Data policies.

●       Expired Account Attribute — If you are using the user expired indicator in the LDAP directory to determine the user status in Entrust IdentityGuard, use this property to set which directory attribute should be interpreted as meaning the user is expired. For more information about setting this attribute, see Suspend disabled and expired LDAP users.

The following choices are available:

–  Vendor Default (default) — When this option is specified, Entrust IdentityGuard uses the value that applies to the specific directory being used, as defined in the LDAP Vendor property. In each case, this is the most commonly used attribute to indicate a expired user in the named directory.

–  accountExpires (AD/AD LDS)

–  loginExpirationTime (eDirectory)

–  orclActiveEndDate (Oracle)

–  Custom — If you are using one of the directories listed, but you are not using the default attribute, select Custom. Selecting Custom reveals another field. Use this field to enter the disabled account attribute for your directory.

Enter this property in the form <attribute_name> where <attribute_name> is the name of the LDAP directory attribute to check to find out if the user is expired. The attribute name is not case sensitive.

If <attribute_name> is not recognized as one of the predefined values set for the supported LDAP directories, it is assumed to be an ASN.1 time type.

Note: To explicitly disable the LDAP expired user features, you must set the Repository data policies to False. See Repository Data policies.

6.      To map the user’s full name from the directory into Entrust IdentityGuard, enter the attribute your directory uses for the full name in Full Name Attribute. If you leave it blank, no mapping is performed.

7.      To map the user’s contact info from the directory into Entrust IdentityGuard, enter the contact information mappings in Apply Contact Info Mappings.

These mappings are case-sensitive and applied in the order listed. If multiple contact information mappings map to the same contact information label, only the first mapping is applied. To define the contact information mappings, see Map contact info from an LDAP directory.

8.      Change other settings as required. If left blank, they use implied defaults. For an explanation of each property and its default, see LDAP Directory Server Settings.

9.      Click Validate & Save.

Attention: If you have only database repositories configured, and you are adding the first LDAP repository, you must set the Card/User Repository Implementation Classes to Database (Default) and Directory Server

10.  If you already have JDBC repositories configured, and this is your first LDAP reposit ory:

a.      Set the Use Optimized Filter property to True.

b.      Click Table of Contents.

c.      From the Table of Contents, click Repository Settings.

d.      Set Card/User Repository Implementation Classes to Database (Default) and Directory Server.

11.  Click Validate & Save.
