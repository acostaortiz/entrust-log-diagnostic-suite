How license counting works in partitions

In normal operation with multiple partitions, general users and other items that consume licenses (for example, soft tokens and smart credentials [one license per user] are created by each location throughout the day, for example. Periodically, as defined in the License Audit Interval property, users and other items from all of the partitions are counted and added together, and the total is compared to the purchased license counts in the global policy.

If the counts do not match:

●       If a count mismatch is found when the count is run on the global policy, (comparing existing users or items against users or items created), the global policy is updated and an audit is written.

●       If a count mismatch is found when the count is run on a partition, (comparing existing users or items against users or items created), a warning audit is written, but the partition is not updated.

If the sum of all users or items in the system is equal to, or exceeds, the number of licenses, you cannot create any more users or other items. This error generates an audit.

Attention: If your replication fails, or is prevented by a loss of network connectivity, it is possible to exceed your license count, because each site continues to create users, grids and licensed items independent of the other, and the totals are not checked until replication resumes.
When replication is restored, if updated counts show that the license count has been exceeded, Entrust IdentityGuard does not allow creation of any more users, grids or licensed items until you purchase more licenses.

Attention: If there are multiple Entrust IdentityGuard servers running, user counting should be enabled on only one of them.
Enable user counting on the Entrust IdentityGuard server that can see all of the data in the system.
