IdentityGuard Server 13.0 Administration Guide

Generate a SAML certificate to be used by Entrust IdentityGuard Server

To generate a SAML certificate to be used by Entrust IdentityGuard Server

1.      Decide on the type of SAML certificate you want. You have these options:

●       You can generate new self-signed certificate (and a corresponding key pair) dedicated to encrypt and sign SAML messages. This option should only be used in test environments. If you choose this option, go to Step 2.

●       You can generate new Certification Authority (CA)-signed certificate (and a corresponding key pair) to encrypt and sign SAML messages. This option can be used in live environments. If you choose this option, go to Step 3.

2.      If, in Step 1, you decided to use a new, self-signed SAML certificate and keys, complete the following steps:

a.      On the Entrust IdentityGuard Server, open the keytool utility in

$IG_HOME/jdk<version>/bin (Linux),

<$IG_HOME>\jdk<version>\bin (Windows).

b.      Generate the key pairs using this command:

keytool -genkeypair -alias <alias> -dname "<required DN>" -keyalg RSA -keysize <keysize> -keystore <path_to_keystore> -keypass entrust -storepass entrust

where:

●       <alias> is a short name you want to associate with your Entrust IdentityGuard Server’s SAML certificate. This guide assumes igsaml.

●       <required_DN> is "cn=<FQDN>" where <FQDN> is the fully-qualified domain name of the Entrust IdentityGuard Server.

●       <keysize> is 1024 or 2048.

●       <path_to_keystore> is the name and path of the Entrust IdentityGuard Server’s keystore, which is <$IG_HOME>\etc\keystore, by default. If you specify a different keystore from the default, supported file extensions are: JKS, JCK (for a JCEKS type of store), and P12 (for a PKCS#12 type of store). If no file extension is provided, JKS is used.

●       -keypass sets the password for the certificate and keys. This guide assumes entrust.

●       -storepass is the password for the keystore specified by -keystore. If you are using the existing <$IG_HOME>\etc\keystore, the password is entrust.

Example:

keytool -genkeypair -alias igsaml -dname "cn=igserver.yourorg.com" -keyalg RSA -keysize 2048 -keystore "C:\Program Files\Entrust\IdentityGuard\
identityguard130\etc\keystore" -keypass entrust -storepass entrust

c.      Export the certificate to a CER file, for later use.

Example:

keytool -exportcert -v -keystore "C:\Program Files\Entrust\IdentityGuard\identityguard102\etc\keystore" -alias igsaml -file "c:\igsaml.cer"

3.      If, in step 1, you decided to use a new, CA-signed SAML certificate and keys, complete the following steps:

a.      On the Entrust IdentityGuard Server, open the keytool utility. It is available in $IG_HOME/jdk<version>/bin (Linux),

<$IG_HOME>\jdk<version>\bin (Windows).

b.      Generate a key pair using the keytool.

Example:

keytool -genkeypair -alias igsaml -dname "cn=igserver.example.com" -keyalg RSA -keysize 2048 -keystore "c:\Program Files\Entrust\IdentityGuard\
identityguard130\etc\keystore" -keypass entrust -storepass entrust

where:

●       <alias> is a short name you want to associate with your Entrust IdentityGuard Server’s SAML certificate. This guide assumes igsaml.

●       <required_DN> is "cn=<FQDN>" where <FQDN> is the fully-qualified domain name of the Entrust IdentityGuard Server.

●       <keysize> is 1024 or 2048.

●       <path_to_keystore> is the name and path of the Entrust IdentityGuard Server’s keystore, which is <$IG_HOME>\etc\keystore, by default. If you specify a different keystore from the default, supported file extensions are: JKS, JCK (for a JCEKS type of store), and P12 (for a PKCS#12 type of store). If no file extension is provided, JKS is used.

●       -keypass sets the password for the certificate and keys. This guide assumes entrust.

●       -storepass is the password for the keystore specified by -keystore. If you are using the existing <$IG_HOME>\etc\keystore, the password is entrust.

Example:

keytool -genkeypair -alias igsaml -dname "cn=igserver.yourorg.com" -keyalg RSA -keysize 2048 -keystore "C:\Program Files\Entrust\IdentityGuard\
identityguard130\etc\keystore" -keypass entrust -storepass entrust

c.      Create a Certificate Signing Request (CSR).

Example:

keytool -certreq -alias igsaml -file "c:\igsamlCSR.txt" -keystore "c:\Program Files\Entrust\
IdentityGuard\identityguard130\etc\keystore" -storepass entrust

d.      Go to http://www.entrust.net. On this website, you can submit your CSR, and Entrust will give you back a certificate that is signed by its CA. Copy the certificate displayed on-screen to a file. For example:

c:\igsaml.cer

e.       Import igsaml.cer to the Entrust IdentityGuard Server’s keystore.

Example:

keytool -importcert -alias igsaml -file "c:\igsaml.cer" -keystore "c:\Program Files\Entrust\IdentityGuard\
identityguard130\etc\keystore" -storepass entrust

f.        Export all the CA certificates in the certificate chain to file. To do this: double-click the igsaml.cer on a Windows computer. Click Certification Path. Click the top-most certificate in the chain. That is the root CA. Any others are intermediate CAs. The certificate at the bottom is igsaml.cer. With the root CA selected, click View Certificate. Click Details. Click Copy to File. Click Next through the wizard, selecting DER encoded binary X.509 (.CER) and selecting a name and location for the file, for example: c:\igsamlRootCA.cer. Repeat for each intermediate CA, giving them distinct file names such as

c:\igsamlIntermediateCA1.cer, and

c:\igsamlIntermediateCA2.cer.

g.      Import each CA CER file to the Entrust IdentityGuard Server’s keystore, using different aliases for each.

Example:

keytool -importcert -alias igsamlRootCA -trustcacerts -file "c:\igsamlRootCA.cer" -keystore "c:Program Files\Entrust\IdentityGuard\identityguard130\etc\keystore" -storepass entrust

After completing step 2 or step 3, you have a SAML certificate and keys that will be used by Entrust IdentityGuard Server (the SP) to secure SAML messages for the Federation Module (the IDP).
