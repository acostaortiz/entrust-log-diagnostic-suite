IdentityGuard Server 13.0 Administration Guide

Password policies

The following table lists the password policies that control user and administrator passwords.

Password name

When you add a user password policy, other than the default, enter its name in the blank field at the top of the definition settings. (Administrators can have named passwords but the Administration interface accepts only the default password.)

The maximum name length is 255 characters. The name is not case-sensitive. It cannot be changed once created.

CHAP/MS-CHAP Compatibility

Sets the method of password storage. You can select or deselect the Compatible with CHAP/MS-CHAP check box. Setting the storage to Compatible with CHAP/MS-CHAP means the password is encrypted (that is, it can also be unencrypted).

Deselecting the check box results in the password being hashed, in addition to being encrypted. This means that the password cannot be read, even with the encryption key.

You must have this option selected if you are using the Entrust IdentityGuard password with MSCHAP-V2 for first-factor authentication

Default: No

Minimum Length

Sets the minimum number of characters that can make up a password. The maximum password length is 255.

Note: Some VPN clients have buffer size restrictions that affect the number of characters you can use in a password. You probably would not notice this until a user tries to change the password while using a VPN client that restricts the input to 20 characters, for example. Entrust IdentityGuard sends password changes as a string—NewPasswordNewPassword—so the maximum password length in this example is 10 characters.

Default: 8

Lifetime

Sets the number of days a password is valid. After the password has expired, the user must first change the password before completing authentication. The maximum is 36,500 days. The value cannot be less than the setting for Minimum Lifetime. Unlimited or 0 means the password never expires.

Note: This policy is ignored when a user changes their LDAP password through Entrust IdentityGuard external authentication.

Default: 56 days (8 weeks)

Minimum Lifetime

Specifies the number of days after a password is created during which a user cannot change it. The value cannot be greater than the setting for Lifetime.

Setting this policy ensures users cannot circumvent the password history restriction by cycling through a set of passwords to get back to an old one. This policy does not prevent an Administrator from changing a user password at any time.

Note: This policy is ignored when a user changes their LDAP password through Entrust IdentityGuard external authentication.

Default: Not set

Number of Passwords Kept in the History List

Specifies the number of recently used passwords to store for each user. Setting this ensures a list of previously used passwords are not reused the next time the user updates their password. The value must be in the range t to 255.

Note: This policy is ignored when a user changes their LDAP password through Entrust IdentityGuard external authentication.

Default: 8

Include Number

Specifies whether the password:

•  must include a number when it is created (Required)

•  may include a number when it is created (Allowed)

•  must not include a number when it is created (Not Allowed)

Default: Required

To create a password that is all numerals, such as for ATM access, set this to option to Required, and options for letters and special characters to Not Allowed.

Number of Numeric Characters Required

Specifies the minimum number of numerals that must be in the password when Required is set for Include Number.

The required value cannot exceed 255.

Include Uppercase Letter

Specifies whether the password:

•  must include a uppercase character when it is created (Required)

•  may include a uppercase character when it is created (Allowed)

•  must not include a uppercase character when it is created (Not Allowed)

Default: Required

Number of Uppercase Characters Required

Specifies the minimum number of uppercase letters that must be in the password when Required is set for Include Uppercase Letter.

The required value cannot exceed 255.

Include Lowercase Letter

Specifies whether the password:

•  must include a lowercase character when it is created (Required)

•  may include a lowercase character when it is created (Allowed)

•  must not include a lowercase character when it is created (Not Allowed)

Default: Required

Number of Lowercase Characters Required

Specifies the minimum number of lowercase letters that must be in the password when Required is set for Include Lowercase Letter.

The required value cannot exceed 255.

Include Nonalphanumeric Character

Specifies whether the password:

•  must include a special character when it is created (Required)

•  may include a special character when it is created (Allowed)

•  must not include a special character when it is created (Not Allowed)

Permitted special characters are: ! @ # $ % ^ & * + ? / < >

Default: Allowed

Number of Nonalphanumeric Characters Required

Specifies the minimum number of special characters that must be in the password when Required is set for Include Nonalphanumeric Character.

The required value cannot exceed 255.

Maximum Repeated Characters

Specifies the maximum number of times any character can appear in the password. For example, if set to 2, Pa$$-code11 would be allowed but not Pa$$-code111 because the one character appears three times.

Default: Unlimited

Maximum Change Time

When Entrust IdentityGuard flags a password for changing, such as when Change Is Required On Next Usage is set, you can choose a time period in which that change must be made. If the time period expires, an attempt to change the password fails and the administrator must intercede. Enter a positive integer representing the number of second, minutes, hours or days.

Must Be Unique

Set this to Yes to prevent users from using the same passwords for different access portals. When selected, a new password cannot match any of the user’s other current passwords. (The history of those other passwords is not considered.) When not selected, the new password is checked against its own history: other passwords are not considered. If a user attempts to change a non-unique password to a value that matches a unique password, it is rejected.
