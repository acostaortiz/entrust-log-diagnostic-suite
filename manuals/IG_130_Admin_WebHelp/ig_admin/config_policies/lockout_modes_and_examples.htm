IdentityGuard Server 13.0 Administration Guide

Lockout modes and examples

A lockout mode is the logic that Entrust IdentityGuard uses tor calculate whether to lock out the user. There are three lockout modes:

●       Lock Authenticator (Authenticator Counter) 

Choose this option if you want to use individual lockout counters for each authenticator. With each failed authentication attempt with a specific authenticator, the number of remaining attempts that are allowed with it is reduced by one. If the counter reaches zero, the user is locked out and cannot attempt further authentications with that authenticator. If the user supplies correct authentication credentials at any time prior to the counter reaching zero, the counter for the authenticator that was used is reset to its original value.

For example, assume you have set lockout counters for grids and tokens to three and four, respectively. A user (Bob) then attempts to authenticate twice with a grid, and three times with a token, and all of these attempts fail. The lockout counters are consequently decreased to one (for grid) and one (for token). On his next attempt, Bob supplies incorrect grid coordinates. This causes the grid’s lockout count to reach zero and Bob is locked out for grid authentication. He still has one more chance to authenticate using his token. If Bob had supplied correct grid coordinates, then the counter for the grid would be reset to three, but the counter for the token would remain at one.

●       Lock User (Authenticator Counter) 

This is the default policy setting, and it was the only option available prior to Entrust IdentityGuard 10.1.

With this option, as with the previous option, there are individual counters for each authenticator. Unlike the previous option, if any one of the individual counters reaches zero, the user is locked out of all authenticators. If the user supplies correct authentication credentials at any time prior to the counter reaching zero, then the counter for the authenticator that was used is reset to its original value.

For example, assume you have set lockout counters for grids and Q&A to three and three, respectively. A user (Alice) then attempts to authenticate once with a grid, and twice with Q&A, and all of these attempts fail. The allowed remaining attempts have decreased to two (for grid) and one (for Q&A). On her next authentication attempt, Alice supplies another incorrect Q&A answer. This causes the Q&A lockout count to reach zero. With this policy setting, Alice is locked out from using Q&A and her grid. If, however, Alice had supplied a correct Q&A answer, then the counter for Q&A would be reset to three. The counter for grid would remain as-is.

●       Lock User (Global Counter) 

Choose this option to have a single, global, lockout counter for all authenticators. With each failed authentication attempt with any authenticator, the global number of remaining attempts that are allowed is reduced by one. If the global counter reaches zero, the user is locked out and cannot attempt further authentications with any authenticator. If the user supplies correct authentication credentials for any authenticator before the counter reaches zero, then the lockout counter is reset back to its original value.

For example, assume you have set the global lockout counter to allow five consecutive incorrect authentication attempts. A user (Bob) then attempts to authenticate twice with a grid, and twice with a token, and all these attempts fail. The global counter is down to one remaining attempt. On his next login, Bob supplies incorrect grid coordinates. This causes the lockout counter to reach zero. Bob is locked out of his grid and token. If, however, Bob had supplied correct grid coordinates, the global lockout counter would have been reset to five.
