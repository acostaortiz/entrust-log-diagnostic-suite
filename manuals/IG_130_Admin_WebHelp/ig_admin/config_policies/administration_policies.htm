IdentityGuard Server 13.0 Administration Guide

Administration policies

These policies control settings related to an administrator’s use of the Administration interface and the Properties Editor. They also apply to any applications that use the Administration API.

Idle Timeout

Specifies the number of minutes an Administration API session can remain idle before the session is terminated. This affects the Administration interface, and any application that uses the Administration API.

This setting does not include the Properties Editor because the Properties Editor only uses the Administration API for authentication.

Default: 15

Confirmation Interval

Specifies the interval, in seconds, at which IdentityGuard validates that the currently logged in user is authorized to perform administrative functions in IdentityGuard. If this validation finds that a user is deleted, disabled, or no longer has an administrative role, subsequent operations through IdentityGuard Administration will fail.

Set to Never to have the confirmation interval last an unlimited amount of time. With this setting, the administrative user is validated only at login.

Set a number of seconds to specify how frequently the validation should occur.

•  Set to 0 to have the system validate the user for each administrative request. This setting may have an impact on performance.

•  Set to a number of seconds to between validations. A small value means there will be frequent validations, which may have an impact on performance. A large value means that it will take longer for changes in the administrator status to be recognized.

Default: Never

First-Factor Authentication Type

Specifies either password or external login for administrators.

Set this policy to External if you want to use the Active Directory password, for example, instead of the Entrust IdentityGuard password to log in to the Administration interface.

Default: Password

Second-Factor Authentication Type

Determines if an administrator, after logging in with a password, receives a second-factor authentication challenge. You can select one of:

•  GRID: authenticates with a card or temporary PIN.

•  TOKEN (Response-Only): authenticates using a dynamic password generated by a response-only token, or a temporary PIN.

•  TOKEN (Challenge and Response): authenticates using a dynamic password generated by a challenge-and-response token, or a temporary PIN.

•  None: requires no second-factor authentication.

Default: None

Allow SAML Authentication

Select this option to enable single-sign on to the Administration interface from Federation Module or other SAML-enabled applications. For more information, see Configuring SAML authentication to the Administration interface.

Default: No.

Allow Smart Credential Authentication

Select this option to enable single-sign on to the Administration interface or administrative users who have logged in to their computer using smart credentials.

Default: No

Allow External Smart Credential Authentication

Select this option to enable smart credential login to the Administration interface with smart credentials created by a vendor other than Entrust IdentityGuard.

Default: No.

Allow Header-Based Authentication

This feature will be available in a future release.

Default: No
