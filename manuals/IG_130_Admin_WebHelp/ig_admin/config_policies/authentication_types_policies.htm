IdentityGuard Server 13.0 Administration Guide

Authentication Types policies

These policies set the authentication methods available to users in the groups associated with a specific policy. Through the Authentication API, your client application can specify any method for second-factor authentication as long as that method is allowed by the Authentication Types policy.

The actual authentication challenge is handled by getGenericChallenge in the Authentication API. If the policy for normal or enhanced authentication lists just one authentication method, that is the authentication method that is used. If the policy lists multiple authentication methods, Entrust IdentityGuard uses the first method in the list that is valid for the user. For example, if the generic or enhanced authentication policy specifies a grid first and then a token, but the user does not have a grid card assigned, Entrust IdentityGuard issues a token challenge.

Normal Security Authentication Types

Sets the methods your application can use for authentication at the normal security level. The order is important as the first one becomes the default if a method is not explicitly stated in your application.

You can select one or more of the authentication types listed.

•  Grid: authenticates with a card or temporary PIN.

•  Q&A: presents knowledge-based authentication (a list of questions the user must answer).

•  OTP: presents out-of-band authentication (a one-time password provided to the user).

•  Token (Challenge and Response): authenticates using a dynamic password generated by a challenge-and-response token, or a temporary PIN.

•  Token (Response-Only): authenticates using a dynamic password generated by a response-only token, or a temporary PIN.

•  Password: authenticates using a password.

•  External: authenticates users through an external resource such as an LDAP directory or a Windows domain controller.

•  Certificate: authenticates using certificates

•  None: No authentication required. To include this option, the Allow ‘None’ Authentication Type policy must be selected first.

Default: All methods except biometric authentication and None are allowed. Biometric is not present unless the feature is licensed.

Allow 'None' Authentication Type

This option must be selected if you have included None in the list of allowed authentication list for Normal or Enhanced security.

Consider Temp PIN Last

In IdentityGuard 9.1, if an application asked Entrust IdentityGuard to choose the authenticator to use, the server chose the first usable authentication type available, but would not consider a temporary PIN as an authenticator, unless no other authenticator was available.

For example, if a user had a grid card currently on hold, and was issued a temporary PIN, but also had Questions and Answers (Q&A) defined, Entrust IdentityGuard would present a Q&A challenge rather than temporary PIN.

This behavior was changed starting at Entrust IdentityGuard 9.2. The new behavior is to allow the user to authenticate with the temporary PIN if their primary authentication method is unavailable.

Set this policy to True to use the Entrust IdentityGuard 9.1 behavior.

Default: False

Store Type and Date of Last Authentication

Disable this policy if you do not want to store the authentication type and date of each user’s last authentication. When this policy is enabled, both user and administrator authentication information is stored.

Default: Yes
