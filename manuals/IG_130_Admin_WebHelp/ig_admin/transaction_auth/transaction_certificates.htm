IdentityGuard Server 13.0 Administration Guide

Transaction certificates

If set by Entrust IdentityGuard policy, each transaction receipt is signed using a transaction certificate.

Entrust IdentityGuard maintains a list of transaction certificates. The list consists of private/public key pairs and a certificate for the public key. The certificate can be self-signed or generated by an external certificate authority. The transaction receipt signature includes the certificate of the private key used to sign the receipt.

Each certificate has one of the following states:

●       pending (has not yet been certified)

●       active (in use for signing)

●       inactive (no longer used for signing)

A maximum of 1 pending and 1 active certificates are allowed at any given time. Multiple inactive certificates are allowed.

When Entrust IdentityGuard creates a self-signed certificate, it does not include any extensions. Only the digitalSignature key usage bit is set.

Entrust IdentityGuard needs an active certificate to sign the transaction receipt, and checks that the certificate has not expired. Entrust IdentityGuard does not check to find out if the certificate has been revoked by the CA. If signed transaction receipts are specified by policy (Transaction Signature Type), and there is no valid certificate, the transaction receipt is returned unsigned, and an audit is written to the audit log.

You can manage your transaction certificates using the transaction certificate commands. See the Entrust IdentityGuard Master User Shell Reference for details of the commands and their syntax. Audits are generated for all operations that create or modify transaction certificates.
