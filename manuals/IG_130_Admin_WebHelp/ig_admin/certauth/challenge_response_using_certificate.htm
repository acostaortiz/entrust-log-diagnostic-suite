IdentityGuard Server 13.0 Administration Guide

Challenge response using certificate

Your application requests a challenge by specifying an authentication mechanism of type CERTIFICATE. Entrust IdentityGuard returns random data to be signed by the application. Upon receipt of the encoded signature, Entrust IdentityGuard checks it to ensure that the signature is valid and that the certificate used for the signature is valid. Certificate validation conforms to RFC 2459, the X.509 standard.

To configure certificate authentication in which the user is authenticated through a challenge that is answered by their certificate, do the following:

●       Ensure that administrators have the required permissions to set policy (see User permissions).

●       Using the Policies pages of the Administration interface, set the certificate authentication policies (see Certificate Authentication policies).

●       Create an application that takes the Entrust IdentityGuard challenge, hashes and signs it, and then returns the base-64 encoded signature to Entrust IdentityGuard as a response to the challenge. Some additional requirements to consider:

–  The application must register a new end user certificate only after the user successfully authenticates with another method.

–  The application must provide a label for each certificate, since users can have more than one.

–  If the user has more than one valid certificate, prompt the user to choose which to use.

For detailed information about configuring your client application, see the Entrust IdentityGuard Programming Guide. A certificate authentication sample is provided with Entrust IdentityGuard.

●       Register one or more CA certificates into Entrust IdentityGuard. See Administering CA certificates for details.

●       Load the certificates into Entrust IdentityGuard and associate them with users. See Importing and assigning user certificates. Certificates must be globally unique.
