IdentityGuard Server 13.0 Administration Guide

Administering assigned grid cards

After you create the grids, you need to reproduce the grids on physical cards, distribute the grid cards to your users, and assign the preproduced grid cards to your users.

Each user can use one grid card at a time, and therefore usually has one grid card associated with the user entry. However, a user entry can have a current grid card and a grid card in pending or hold_pending state. For example, if the current grid card is nearing expiry, you can associate a pending grid card with the user entry that replaces the existing grid card. After the new grid card’s state changes from pending to current (which occurs when the user uses it for authentication), the old grid card is canceled by Entrust IdentityGuard. (See Grid card state overview for more information about grid card states.)

While users are waiting for their grid cards, you can issue them a temporary PIN. The user can then identify themselves using the temporary PIN for a specific number of uses or a limited time. For more information, see Configuring and using temporary PIN authentication.

After you assign grid cards to users, Entrust IdentityGuard allows you to search for grid cards in a variety of ways, for example:

●       grid cards in a certain state (for example, all pending grid cards)

●       grid cards created within a certain date range

●       grid cards belonging to a user

You can change the attributes that describe a grid card for a given user. For example, you can change:

●       the grid card state

●       the grid card lifetime

●       the grid card superseded date

The default grid card lifetime and supersede period are set by policy. Administrators cannot change these defaults unless they have the userCardOverridePolicy permission.

You can move an assigned grid card back to the preproduced list (see Move an assigned grid card back to the preproduced list). For example, you can use this option if you mistakenly assign the wrong grid card to a user, or if the user does not require the grid card for second-factor authentication.

Note: You can only unassign grid cards that were originally preproduced grid cards, and that are in the pending or hold-pending state.

You can delete a user’s grid card if it is lost, canceled, or expired. When you delete a grid card, Entrust IdentityGuard removes it from the repository. You can only retrieve deleted grid cards by restoring your data repository from backup. For details on deleting grid cards, see Delete a grid card.

After you assign a grid card to a user, use the Account Information pane for that user to display the user’s grid cards and to administer them.

Any changes made to the grid card take effect the next time it is used for authentication.

In order to complete these procedures, administrators must have the correct role permissions. See Configuring grid card policies for a list of all role permissions relating to grids.
