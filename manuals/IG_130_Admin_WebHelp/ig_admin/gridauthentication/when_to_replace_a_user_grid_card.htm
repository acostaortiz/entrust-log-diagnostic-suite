IdentityGuard Server 13.0 Administration Guide

When to replace a user grid card

In the course of normal organizational operations, changes can take place that necessitate changing user grid cards.

One reason for changing user grid cards is a suspected security breach, that is, grid cards have been lost or stolen, or you suspect that the database has been compromised.

You may also have to change grid cards when you change the user’s group, or the grid card policies change. The following situations require you to issue new grid cards for your users:

●       an increase in the number of rows or columns in the grids. This could happen if you move a user to a different group, and the new group uses grids with a larger Number of Rows or Number of Columns.

When you issue a new card with new grid dimensions, the user is not able to answer challenges with the new pending grid card. To work around this, delete or cancel the user’s current grid card. Entrust IdentityGuard begins generating the challenges according to the grid size of the pending grid card. A user can then authenticate with the new grid card.

●       a change in the number of characters per cell. This could happen if you move a user to a different group, and the new group uses grid cards with a different Number of Characters per Cell.

●       a mismatch between the grid size and the Challenge Size or Maximum Challenge Size 

●       removal of a character from the cell alphabet, combined with a new cell replacement mapping. This could happen in the following circumstances, for example:

–  Let’s say the user’s grid has a Z on it.

–  You remove Z from the cell alphabet and move the user to a group for which there is no Z in the cell alphabet.

AND 

–  You change the mapping to make a Z map to a 2.

After this, challenges including Z no longer work, because when the user types a Z, Entrust IdentityGuard gets a 2 instead.

Entrust IdentityGuard generates each challenge using the grid size policy. The least-used challenge algorithm generates challenges according to the history of previous challenges using the current grid card. The least-used algorithm does not update automatically when there are policy or group changes. You might have to issue new grid cards that match the new challenge policies if the policy mismatches result in users being unable to correctly answer challenges with their current grids.
