IdentityGuard Server 13.0 Administration Guide

Updating the master keys and repositories

Master keys are used to protect all sensitive information in the repositories. If you think that this protection may be compromised—perhaps an unauthorized person has learned the master user passwords—you should do the following:

●       Change all your master user passwords. See the Entrust IdentityGuard Master User Shell Reference for instructions.

●       Update the master keys on the primary and replica system. See the Entrust IdentityGuard Master User Shell Reference for instructions.

●       Do a bulk re-encryption of all repository data, as described in To update the repository.

Even if there is no security breach, updating encryption keys on a regular basis is good policy. In this case, just update the master keys without doing a bulk re-encryption. Entrust IdentityGuard will gradually apply the new keys to repository data as it changes.

Follow the instructions below to update the master keys and repositories. These instructions work regardless of where the master keys are stored—either in software, on the Entrust IdentityGuard server, or on a Hardware Security Module (HSM).

To update the master keys

1.      Stop all Entrust IdentityGuard services on the primary and replica systems. For instructions, see the Entrust IdentityGuard Installation Guide.

2.      Back up Entrust IdentityGuard. For instructions, see the Entrust IdentityGuard Installation Guide.

3.      On the primary server:

a.      Start the Master user shell. See Using the Master user shell.

Note: Do not log in to the Master user shell. All master users must be logged out before the master keys can be updated.

b.      Enter the command

system keyupdate

Or, to add a reason for the update, enter:

system keyupdate -reason <text>

The text is added to audit message AUD116.

c.      Enter the three master user passwords when Entrust IdentityGuard prompts for them.

Entrust IdentityGuard generates new master keys and updates the master key file (.enc) on the primary system.

4.      Back up the new master key file (.enc).

Entrust IdentityGuard services cannot start and master users cannot log in without the new master key file.

5.      Copy the master key file (.enc) from the primary system onto each replica system. 

6.      If the master keys are stored on an HSM, and different HSMs are used by different replicas, replicate the master keys from the primary server’s HSM to all replica HSMs. HSMs offer dedicated tools to perform this key replication. Consult your HSM vendor’s documentation for details.

7.      Re-initialize the replica systems like this:

a.      Log in to the Master user shell on the replica systems.

b.      Enter the command:

init -replica -overwrite

For details on the prompts that appear, see the replica section in the Entrust IdentityGuard Installation Guide.

c.      If you want to bind the key protection file to the replica system, enter the command:

system bind

8.      Start all Entrust IdentityGuard services on the primary and replica systems.

After you update the master keys, Entrust IdentityGuard gradually applies the new keys to repository content by securing new or updated data with the new master keys.

Alternatively, you can force an immediate bulk update of all protected data in the repository, as described in the following procedure.

To update the repository

1.      To force a bulk update of the repository, enter this command in the Master user shell on the primary system

system repositoryupdate -start

where -start begins the process.

There are additional parameters available:

●       -status is an optional parameter that provides a small status report

●       -continue is an optional parameter that instructs the process to continue even when errors occur

If you do not include a parameter with this command, Entrust IdentityGuard displays just a status report.

Note: You do not need to enter this command on more than one Entrust IdentityGuard machine.

a.       If you need to stop a bulk re-encryption at any time, enter:

system repositoryupdate -stop

b.      To resume a bulk re-encryption that was stopped, enter:

system repositoryupdate -resume

This command applies to any Entrust IdentityGuard database or LDAP repository, and any file-based repositories used for preproduced cards or unassigned tokens.
