Recovering from hardware changes when the master keys were bound

By default, Entrust IdentityGuard binds the Master Keys to the local computer hardware in such a way that minor changes to the hardware still allows the Entrust IdentityGuard services to start. You can also bind the master keys in strict mode. In strict mode, minor hardware changes will cause the services to fail to start.

If you change your hardware while the master keys are still bound to the computer, the Entrust IdentityGuard services can fail to start and you are prevented from logging in to the Master user shell. To recover from hardware changes when the master keys were bound to the computer, complete the following procedure.

To recover from hardware changes when the master keys were bound

1.      Stop all Entrust IdentityGuard services.

2.      Delete the masterkeys.kpf file (the master keys protection file) from the following location:

●       Windows: <$IG_HOME>\etc 

●       Linux: $IG_HOME/etc 

3.      Start the Master user shell in Linux or Windows (see Using the Master user shell).

4.      Run the following command to re-create the masterkeys.kpf file:

init -replica

You will be prompted to provide passwords for all three Master users.

5.      When prompted, enter the passwords for all three Master users.

6.      Bind the master keys back to the local computer by entering the following command:

system bind [-strict]

Where -strict binds the binds the Master Keys to the local computer hardware in strict mode. In strict mode, minor hardware changes will cause the services to fail to start.

7.      Restart the Entrust IdentityGuard services.
