IdentityGuard Server 13.0 Administration Guide

Token state overview

Tokens have the same states and follow the same state transition rules as grid cards.

For detailed descriptions of the states and state transitions, see Grid card and token state overview. Wherever you see the word “grid card,” substitute the word “token.”

By default, each user can use one token device at a time. However, a user can have a current token and a token in the pending state. For example, if the current token device’s battery is running low, you can associate a pending token with the user. That token replaces the existing token as soon as it is used the first time. After the new token’s state changes from pending to current (which occurs when the user first authenticates successfully using the new token), the old token is canceled by Entrust IdentityGuard.

The current and pending tokens do not have to be the same model or from the same token supplier.

Users can have more than one token. How many they can have is controlled by the Token policy, Maximum Number of Token Sets per User.
