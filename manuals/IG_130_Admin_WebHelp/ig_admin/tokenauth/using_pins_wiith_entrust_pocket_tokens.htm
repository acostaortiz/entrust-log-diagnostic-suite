Using PINs with Entrust Pocket Tokens

Entrust Pocket Token functions are protected by an optional PIN. Users need to enter the PIN before they can access the features of the Pocket Token.

Users can generate only one dynamic password after entering the PIN; to generate another dynamic password, users must enter the PIN again. The PIN should be known only to the individual user, and it may be up to 8 digits in length. Longer PINs provide more secure access to the Pocket Token.

Because a PIN is an optional feature (but recommended for greater security), you can configure Entrust Pocket Tokens to:

●       always require a PIN

●       never require a PIN

●       allow users to disable or enable the PIN feature (see Enable or disable the PIN on a Pocket Token)

Initial PIN

Entrust Pocket tokens are configured with an initial PIN, and users must change the PIN the first time they use the Entrust Pocket Token (see Use a Pocket Token for the first time). Entrust Pocket Tokens can be configured to force users to change the initial PIN before accessing any other functionality, or they can be configured to allow users access to the PIN change function after generating a dynamic password (less secure method). See Change the PIN on a Pocket Token.

Note: The default PIN of the Pocket Token when it is shipped is 1254.

Weak PIN checking

The Entrust Pocket Token can also be configured to check for weak (easy to guess) PINs and reject such PINs during a PIN change operation. When this option is set (during initialization), a PIN is considered weak if the distance between subsequent digits is a constant value. For example, 0000, 12345, and 97531 are weak PINs, while 1254, 12856, and 9371 are considered strong PINs.
