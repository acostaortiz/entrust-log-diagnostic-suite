IdentityGuard Server 13.0 Administration Guide

Configure token policies

Set the token policies in the Administration interface.

To view hardware token policies

1.      Log in to the Entrust IdentityGuard Administration interface as the administrator.

On the Windows computer where Entrust IdentityGuard is installed

●       Select Start and expand Entrust  IdentityGuard in the list of applications. Select Administration Interface. For other login scenarios, see Log in and out of the Administration interface.

On Linux or from a remote client

●       Enter the URL of your Administration interface web application in a Web browser. It has this form:

https://<hostname>:<port>/IdentityGuardAdmin

Where:

<hostname> is the host name you selected during configuration

<port> is the administration port you selected during configuration

If you cannot find the correct URL, see Locate your Administration interface URL.

For other login scenarios, see Log in and out of the Administration interface.

2.      Select Policies on the menu bar.

A list of all policies appears on the List Policies tab.

3.      Click a policy name.

The View Policy page for the selected policy appears.

4.      From the Policy Category drop-down list, select Token.

The token policies appear.

To configure hardware token policies

1.      Find the authentication policy to change.

2.      On the View Policy page, click Edit Policy.

An editable version of the settings appears.

3.      Edit the policies as required. The following policies are related to hardware tokens. Select a policy in the list to see its description.

Unassign Hardware Tokens When User is Deleted

When you remove users, this parameter determines whether their tokens are deleted or unassigned. If you delete a token, it can never be used again with Entrust IdentityGuard.

Yes indicates their tokens are unassigned before the users are deleted, and No means their tokens are deleted with the user.

Default: Yes

Move Hardware Tokens to User’s Group During Assignment

When tokens are loaded, they are assigned to a particular group. When assigning the tokens to users, the token’s group and the user’s group may not match.

Select this policy to automatically move tokens from their current group to the group of the user during assignment.

When this policy is set to No, a mismatch of the user group and the token group results in an error message.

Default: No

Reset Token When Token is Created or Activated

Specifies whether a token will be reset on first authentication after the token is assigned to a user (for hardware tokens) or when it is created and activated (for soft tokens). This policy resets the time for time-based tokens, the event counter (for event-based tokens), or both (for tokens that are time- and event-based.

Default: No

Note: This policy is not enabled by default. Enabling this policy is recommended, especially for event-based tokens( which can get out of sync if a button is pressed during shipping or if users test it prior to activation).

Maximum Number of Token Sets per User

Specifies the number of token sets a user is allowed. A token set is a name given to the set of tokens that move through their state transitions together. For example, a single user might have one token set called "BlackBerry" and another token set called "Hardware token".

For details on token sets, see Token set overview (using multiple tokens).

Default: 1

Disable Challenge Retention

This setting applies only to challenge-response hardware tokens.

Enable this setting if you want to replace the token challenge each time a challenge is requested. Users who answer a challenge incorrectly will have a new challenge presented to them for the next attempt.

Deselect it if you want to retain the challenge for the duration of the Token Challenge Lifetime. Users who answer a challenge incorrectly will have the same challenge presented to them for all subsequent attempts until they are locked out or until the challenge lifetime is exceeded. After the challenge lifetime is exceeded, a new challenge is presented.

Default: No

Token Challenge Lifetime

This setting applies only to challenge-response hardware tokens.

Set it to Unlimited to have the token challenge last an unlimited amount of time.

Set it to a number of seconds to limit the lifetime. If it is not answered in the lifetime, a new challenge is generated.

Default: Unlimited

Update Lockout for Replaced Challenge

This setting applies only to challenge-response hardware tokens.

When set to Yes, the lockout count is increased when a token challenge is replaced because:

•  a user does not answer a token challenge in the allotted time (as defined by the Token Challenge Lifetime setting) causing a new challenge to be requested by the client application

•  a user restarts the client application without answering the token challenge, causing a new challenge to be requested by the client application

When set to No, the lockout count is not increased in the above-mentioned scenarios.

Note: The lockout count is always increased when a user enters an incorrect challenge response, regardless of how you configure this setting.

4.      If you are using a client application that allows token authentication when users are not connected to their network, configure the following policies.

Note: The offline token authentication feature can be used with hardware tokens that support the OATH TOTP protocol, ActiveIdentity OT tokens, and Entrust soft tokens. It is not supported with hybrid time-and-event-based tokens such as Entrust Datacard CR tokens and Entrust Pocket tokens. Currently, this feature is used only with Entrust IdentityGuard Desktop for Microsoft Windows (version 11.0 or later). In the future, they could be used with other applications.

Protected Offline OTP Support

Specifies whether users of the client application can download a supply of time-based, one-time passwords for use when they are not connected to their network.

•  Not Allowed — Users cannot download OTPs for offline authentication.

•  Allowed — When connected to the network, users can download a supply of OTPs for later use when they are not connected to their network.

•  User Requires PVN —  Users can download a supply of OTPs for offline authentication and their PVNs are also used as part of the offline authentication. This option is used only when the PVN policy requires use of PVNs as part of token authentication.

Default: Not Allowed

This feature should be enabled in a policy applied only to groups of users who will need to perform offline token authentication, not to all users because download of OTPs can have an impact on product performance. For more information, see the Entrust IdentityGuard Desktop for Microsoft Windows Administration Guide.

Protected Offline OTP Max. Clients

Specifies the maximum number of client applications through which users can request download of OTPs for offline token authentication.

Default: 1

Note: Currently, the only client application that supports download of tokens for offline use is Entrust IdentityGuard Desktop for Microsoft Windows (version 11.0 or later). For more information, see the Entrust IdentityGuard Desktop for Microsoft Windows Administration Guide.

Protected Offline OTP Minor Refill

When an application that allows offline token authentication requests a small refill of a number of hours' worth of OTPs to download, the server uses this setting to determine the number of OTPs to generate. The value can be expressed in hours or in days. For example, a value of 1 day means that Entrust IdentityGuard downloads 2880 OTPs, enough to refresh the OTP every 30 seconds for 1 day (24 hours).

Enter a value in  hours or days. For hours, valid values are 1 to 366. For days, valid values are 1 to 14. This setting must have a value.

Default:1 hour

Note: If you enter a larger value for Protected Offline OTP Minor Refill than for Protected Offline OTP Max. Refill, Entrust IdentityGuard allows the configuration to be saved but it adjusts the numbers during client authentication to ensure that no more than the Protected Offline OTP Max. Refill value is generated and returned.

For more information, see the Entrust IdentityGuard Desktop for Microsoft Windows Administration Guide.

Protected Offline OTP Max. Refill

When an application that allows offline token authentication requests the maximum number of hours' worth of OTPs to download, the server uses this property to determine the number of OTPs to generate. The value can be expressed in hours or in days. For example, a value of 14 days (the maximum allowed) would mean that Entrust IdentityGuard would download 40,320 OTPs, enough to refresh the OTP every 30 seconds for 14 days.

Enter a value in hours or days. For hours, valid values are 1 to 366. For days, valid values are 1 to 14. This setting must have a value

Default:1 hour

For more information, see the Entrust IdentityGuard Desktop for Microsoft Windows Administration Guide.

Protected Offline OTP Protection

Specifies the strength of the protection that is used when hashing the OTPs that are stored on a user’s computer.

The options are Normal, Strong, and Very Strong. The stronger the protection, the more difficult it becomes for a potential attacker to guess the OTP. However, when the protection level is stronger, it takes longer for Entrust IdentityGuard Desktop to validate the OTP.

Default: Normal

For more information, see the Entrust IdentityGuard Desktop for Microsoft Windows Administration Guide.

5.      Click Save Changes.
