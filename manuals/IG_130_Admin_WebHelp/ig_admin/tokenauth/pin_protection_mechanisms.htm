IdentityGuard Server 13.0 Administration Guide

PIN protection mechanisms

Entrust Pocket Tokens offer a choice of protection mechanisms in case someone enters the wrong PIN:

●       delay (fixed or incremental)

●       lock

●       reset

The fixed delay and incremental delay mechanisms are mutually exclusive, but you can use the locking and resetting mechanisms with either of the delay mechanisms. See the following topics for more information about each mechanism.

Delay mechanism

If the Pocket Token is configured to use the delay mechanism and you enter the wrong PIN, the Pocket Token displays ERROR and then automatically shuts off.

●       Fixed delay — You cannot turn the Pocket Token back on for a specified length of time (0 to 128 seconds). If you attempt to turn the Pocket Token back on before the delay period ends, the token displays a WAIT message. The fixed delay time is configured during initialization.

●       Incremental delay — For the first wrong PIN entry, you cannot turn the Pocket Token back on for two seconds. For each successive wrong PIN entry, the delay before you can turn the Pocket Token back on is double the time of the previous delay (that is, 4 seconds, then 8 seconds, then 16 seconds, and so on). The maximum delay is 9 hours. If you attempt to turn the Pocket Token back on before the delay period ends, the token displays a WAIT message.

The delay mechanism gives a user several chances to enter the correct PIN without locking or resetting the Pocket Token. The delay mechanism makes Pocket Tokens easier for the system administrator to manage. The delay mechanism also avoids accidental locking of the token by someone playing with it.

For additional protection, a Pocket Token using the delay mechanism can also be configured to automatically lock or reset, or both, if someone continues to enter wrong PINs. See the appropriate sections below for more information about these PIN protection mechanisms.

Lock mechanism

If an Entrust Pocket Token is configured to use the lock mechanism and you enter the wrong PIN, the Pocket Token displays ERROR and then prompts you to enter the correct PIN.

If you continue to enter wrong PINs (up to 4), the Pocket Token displays the LAST TRY message. If you enter the wrong PIN again, the token will lock. The number of consecutive wrong entries allowed before the token locks is configured during initialization.

Unlock function

When the Pocket Token is locked, only the unlock function is available. When you turn the Pocket Token on, it displays the unlock challenge. The system administrator needs this unlock challenge to generate the unlock code. After the system administrator generates the unlock code, the user enters it into the Pocket Token to unlock it.

●       If the unlock code is correct, the Pocket Token unlocks and, optionally, prompts you to change your PIN (see Change the PIN on a Pocket Token).

●       If the unlock code is incorrect, the Pocket Token remains locked, increases the unlock counter by one, and then turns off.

●       If the unlock counter exceeds the maximum value (configured during initialization), the Pocket Token automatically resets.

●       If the Pocket Token resets, the token must be initialized again.

The lock mechanism provides the strongest protection for the Pocket Token; however, it can result in more work for the system administrator who manages the Pocket Tokens.
