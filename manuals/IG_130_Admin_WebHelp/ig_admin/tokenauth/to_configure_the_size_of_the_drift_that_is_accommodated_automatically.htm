To configure the size of the drift that is accommodated automatically

1.      Find the entrusttoken.conf file (or an equivalent file with a different name). If the file does not exist, create it as a text file. The default location is:

●       on Linux, $IG_HOME/etc/

●       on Microsoft Windows, <$IG_HOME>\etc\

2.      Add one of the following entries to the file:

Token type

Add...

Event-based tokens

automaticResetEventWindow=<size>

where <size> is the number of token responses that Entrust IdentityGuard searches during a normal authentication operation to find a token response that matches what the user entered.

Rules for allowable <size> values:

·      must be an integer divisible by 10

·      minimum 10, maximum 200

·      must be smaller than the value set in the resetEventWindow parameter

automaticResetEventWindow=50

The default is 10.

The larger the event window, the greater the risk of someone being able to guess the dynamic token password. Larger event windows can also make authentication slower.

Time-based tokens

maxTimeSteps=<timestep>

where <timestep> is a number of 30-second time steps that Entrust IdentityGuard searches in both positive and negative directions during a normal authentication operation to find a token response that matches what the user entered.

One timestep = 30 seconds.

Examples:

maxTimeSteps=10 (10 X 30 = 300 seconds = 5 minutes)
maxTimeSteps=120 (120 X 30 = 3600 seconds = 1 hour)

The default is 10 (5 minutes).

The maximum is 120 (1 hour).

As the clock window is set larger, the risk of someone being able to guess the dynamic token password increases.

Exactly how long a response is valid depends on how much of the time window had elapsed the last time the user authenticated. Therefore, a token response can be said to be valid for at least maxTimeSteps X 30 and at most (maxTimeSteps + 1) X 30.

Note: Although this is atypical, some tokens (for example, OATH tokens) might use different time-step values such as 60 seconds.

3.      Save the file.
