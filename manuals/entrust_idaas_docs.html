1. Visión General y Arquitectura IDaaS (Getting Started)

Entrust Identity as a Service (IDaaS) es la plataforma de gestión de accesos e identidades (IAM) en la nube de Entrust. Proporciona autenticación multifactor (MFA), Single Sign-On (SSO) federado mediante SAML 2.0 y OpenID Connect (OIDC), aprovisionamiento automático mediante SCIM 2.0 y políticas adaptativas basadas en riesgo (RBA).

🏢 Roles de Administración
  • Super Administrator: Control total del tenant, configuración de conectores, políticas globales y certificados.
  • Help Desk Administrator: Gestión de usuarios, reseteo de contraseñas, enrolamiento de tarjetas y desbloqueo de tokens.
  • Auditor: Acceso de solo lectura para reportes de cumplimiento, auditoría y trazabilidad.
  • SIEM Add-on: Exportación continua de eventos de auditoría vía Webhooks o streaming hacia SOC.

2. Aprovisionamiento Masivo & Gestión de Identidades (Bulk Operations)

Para operaciones bancarias y corporativas masivas (como Banco Mercantil con más de 16.5 millones de registros), IDaaS soporta la carga y reconciliación por lotes de credenciales (Tarjetas Grid, Contraseñas, Desafíos Q&A y Tokens de Hardware/Software).

📋 Estructura de Lote Bulk CSV / API: Los archivos de importación deben estructurarse con codificación UTF-8, delimitados por comas o tabulaciones, respetando los identificadores de credencial y políticas de reemplazo.

Mapeo Forense de Códigos de Error en Aprovisionamiento Masivo

Patrón de Log / Error Significado Técnico Causa Raíz Remediación Oficial
bulkidentityguard.add.error.assignedgrid Conflicto de Tarjeta Grid preexistente El usuario ya tiene una tarjeta Grid activa y el lote no incluyó la bandera de reemplazo. Establecer overwriteExistingGrid=true o excluir usuarios ya aprovisionados en el delta CSV.
bulkidentityguard.add.error.qa Preguntas secretas (Q&A) duplicadas Intento de registrar preguntas de desafío sobre una identidad con preguntas ya configuradas. Habilitar updateExistingCredentials=true en la definición del trabajo por lotes.
bulkidentityguard.add.error.password Conflicto de credencial de contraseña Colisión de hash o directiva de cambio de password mandatoria sin autorización de reseteo. Verificar directiva allowPasswordReset=true y formato de hash admitido (SHA-256 / PBKDF2).
bulkidentityguard.add.error.invaliduser Identificador de usuario inválido El campo de nombre de usuario contiene caracteres no soportados o supera la longitud permitida. Sanitizar el archivo de origen según el esquema de nombres de IDaaS (alfanumérico y sin espacios).

3. Autenticación, MFA Adaptativo & Passwordless

Entrust IDaaS integra múltiples factores de autenticación adaptativos calibrados por nivel de riesgo, ubicación geográfica, huella de dispositivo y reputación de IP.

📱 Factores Soportados
  • Entrust Identity Mobile App: Push notifications (Touch ID / Face ID) y Soft Token OTP dinámico.
  • FIDO2 / WebAuthn: Llaves de seguridad físicas (YubiKey) y passkeys biométricas en navegador.
  • Tarjetas Grid / eGrid: Matriz de coordenadas alfanuméricas para banca electrónica.
  • Hardware Tokens: OATH TOTP / HOTP estándar y WatchData QRO.
  • SMS / Email OTP: Entrega de contraseñas de un solo uso por canales alternos.

⚠️ Troubleshooting de Autenticación

Fallo SAML_RESPONSE_EXPIRED:

ClockSkew: Asegurar desfase < 180s entre IdP y SP. NTP Server: Verificar sincronización en servidores locales.

Fallo PUSH_NOTIFICATION_FAILED:

APNs / FCM: Comprobar conectividad hacia push.apple.com y fcm.googleapis.com Device ID: Validar que el dispositivo no haya sido des-asociado.

5. Guía para Desarrolladores: APIs REST, SCIM & SDKs

La plataforma expone dos familias de interfaces de programación REST bajo especificación OpenAPI:

🛠️ Administration REST API

Permite automatizar la administración de identidades, grupos, roles y credenciales:

# Ejemplo: Obtener detalles de usuario vía Admin API GET https://api.trustedauth.com/admin/v1/users/{userId} Authorization: Bearer <ADMIN_ACCESS_TOKEN> Content-Type: application/json

6. Migración desde IdentityGuard OnPremise a IDaaS Cloud

Para migrar almacenes existentes de Entrust IdentityGuard (v11.0, v12.0, v13.0) hacia IDaaS Cloud:

  1. Extracción en OnPremise: Ejecutar la utilidad IG_Migration_Tool (comando authexport) para generar el archivo cifrado .dat.
  2. Auditoría de Eventos: Supervisar los eventos [AUD8500] (inicio), [AUD8503] (despliegue de clave simétrica) y [AUD8502] (finalización exitosa).
  3. Carga en IDaaS Cloud: En el Administrator Portal de IDaaS, navegar a Migration > Import Package e introducir la clave generada por el usuario Master.
  4. Validación y Switchover: Ejecutar pruebas de autenticación cruzada con el conector RADIUS/SAML antes del corte definitivo.
