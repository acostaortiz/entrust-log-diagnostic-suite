Machine secrets that provide a low or variable security level

The same machine secret policy settings can lead to a security level that varies depending on what is happening on the computer. This topic describes scenarios in which this can happen.

Machine secret policy settings for low or variable security level

Disable the policy attributes for using a machine nonce and a sequence nonce. Have the application supply at least one set of application data and be sure to set the Bad Application Data Elements Allowed policy to 0. The following table shows the machine secret settings for this level of security.

Machine Secret Policy

Value

Sequence Nonce Required

Not set

Machine Nonce Required

Not set

Application Data Elements Required

at least 1

Bad Application Data Elements Allowed

0

Scenario 1: The client machine cannot or will not store the machine secret

In this scenario, the client machine cannot or will not store the machine secret, so computer identification depends entirely on the application data. More...

With the machine secret settings shown in the preceding table, this is what happens:

●       When a user first registers for machine authentication, the application generates and passes the application data to Entrust IdentityGuard as part of a machine authentication request. Entrust IdentityGuard stores the application data in the repository. Entrust IdentityGuard still generates a machine nonce and returns it as a machine secret to the application, but the application does not store the machine secret.

●       The next time the user logs in, the application generates and sends the same application data to Entrust IdentityGuard as it did the last time. Entrust IdentityGuard compares the application data passed by the application to that stored in the repository, looking for a match. If it finds a match, machine authentication succeeds.

If the application data passed by the application does not contain unique or uncommon data items, it is possible for more than one user to have the same machine secret, so it is possible to match an unintended user.

Scenario 2: The client deletes the machine secret from the machine after it is stored

In this scenario, the client computer stores the machine secret and returns it during authentication, if available. Sometimes users delete the object that contains the machine secret (for examplek, a cookie or a local flash object), but you want machine authentication to proceed anyway. In this case, only application data is available for use in machine authentication. More...

With the machine secret settings shown in the preceding table, this is what happens:

●       When a user first registers for machine authentication, the application generates and passes the application data to Entrust IdentityGuard as part of a machine authentication request. Entrust IdentityGuard generates a machine nonce, and possibly a sequence nonce, to create the machine secret. It stores the machine secret and application data in the repository and returns a copy of the machine secret to the application. The application stores the machine secret on the client computer.

●       The next time the user logs in, one of two things happens:

–  If the cookie exists, the application passes the machine secret and regenerated application data to Entrust IdentityGuard as part of a machine authentication request. Entrust IdentityGuard compares it to the copy stored in the repository. If they match, machine authentication succeeds.

–  If the cookie is absent, the application generates and sends the same application data to Entrust IdentityGuard as last time. Entrust IdentityGuard compares the application data passed by the application to that stored in the repository looking for a match. It accepts the first match it finds.

●       Entrust IdentityGuard regenerates the machine secret and passes it to the application. The application stores the new machine secret on the client computer.

During authentication, Entrust IdentityGuard expects the application to return the machine nonce but failure to do so does not result in failed authentication. The actual security level (medium or low) depends on whether computers are identified by a complete machine secret based on a machine nonce or just a machine secret based on application data.

Note: Some users delete their browser cookies regularly. To avoid the loss of machine secrets in this manner, configure your application to use local shared objects instead (this requires Macromedia Flash Player).
