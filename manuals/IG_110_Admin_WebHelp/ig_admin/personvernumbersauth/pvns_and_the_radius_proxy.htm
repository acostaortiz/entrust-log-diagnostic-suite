IdentityGuard Server 11.0 Administration Guide

PVNs and the Radius proxy

If your users access Entrust IdentityGuard through the Radius proxy, you can include the PVN as part of a challenge for:

●       grids (second-factor authentication)

●       response-only tokens (first or second-factor authentication)

●       challenge-response tokens (second-factor authentication)

●       one-time passwords (second-factor authentication)

The Radius proxy does not support the creation of new PVNs. If users access your application through a VPN, administrators must assign users their PVNs. PVN updates are supported through PAP only. For details, on Radius protocols, see Configuring the Entrust IdentityGuard Radius proxy.

Responses to a challenge through the Radius proxy must be entered as a single string. The user must concatenate all responses into a single string of numbers, or numbers and characters, as applicable. For example, the response to a four-digit PVN challenge (for example, 1234) with a three-cell grid challenge (for example, DX9) looks like this:

1234DX9

And the response to a four-digit PVN challenge and an eight-digit token challenge (for example, 96784567) looks like this:

123496784567

A PVN update always requires that the new PVN be entered twice for confirmation. The current PVN is entered before the challenge response, and the new PVN is entered twice, after the challenge response. For PVN updates through the Radius proxy (PAP protocol only), the response to a four-digit PVN challenge and a three-cell grid challenge plus the PVN updates (for example, 6789) looks like this:

old pvn + challenge response + new pvn + new pvn

1234DX967896789

Using the “Separate Challenge for PVN Update” property in the Properties Editor, you can change this PVN update behavior so the user does not have to enter all of the information in one line. First, the user is asked for the challenge response. The user enters the old PVN, followed by the challenge response.

old pvn + challenge response

Using the same example codes as above, the old pvn and challenge response looks like this:

1234DX9

The user is then prompted to enter a new PVN:

6789

Then the user is prompted to confirm the new PVN:

6789

If the user wants to change their PVN when Entrust IdentityGuard does not require a change, the user must enter the new PVN, as confirmation, with the challenge response.

1234DX967896789

Use the Properties Editor to set the related Radius challenge strings (see Customizing VPN challenge strings).
