Synchronization of user accounts in Active Directory and Entrust IdentityGuard databases

With this release, Entrust IdentityGuard supports synchronization between Microsoft Active Directory user data and Entrust IdentityGuard user data stored in a database. The feature is configured in Entrust IdentityGuard and requires no schema or other changes in the Active Directory environment. 

More...

Users added in Active Directory can be displayed in an enrollment list that an administrator can then use to create Entrust IdentityGuard accounts. User accounts created this way or already existing in Entrust IdentityGuard can then be synchronized with Active Directory. During a synchronization operation, user names, contact information and expired or disable status in Active Directory can be updated in the Entrust IdentityGuard database. Synchronization can be performed automatically through Active Directory notifications or on demand by an administrator. 

The synchronized user data in the Entrust IdentityGuard database is a copy of what is in Active Directory, however, Entrust IdentityGuard makes real-time calls to Active Directory to validate a user's Active Directory password and obtain user attributes for Entrust IdentityGuard Radius authentication and during smart credential activation.

Enhancements to risk-based authentication

This release features enhancements to the machine authentication portion of risk-based authentication (RBA). Previously, Entrust IdentityGuard depended on a customer application to deliver a machine nonce and sequence nonce from a user's browser to test whether there was an exact match that would allow machine authentication. Today, many users delete cookies from their browsers, causing machine authentication to fail and forcing them to re-authenticate.

The new Entrust IdentityGuard Device Fingerprint SDK helps you add new data capture capabilities to your client applications to deliver a more comprehensive and flexible "device fingerprint". More...

The device fingerprint is based on a number of attributes of the user's browser, Android device, or iOS device, with allowances for some change in some attributes. Within Entrust IdentityGuard, new Machine Secret policies related to the device fingerprint allow you to specify which collected attributes should be used in the device fingerprint, specify the degree of change (if any) allowed for each attribute, and assign each attribute a relative weight based on the potential risk posed by a change in that attribute.

In addition, if you set Machine Secret policies to require use of nonce values, the Device Fingerprint SDK provides that ability to store the machine nonce and sequence nonce to various storage locations to improve their robustness and protect against a user deleting this information when they delete browser cookies. Use of nonce values is optional with this release due to the enhanced device fingerprinting capabilities.

For more information, see the Entrust IdentityGuard Device Fingerprint SDK Programming Guide, and the "Machine authentication" and "Risk-based authentication" sections of the Entrust IdentityGuard Server Administration Guide.

New security policies to control usage of mobile apps on unsecured devices

The Entrust IdentityGuard mobile applications (Entrust IdentityGuard Mobile Smart Credential version 3.0 or later and Entrust IdentityGuard Mobile Soft Token version 3.1 or later) app can now optionally be run on unsecured devices, that is, on Android devices that have been rooted or iOS devices that have been jailbroken. New smart credential and token policies in Entrust IdentityGuard support optional use of this feature.

Storage of mobile soft token seed in Trusted Execution Environment (TEE)

The Entrust IdentityGuard Mobile Soft Token version 3.1 introduces the capability to store mobile soft tokens in the isolated hardware of a mobile device. This provides enhanced security for the soft token seed.  A new optional Entrust IdentityGuard Soft Token policy (Mobile Soft Token Trusted Execution Environment) supports this feature. 

More...

Currently, only the Samsung KNOX TEE is supported on Samsung devices on which the TEE has been enabled. Review the technical specifications of Samsung devices in your user population to determine if you can make use of this feature. 

Use of this feature requires one TEE Storage for Soft Tokens license for each soft token stored in the TEE.

Support for Touch ID on Mobile Smart Credential app

Users of the Entrust IdentityGuard Mobile Smart Credential app (version 3.0 or later) can take advantage of the iOS Touch ID feature instead of a PIN to unlock the app and to authenticate security challenges. A new Smart Credential policy, Mobile Smart Credential Allow Fingerprint Authentication, enables optional support of this feature.  User procedures are documented in the app help and user guide.

Licensing changes

In previous releases of Entrust IdentityGuard, feature-specific licenses were counted for each authenticator created. Entrust IdentityGuard now associates most licenses with a user account so a user can have more than one of a licensed type of authenticator, for example, multiple soft tokens use only one license. This change applies to all license types except Biometrics and the new license type, TEE Storage for Soft Tokens.

Support for external smart credential login to the Administration interface

Entrust IdentityGuard supports login to the Administration interface with smart credentials. In this release, the feature is enhanced to allow administrators to log in with smart credentials created by a smart credential issuer other than Entrust IdentityGuard.
