IdentityGuard Server 11.0 Administration Guide

How Active Directory synchronization works

The following sections describe how the Active Directory synchronization feature works when administrators or users perform various actions.

When you add a new user in Active Directory

After you configure the Active Directory synchronization feature as described in this section, you have the option to create Entrust IdentityGuard user accounts for new Active Directory users as described in Create new Entrust IdentityGuard user accounts from Active Directory. (You can also create the Entrust IdentityGuard user accounts directly in Administration interface, after which they can be synchronized with Active Directory.)

Entrust IdentityGuard creates the user accounts and performs a first synchronization operation for the new user accounts. User accounts that have been synchronized display synchronization information in the Account Information and have the Sync Account and Unsync Account option buttons.

When you change user account information in Active Directory

The following Active Directory account information can be synchronized with Entrust IdentityGuard (copied into the Entrust IdentityGuard database):

●       Disabled

●       Expired

●       Fullname — The user’s full name in the repository. If the Entrust IdentityGuard user fullname is not set, the Active Directory value is used.

●       Contact information — The user’s contact information in the repository. This data is merged with the user’s current Entrust IdentityGuard contact information. This is mapped using the current LDAP Contact Info Mapping settings. The following values are stored in the Entrust IdentityGuard database repository with an AD Sync directory configured.

–  Value

–  Label

–  Is Default

–  Delivery Method

When you delete a user from Active Directory

When a user is deleted from a synchronized Active Directory container, Entrust IdentityGuard receives a notification and marks the user account as Orphaned in Repository.

Entrust IdentityGuard does not automatically delete Entrust IdentityGuard user accounts because doing so would delete all authenticator data for the user and it cannot be recovered if the user account was deleted by mistake from Active Directory.

Note: If a deleted user account is recreated in Active Directory, the new account has a new unique ID, so the original user account must be deleted and recreated or unsynchronized and resynchronized so the sync unique user ID is reset.

If a user account is moved to a different Entrust IdentityGuard repository

●       If the user is placed in an Entrust IdentityGuard LDAP repository, all sync operational and user data is removed.

●       If the user is placed in an Entrust IdentityGuard database repository without an AD Sync directory configured (or the Entrust IdentityGuard database no longer has an AD Sync directory configured), all sync operational and user data is removed

●       If the user is placed in an Entrust IdentityGuard database repository with the same AD Sync directory, the user remains synchronized.

●       If the user is placed in an Entrust IdentityGuard database repository with a different AD Sync directory, the user account is synchronized at the time of the update. If the user account cannot be synchronized (for example, because the user does not exist in the new AD Sync directory), the user is orphaned. In this case the source unique id and the sync DN value are also removed and the sync user name is reset to the Entrust IdentityGuard user name. The following audit message is written:

Unable to synchronize user default/john with unique user ID 119d0d80-699d-4e81-8e4e-5477e22ac1b3 as the user cannot be found against the LDAP sync directory AD, the unique user ID will be removed and the user will be orphaned.

When a user's name changes in Active Directory

If a user name is changed in Active Directory the Entrust IdentityGuard user and sync data remain in place because the source unique user ID has not changed. The list of users that can be enrolled in Entrust IdentityGuard will include the new user name, however, creation of this user will fail because the ID already exists in Entrust IdentityGuard  or a user. The administrator must explicitly update the Entrust IdentityGuard user name. Automatic handling of Active Directory user name changes is not currently supported. This might be considered in a future release.

Note: In the current release, the user name used for external authentication must be the same as the Entrust IdentityGuard user name. If the Active Directory user name changes and it is not updated in Entrust IdentityGuard (or vice-versa), external authentication will fail for the user.

When users change their name or contact information through Self-Service or another client application

Synchronized data is read only, but fullname and contact info have corresponding Entrust IdentityGuard user attributes. If these attributes are changed by a user, updated values are retained in the Entrust IdentityGuard database. They are not overwritten by Active Directory values during subsequent synchronizations.
