IdentityGuard Server 11.0 Administration Guide

Limitations of the Active Directory synchronization feature

This feature has the following limitations in the current release:

●       Active Directory groups are not mapped to Entrust IdentityGuard groups in this release.

●       This feature is not supported for Microsoft Active Directory Lightweight Directory Services (AD LDS) or Microsoft Active Directory Application Mode (ADAM) at this time.

●       Only one Active Directory searchbase is supported for each Entrust IdentityGuard database. If an additional Active Directory searchbase is required, it must be configured and associated with a different Entrust IdentityGuard database.

●       If the Active Directory change notification mechanism is not running or Entrust IdentityGuard is not running, any changes during that time will be missed if an error occurs during a synchronization operation and the synchronization doesn't occur, Entrust IdentityGuard does not repeat the operation. In this case, user accounts will not be synchronized until the next background synchronization operation when the user entry is updated again (for example, the next time the user logs in). If an immediate synchronization is required, it can be done manually through the Administration interface or the Master user shell. For instructions see, perform a manual synchronization. Alternatively, you can perform an Entrust IdentityGuard bulk operation using  the user set command for a specified file of users that require re-synchronization. (This could be done each night, for example.) Bulk operations can be done through the Administration interface or through the Master user shell. They can also be initiated using the Entrust IdentityGuard Administration API.
