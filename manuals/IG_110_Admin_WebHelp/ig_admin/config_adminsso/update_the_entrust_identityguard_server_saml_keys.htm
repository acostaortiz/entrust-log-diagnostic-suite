IdentityGuard Server 11.0 Administration Guide

Update the Entrust IdentityGuard Server’s SAML keys

As part of your SAML configuration, you specified a SAML certificate to be used by Entrust IdentityGuard Server. This certificate’s keys are used to secure SAML messages bound for the Federation Module. If this certificate is scheduled to roll over soon, use this procedure to add a new certificate and keys to Entrust IdentityGuard.

Generate a new SAML certificate and keys for Entrust IdentityGuard Server

1.      Generate and import a new SAML certificate and corresponding keys for use by the Entrust IdentityGuard Server. See Generate a SAML certificate to be used by Entrust IdentityGuard Server for details.

2.      When importing the SAML keys to the keystore on the Entrust IdentityGuard Server, give the keys a unique alias such as igsaml2 to distinguish them from any other SAML keys that may be present. You do not want to overwrite the old keys.

Configure SAML SP key settings in the Properties Editor 

1.      On the Entrust IdentityGuard Server, log in to the Properties Editor. See Log in or out of the Properties Editor.

2.      From the table of contents, click SAML SP Keys Settings.

3.      Under Configuration Instances, enter a name for the new SAML certificate and corresponding keys.

Example: IG Server SAML Keys 2

4.      Under Key Alias, enter the alias of the new SAML certificate. The certificate’s corresponding keys will be used by the Entrust IdentityGuard Server to secure SAML messages for all the Federation Module deployments defined under SAML IDP Settings. For example, igsaml2.

5.      Under Key Password, enter the password for the certificate specified under Key Alias. You would have specified this password when you imported the SAML certificate to the keystore using the keytool utility. If you did not specify a password for the certificate when you imported it, then enter the associated keystore password. If you are using the Entrust IdentityGuard Server’s default keystore, the password is entrust.

6.      Select Encrypt to encrypt the password.

7.      Click Validate & Save.

You have now defined and loaded the new SAML certificate and keys. At this point, the Entrust IdentityGuard Server continues to use the old certificate and keys to secure its SAML messages to the Federation Module.

Update the SP metadata on the Federation Module

1.      On the Federation Module, open the igfmconfig.bat utility and run this command:

igfmconfig.bat setSAMLpartner <PartnerEntityID> -autoReloadMetadataEnabled true

[-verifymetadata true] -resetCacheDuration true

For details on this command, see the "Enabling auto-reloading of metadata (SAML)" section of the Entrust IdentityGuard Federation Module Installation and Configuration Guide.

This command refreshes the Entrust IdentityGuard Server’s (SP’s) metadata, and consequently makes the Federation Module aware of both the old and new SAML certificates and keys.

2.      Wait five minutes. This is the amount of time it takes before you can be sure the metadata is refreshed.

Set a new default SAML key

1.      Go back to the Entrust IdentityGuard Server and log in to the Properties Editor. See Log in or out of the Properties Editor.

2.      From the table of contents, click SAML SP Keystore Settings (near the bottom).

3.      Under Default Signing Key Alias, set the alias to the new SAML certificate alias. For example, igsaml2.

4.      Click Validate & Save.

The new certificate and keys are now used by the Entrust IdentityGuard Server to secure SAML messages. The old certificate is no longer used.
