IdentityGuard Server 11.0 Administration Guide

How SAML login works with the Administration interface

This section describes the SAML login process into the Administration interface:

1.      An administrator, Bob, navigates to the Administration interface, and he clicks the SAML Single Sign-On link on the login page. This redirects him to the Federation Module login page.

OR

An administrator, Bob, navigates to the Administration interface, and he is immediately redirected to the Entrust IdentityGuard Federation Module login page. The Federation Module is a separate Web application. It is a mandatory component.

2.      Bob logs in through the Federation Module using the authentication methods that you configured in the Federation Module. For example, Bob might log in with LDAP credentials for first-factor authentication, and a grid for second-factor authentication.

3.      The Federation Module communicates with Entrust IdentityGuard Server to authenticate Bob.

4.      A SAML assertion is created indicating that Bob has successfully logged in. It includes information that identifies Bob, including his Entrust IdentityGuard user name. The SAML assertion is in XML format and is passed between Bob, the Federation Module, and the Administration interface.

5.      The Administration interface uses a built-in administrative account with the delegationadmin role to gain access the Entrust IdentityGuard APIs necessary to perform the user authentication. (For more information about this account, see Create a delegation administrator.)

6.      Bob is granted access to the Administration interface, with access to the functionality defined by his Entrust IdentityGuard role.

7.      Bob can now access other SAML applications (that is, SP sites) without re-submitting his credentials, as long as those SP sites are configured to use the same Federation Module, and are configured to ask for the same authentication methods.
