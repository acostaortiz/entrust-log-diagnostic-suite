IdentityGuard Server 11.0 Administration Guide

User Data policies

These policies cover miscellaneous user specification features.

Maximum Number of Aliases

Sets the maximum number of application user names to be mapped to a Entrust IdentityGuard user ID. A reasonable default number is set to ensure that capacity issues are not encountered. A setting of 0 means no aliases are allowed.

Default: 5

Include User Information in Challenge

Determines whether the grid challenge or token includes information about a user. Examples of the information displayed are a grid or token serial number or and indicator of whether the user has a temporary PIN. Displaying this information provides a form of mutual authentication.

Note: This may reveal additional information to an attacker.

Default: Yes (selected)

Maximum Number of Contact Info Entries

Sets the maximum number of contact references (email addresses, phone numbers, OTP delivery solutions) to store for each user. It must be greater than zero. If the setting is 0, users cannot have contact information.

Default: 10

Note: When creating a user from an LDAP-compliant directory, the number of contact information entries is not checked. An error message is displayed when you modify or update the user’s account at a later time.

User Registration Password Lifetime

The lifetime, in minutes, associated with an internally generated password that authenticates a request to activate a smart credential, activate a soft token online, or submit fingerprint biometric data. The maximum is 36,500 minutes.

Default: 10 minutes

User Registration Password Length

The length of a user registration password, in bytes. This is an automatically generated password that is used internally by Entrust IdentityGuard, therefore, there are no usability concerns to offset the increased security associated with a long password length.

Default: 16 bytes

Maximum Number of Federations per User

The maximum number of SAML service providers with which the IdentityGuard users in this group can federate.

Default: 10

Maximum Number of User Preferences

An example of a user preference is a saved report query.

By default, each administrator can store up to 50 user preferences. If you set this policy to zero, the user cannot have any user preferences.

Default: 50

Maximum Number of Characters in a User Preference

This policy defines the size limit of each search criteria preference, in characters, stored by Entrust IdentityGuard for reporting.

Default: 5000
