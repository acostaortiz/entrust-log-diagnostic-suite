IdentityGuard Server 11.0 Administration Guide

Machine secret policies

These policies set machine authentication rules that apply to users who access your site.

Machine secrets are used as part of risk-based authentication.

Total Maximum Size in Kilobytes (Machine Secret)

Sets the maximum storage space (in KB) for each user’s machine secrets (which could include sequence nonce, machine nonce, application data and device fingerprint). A setting of 0 disables storage of machine secrets, which is equivalent to turning off machine authentication.

Default: 10

Maximum Number Of Machine Secrets

Sets the maximum number of machine secrets to store for a user. A setting of 0 disables the storage of machine secrets, which is equivalent to turning off machine authentication.

When Entrust IdentityGuard needs to store a new machine secret but the maximum allowable already exist, it first removes the secret with the longest period of disuse and then adds the new secret.

Default: 10

Sequence Nonce Required

Sets whether Entrust IdentityGuard requires that a sequence nonce be part of the machine secret used for authentication. (See Configuring a good machine secret.)

Default: No

Machine Nonce Required

Sets whether Entrust IdentityGuard requires that a machine nonce be part of the machine secret used for authentication. Wherever possible, you should include a machine nonce, as it provides the highest level of security.

Set this policy to No only if the machine secret cannot be stored on the client computer. (See Configuring a good machine secret.) Machine secrets cannot be stored on the client computer if the users have disallowed cookies or flash.

When this policy attribute is No, consider the following:

–  the setting for Application Data Elements Required must be 1 or more—the more the better because application data is all that is available to create the fingerprint

–  the setting for Bad Application Data Elements Allowed must be 0 because all application data is needed to create a secure fingerprint

Default: Yes

Application Data Elements Required

Sets how many application data elements (if any) your client application must provide for machine authentication. A setting of 0 means no application data is required.

Default: 0

Bad Application Data Elements Allowed

Determines how many invalid application data elements Entrust IdentityGuard should tolerate from your application. For example, if your client application passes five data elements but you set this attribute to 2, Entrust IdentityGuard tolerates up to two invalid data elements.

Default: 0

Machine Secret Lifetime

Sets the lifetime, in hours, of an unused machine secret. A setting of 0 means the machine secret has an infinite lifetime. There is a limit of 100 years, which equals 876,000 hours.

Default: Unlimited

Device Fingerprint Required

Sets whether Entrust IdentityGuard requires that a device fingerprint be part of the machine secret used for authentication.

Default: No

Device Fingerprint Attributes

Choose an option from the drop-down list to configure the properties of user devices (Web browser or selected mobile devices) that you want to include in machine authentication and risk-based authentication. The attributes help to determine whether a user is authenticating from the same device used for a previous successful machine authentication.

See the following topics for details about the attributes:

–  Device fingerprint attributes Android

–  Device fingerprint attributes iOS

–  Device fingerprint attributes Web

–  Characteristics of device fingerprint attributes

Normal Security Device Fingerprint Risk Limit

Sets the maximum total number of non-matching risk points allowed before a user's machine authentication attempt fails. This setting is used if your client application calls for authentication with the Normal security level.

A zero value means that no risk is allowed and a device fingerprint must exactly match the one used for the last successful authentication.

Note: This value cannot be lower than the value of Enhanced Security Device Fingerprint Risk Limit.

Default: no value (zero)

Enhanced Security Device Fingerprint Risk Limit

Sets the maximum total number of non-matching risk points allowed before a user's machine authentication attempt fails. This setting is used if your client application calls for authentication with the Enhanced security level.

A zero value means that no risk is allowed and a device fingerprint must exactly match the one used for the last successful authentication.

Note: This value cannot be higher than the value of Normal Security Device Fingerprint Risk Limit.

Default:no value (zero)

Count Failed Machine Authentication as Login Failure

Sets whether a failed machine authentication increments the user’s failed authentication lockout count. Yes means that failed machine authentications increment the lockout count. No means that a failed machine authentication does not increment the lockout count.

Default: No
