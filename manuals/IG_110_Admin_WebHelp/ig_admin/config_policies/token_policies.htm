IdentityGuard Server 11.0 Administration Guide

Token policies

The token policies define how tokens are handled in the IdentityGuard system.

Unassign Hardware Tokens When User is Deleted

When you remove users, this parameter determines whether their tokens are deleted or unassigned. If you delete a token, it can never be used again with Entrust IdentityGuard.

Yes indicates their tokens are unassigned before the users are deleted, and No means their tokens are deleted with the user.

Default: Yes

Move Hardware Tokens to User’s Group During Assignment

When tokens are loaded, they are assigned to a particular group. When assigning the tokens to users, the token’s group and the user’s group may not match.

Select this policy to automatically move tokens from their current group to the group of the user during assignment.

When this policy is set to No, a mismatch of the user group and the token group results in an error message.

Default: No

Reset Token When Token is Created or Activated

Specifies whether a token will be reset on first authentication after the token is assigned to a user (for hardware tokens) or when it is created and activated (for soft tokens). This policy resets the time for time-based tokens, the event counter (for event-based tokens), or both (for tokens that are time- and event-based.

Default: No

Maximum Number of Token Sets per User

Specifies the number of token sets a user is allowed. A token set is a name given to the set of tokens that move through their state transitions together. For example, a single user might have one token set called "BlackBerry" and another token set called "Hardware token".

For details on token sets, see Token set overview (using multiple tokens).

Default: 1

Disable Challenge Retention

This setting applies only to challenge-response tokens.

Enable this setting if you want to replace the token challenge each time a challenge is requested. Users who answer a challenge incorrectly will have a new challenge presented to them for the next attempt.

Deselect it if you want to retain the challenge for the duration of the Token Challenge Lifetime. Users who answer a challenge incorrectly will have the same challenge presented to them for all subsequent attempts until they are locked out or until the challenge lifetime is exceeded. After the challenge lifetime is exceeded, a new challenge is presented.

Default: No

Token Challenge Lifetime

This setting applies only to challenge-response tokens.

Set it to Unlimited to have the token challenge last an unlimited amount of time.

Set it to a number of seconds to limit the lifetime. If it is not answered in the lifetime, a new challenge is generated.

Default: Unlimited

Update Lockout for Replaced Challenge

This setting applies only to challenge-response tokens.

When set to Yes, the lockout count is increased when a token challenge is replaced because:

–  a user does not answer a token challenge in the allotted time (as defined by the Token Challenge Lifetime setting) causing a new challenge to be requested by the client application

–  a user restarts the client application without answering the token challenge, causing a new challenge to be requested by the client application

When set to No, the lockout count is not increased in the above-mentioned scenarios.

Note: The lockout count is always increased when a user enters an incorrect challenge response, regardless of how you configure this setting.

Token Transaction Lifetime

This setting applies only to soft tokens licensed to use transaction verification.

Specifies the amount of time, in seconds, that a transaction is available for a response (Confirm, Cancel, or Concern) from the user.

If the user does not respond in the lifetime, the transaction expires and any subsequent attempt to respond to the transaction will fail.

Default: 300 seconds

Perform Transaction Delivery to Soft Tokens

Specifies whether transaction details are sent to the Entrust IdentityGuard Mobile ST app. For details on transactions, see Soft token transaction verification overview.

Default: False

Soft Token OTP Length

Specifies the length for the OTP.

The available values are 6 or 8.

Default: 8

Soft Token PIN Required

Specifies whether a PIN is mandatory or optional for PIN-enabled soft tokens. If mandatory, users must enter a PIN to unlock the application that contains soft tokens—either the Entrust IdentityGuard Mobile ST app or Entrust IdentityGuard Desktop Soft Token. If optional, users can optionally set a PIN.

Default: Yes (a PIN is mandatory for PIN-enabled soft tokens)

Mobile Soft Token Allow Unsecured Device

This setting applies only to mobile soft tokens on iOS or Android devices.

Specifies whether soft token identities can be created and used on unsecured devices. A device is considered to be unsecured if it has been rooted (Android) or jailbroken (iOS).

For more information, see Enable use of soft tokens on an unsecured mobile device.

Default: No

Mobile Soft Token Trusted Execution Environment

This policy applies only to mobile soft tokens on Samsung mobile devices with the Samsung KNOX Trusted Execution Environment (TEE) enabled. When this policy is enabled, the mobile soft token is stored within the Trusted Execution Environment on the device. For more information, see Enable storage of soft tokens in TEE.

Use of this feature requires license for each soft token stored in the TEE.

Options are:

–  Required — A supported  TEE must be used to store the soft token seed. If the mobile device does not have a supported TEE, the soft token cannot be activated on such a device.

–  Allowed — If a supported TEE is present on the device, it should be used to store the soft token seed. If the device does not have a supported TEE, then the seed can be stored in a protected file elsewhere on the device.

Note: The number of soft tokens that can be stored in the TEE could be limited. If the limited is exceeded, soft tokens are stored outside the TEE.

–  Not Allowed — The seed must be stored in protected file on the device (not in the TEE), even if the device has a supported TEE.

Default: Not allowed

Token Activation Lifetime

This policy applies to mobile soft tokens. Controls how long, in seconds, a token activation code is valid after it is created. A value of 0 means that the activation code is valid indefinitely. If a user attempts to complete activation of a token after the activation code has expired, the activation will fail. The user must contact the administrator to regenerate the code. For more information, see To create and activate a soft token using a QR code.

Default: Unlimited

Token Activation QR Code Password Length

For soft token vendors that use QR codes for activation (for example, Entrust soft tokens used with the Entrust IdentityGuard Mobile Soft Token app), a password is created to protect the contents of the QR code. This policy specifies the length of that password. It can have a value between 4 and 100.

Default: 8
