IdentityGuard Server 11.0 Administration Guide

Cell replacements

Along with the cell alphabet (see Cell alphabet), the grid card policy also includes a list of cell replacements. (The One-Time Password and Temporary PIN policies also allow you to define cell replacements.) Cell replacements allow Entrust IdentityGuard to “forgive” a user for typing a wrong character in a challenge if the user misread the correct character.

Note: If you are using Entrust IdentityGuard with Radius, cell replacements are supported only if you are using Password Authentication Protocol (PAP).

For example, say Entrust IdentityGuard generates a challenge, and one of the characters is the number 8. If the user confuses the number 8 with the letter B, the user cannot correctly answer the challenge unless the policy includes a cell replacement to allow the user to type B instead of 8.

A cell replacement consists of two characters and looks something like this: B–>8. The second character of a cell replacement is the character that a user can misread, and it must be a character that is in the cell alphabet (for example, 8). The first character of a cell replacement is the character that a user can type instead of the second character (for example, B). So if a cell replacement is B–>8, a user can type the letter B instead of the number 8 and still correctly answer a challenge.

By default, the list of cell replacements includes character maps for all lowercase and equivalent uppercase letters in the cell alphabet (such as c–>C and m–>M). The list of cell replacements also includes cell replacements for the most commonly confused characters (such as B–>8 and O–>0).

●       To modify the grid cell replacements, see Configuring grid card design and behavior policies.

●       To modify the temporary PIN cell replacements, see Configuring temporary PIN policies.

●       To modify the one-time password cell replacements, see Setting policies for out-of-band OTPs.
