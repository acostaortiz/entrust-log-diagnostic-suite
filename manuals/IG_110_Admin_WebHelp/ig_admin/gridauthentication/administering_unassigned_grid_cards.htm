Administering unassigned grid cards

After you create (or receive) preproduced grid cards but before you assign them to users, you can:

●       modify group information

●       export the grid card information to a file

●       delete unneeded grid cards

After you create a preproduced grid card, you can modify its group association and other details. If you move a grid card to another group, the challenges generated once the grid card is assigned to a user uses the policies of the new group. Ensure that the grid card’s policies match those of its new group (for example, it has the same number of characters per cell and the same numbers of rows and columns).

Attention: If you are moving all of the grid cards from one group to another group, you must change the definition of the new group to include the repository containing the grid cards you are moving. For details, see the card move command in the Entrust IdentityGuard Master User Shell Reference.

Delete an unassigned grid card if it is no longer required. A deleted grid card is removed from the Entrust IdentityGuard server. You can only retrieve deleted grid cards by restoring your data repository from backup.

The location of the unassigned grid cards depends on your repository:

●       If you are using a database, Entrust IdentityGuard stores the cards in a database table.

●       If you are using an LDAP repository, Entrust IdentityGuard creates a file-based repository for the unassigned grid cards on the server. If you have set up multiple Entrust IdentityGuard servers, you must load the data file on the primary server.

For information about grid card repositories, see Setting up user, grid card, and token repositories.

To complete the following procedures, administrators must have the correct role permissions. See Card permissions for a list of all role permissions relating to grids.
