IdentityGuard Server 11.0 Administration Guide

Grid card and token state overview

Grid cards, tokens, and soft tokens follow the same state progression and rules, so this section applies to all these authenticators.

These Entrust IdentityGuard authenticators begin in the Pending or Hold-pending state, and progress to the Current state when they are first used for authentication.

After a user has been assigned a grid card or token, it can have any one of the following states at any given time.

Grid card and token states

Pending

Pending means that the grid card or token has not yet been used for authentication.

Hold-pending

Hold-pending means the grid card or token cannot be used to log in until it is moved into the Pending or Current state.

The Hold-pending state is typically used for situations where your application wants to verify the user before letting them log in with their grid card or token. For example, a Web registration application might verify the user’s identity and then use the Administration API to change the grid card’s state from Hold-pending to Pending. When the grid is in the Pending state, the user can begin authenticating.

Current

Current means the grid card or token is currently in use.

Hold

Hold means the grid card or token cannot be used to log in.

It might have been put on hold by the administrator because it was reported lost or because the user requested that it be placed on hold. Or, it might switch to the Hold state automatically if either the Least-used or Challenge Count Replacement threshold is met. For more information see Card policies.

Canceled

Canceled means the grid card or token can no longer be used to authenticate.

Canceled grids and tokens are shown in the user account, and can never be used again. They cannot be changed to any other state, and they can never be assigned to any user again. To avoid seeing canceled grids or tokens in the Administration interface, you can delete them.

 

Other terminology related to states

Active

An active grid card or token is one that is in the Current or Pending state.

Deleted

A deleted grid card or token is one that an administrator has deleted from the system. Deletion removes the grid card or token  completely from Entrust IdentityGuard. It cannot be re-assigned.

Expired

An expired grid card is one whose expiry date has passed.

When an authenticator expires, it is not automatically placed in the Canceled state; an administrator must cancel it manually.

Superceded

A superseded grid card or token is one in the Current or Hold state whose owner has been issued a newer grid card or token in the Pending state. As soon as the newer, pending grid card or token  is used for authentication, it becomes current and the superseded authenticator is canceled.

A user can continue to use a superseded grid card or token for a period of days set by policy. This period takes effect the moment a grid card or token is superseded. For more information see Card policies.

Note: Tokens and soft tokens do not have a superseded date.

Unassigned

Though this is not considered a state, the administrator can unassign grid cards or tokens. (Soft tokens cannot be unassigned; they can only be deleted.) Unassigning a grid card or token from a user moves it back into the preproduced pool of grid cards or into the list of unassigned tokens. An unassigned grid card or token can be assigned to the same user again or to another user.

Valid

A valid grid card or token is one that has not yet expired or been superseded.
