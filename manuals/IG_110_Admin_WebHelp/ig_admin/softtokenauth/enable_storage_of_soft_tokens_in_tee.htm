IdentityGuard Server 11.0 Administration Guide

Enable activation and use of soft tokens in a Trusted Execution Environment (TEE)

A trusted execution environment (TEE) is a hardware-based container that is isolated from the main mobile operating system. This hardware isolation helps to prevent leaking sensitive data, such as the token seed, because that data never leaves the TEE. In addition, by performing cryptographic operations within the TEE, mobile soft tokens can leverage the underlying FIPS 140-2 Level 1 certified cryptographic algorithms, providing a higher level of assurance.

Available on some mobile devices, the TEE can be enabled by a service provider or IT department. When available and enabled, the Entrust IdentityGuard Mobile Soft Token app can make use of the TEE for automatic online soft token activation and transaction verification.

Currently, this feature supports only the Samsung KNOX TEE and the Samsung OTP Framework within it, available on some Samsung mobile devices. Review the technical specifications of devices in your user population to determine if you can make use of this feature.

Each soft token stored in a TEE consumes one TEE Storage for Soft Tokens license.

There is no change to the user procedures when using the Entrust IdentityGuard Mobile Soft Token with this feature enabled, except that online activation is the only activation method that stores the token seed in the TEE.

A maximum of 6 soft tokens that can be stored in the Samsung KNOX TEE.

Note: This feature works with Entrust IdentityGuard Mobile Soft Token app version 3.1 or later.

To enable storage of soft token in a TEE

1.      Log in to the Entrust IdentityGuard Administration interface as the administrator.

On the Windows computer where Entrust IdentityGuard is installed

●       Select Start > All Programs > Entrust > IdentityGuard > Administration Interface.

On UNIX or from a remote client

●       Enter the URL of your Administration interface web application in a Web browser. It has this form:

https://<hostname>:<port>/IdentityGuardAdmin

Where:

<hostname> is the host name you selected during configuration

<port> is the administration port you selected during configuration

If you cannot find the correct URL, see Locate your Administration interface URL.

Note: Log in as a user with a role that includes these permissions: policyGet, and one of policyCreate, or policySet. See Policy permissions for details.

2.      Select Policies on the menu bar.

A list of all policies appears on the List Policies tab.

3.      Click the name of the policy for which you want to enable this feature.

The View Policy page for the selected policy appears.

4.      From the Policy Category drop-down list, select Token.

The token policies appear.

5.      Click Edit Policy.

An editable version of the settings appears.

6.      From the drop-down list, select one of the options for the following policy. Click + to see the options.

Mobile Soft Token Trusted Execution Environment

This policy applies only to mobile soft tokens on Samsung mobile devices with the Samsung KNOX Trusted Execution Environment (TEE) enabled. When this policy is enabled, the mobile soft token is stored within the Trusted Execution Environment on the device. For more information, see Enable storage of soft tokens in TEE.

Use of this feature requires license for each soft token stored in the TEE.

Options are:

–  Required — A supported  TEE must be used to store the soft token seed. If the mobile device does not have a supported TEE, the soft token cannot be activated on such a device.

–  Allowed — If a supported TEE is present on the device, it should be used to store the soft token seed. If the device does not have a supported TEE, then the seed can be stored in a protected file elsewhere on the device.

Note: The number of soft tokens that can be stored in the TEE could be limited. If the limited is exceeded, soft tokens are stored outside the TEE.

–  Not Allowed — The seed must be stored in protected file on the device (not in the TEE), even if the device has a supported TEE.

Default: Not allowed

7.      Click Save Changes.

Mobile soft tokens activated after this configuration use this new policy. To have the new policy apply to existing mobile soft tokens, users must delete the old soft tokens and recreate them.

The View Policy page reappears.
