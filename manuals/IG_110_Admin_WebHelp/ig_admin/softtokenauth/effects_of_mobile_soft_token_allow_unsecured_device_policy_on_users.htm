Effects of enabling the Mobile Soft Token Allow Unsecured Device policy

Read this topic if you are considering allowing users to have mobile soft tokens on mobile devices that have been rooted or jailbroken.

Users of secure devices will see no changes in their use of the app.

A user who created soft tokens when a mobile device was secure, but later unsecured the device, could end up with soft tokens that are unusable. The user should restore the device to a secure state or delete these soft tokens from the mobile device. The soft tokens should also be deleted from Entrust IdentityGuard. A user can do this through Self-Service or an administration can delete them using the Administrator interface.

Specific behavior is described in the following tables.

Soft tokens created on a secure device that is subsequently rooted or jailbroken

Mobile Soft Token Allow Unsecured Device=No (default)

User action

What user will observe

App startup

Error message: One or more identities have been disabled because they cannot be used on an unsecured device. (If only one identity is governed by the policy, the identity is named in the message.)

A circle with a diagonal slash appears next to the identity.

Attempt to use the disabled soft token or set it as the default identity.

Error message:This identity cannot be used on an unsecured device.

Attempt to get security code for default identity

If the unusable identity was the default identity, the app displays the Identity list, forcing the user to select a valid identity to use, if one is available.

An unusable identity cannot be selected as the default identity.

Any type of activation

Error message: This identity cannot be activated on an unsecured device.

Manual activation

Error message: Manual activation is not supported on an unsecured device.
