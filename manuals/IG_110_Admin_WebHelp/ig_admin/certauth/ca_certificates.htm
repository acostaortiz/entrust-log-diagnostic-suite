IdentityGuard Server 11.0 Administration Guide

CA certificates

The information associated with the CA certificate is used to perform certificate validation on any user certificate issued by that CA certificate. A CA certificate can be either a root CA certificate or a subordinate CA certificate. In the case of a subordinate CA, Entrust IdentityGuard also stores the chain of certificates from the subordinate CA to its root CA.

The following list describes the information that Entrust IdentityGuard stores for each CA certificate. Click a list item to read the description for each item.

Name

Specifies the name of the CA certificate.

The name of a CA certificate must be case-insensitive unique across all CA certificates. The name must be between 1 and 255 characters (with leading and trailing white space removed) and can not contain the / character.

State

Specifies the state of the CA certificate, either ACTIVE or INACTIVE.

The CA certificate must be in the active state for certificate authentication to succeed.

Changing the CA certificate to the inactive state allows you to invalidate all user certificates and prevent authentication without having to delete the CA certificate from Entrust IdentityGuard.

Issuer DN

Specifies the issuer DN of the CA certificate.

The issuerDN is stored as a string.

The issuer DN and serial number of a CA certificate must be unique across all CA certificates. A given CA certificate can only be imported into Entrust IdentityGuard once.

Subject DN

Specifies the subject DN of the CA certificate.

The subjectDN is stored as a string.

Serial number

Specifies the serial number of the CA certificate.

The serial number is stored as a string.

The issuer DN and serial number of a CA certificate must be unique across all CA certificates. A given CA certificate can only be imported into Entrust IdentityGuard once.

Issue date

The date the CA certificate was issued.

Expiry date

The date the CA certificate expires.

Certificate

The full CA certificate.

Certificate chain

The full certificate chain is stored with the certificate.

Comment

This is a comment describing the certificate.

You enter this comment when you load the CA certificate.

 

The following attributes are used for certificate revocation checking:

LDAPUseURLCDP

Boolean

If set to true, CRLs are retrieved by following the URLs specified in the certificate’s Certificate Distribution Point (CDP) extension.

When the LDAP URL is specified, UseURLCDP is always true.

LDAP URL

Specifies the URL of an LDAP server from which CRLs can be retrieved.

LDAP UserDN

If specified, LDAP UserDN is used to authenticate the connection to the LDAP URL. If it is not specified, anonymous authentication is used.

If LDAP UserDN and LDAP UserPassword are specified, the LDAP URL must be specified.

LDAP UserPassword

Specifies the LDAP user password.

If specified, LDAP UserPassword is used to authenticate the connection to the LDAP URL.

If LDAP UserDN and LDAP UserPassword are specified, the LDAP URL must be specified.

OCSP URL

Specifies the URL for accessing the OCSP (Online Certificate Status Protocol) revocation checking.

OCSP UseAIA

Specifies whether to use the AIA attribute to locate the OCSP server.

Boolean

If set to true, the OCSP entry in the certificate Authority Information Access (AIA) extension will be used to locate OCSP server from which to retrieve certificate revocation information.

 

When registering a CA certificate, all of the CAs in the certificate chain must have the keySigning key usage bit set. The certificates must also be in their validity period. Subordinate CAs must contain the basicConstraints=true extension.

When user certificates are assigned, they link to a registered CA certificate if it was issued by one of the registered CA certificates. A CA certificate cannot be deleted if any user certificates issued by that CA certificate exist.
