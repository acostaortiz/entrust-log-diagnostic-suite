Risk-based authentication overview

There are situations in which, for security reasons, you want to present users with an extra authentication challenge or reject the user authentication attempt immediately. However, when users pose no risk, it is ideal to authenticate them automatically. Risk-based authentication is a way to handle all of these scenarios.

To take advantage of all the features of risk-based authentication, you can use any one of the following types of data, any combination of the types, or all of the types:

●       IP/Geolocation data (See About IP/Geolocation.)

●       certificate data (See About certificate authentication.)

●       device data (See About machine authentication.)

In addition, with Entrust IdentityGuard, you can configure your application to provide normal or enhanced risk-assessment levels based on the sensitivity of the information a user wants to access or the potential for fraud that a transaction poses. (See About normal and enhanced levels.

Complete the procedures in this section to configure all or some of the types of risk-based authentication you plan to use.

After you configure Entrust IdentityGuard policies and properties for risk-based authentication, configure your client application to use the Entrust IdentityGuard features. For guidance, see the Entrust IdentityGuard Programming Guide.
