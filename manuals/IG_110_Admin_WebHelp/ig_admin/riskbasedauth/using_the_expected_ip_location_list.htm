IdentityGuard Server 11.0 Administration Guide

Using the expected IP location list

The expected location list contains IP locations that you expect users to log in from. Entrust IdentityGuard provides two expected location lists:

●       One is set through policy and applies to all users in a group.

●       One is a user’s personal expected location list, which overrides the group list.

Users do not have an expected location list unless an administrator specifically assigns one. Once a personal expected location list exists for a user, Entrust IdentityGuard always checks the personal list (not the group list), when the user logs in.

When a user logs in from a location on the expected location list (the group list or user list), all of the other tests are skipped except for the velocity check. For details on how the expected location list affects other tests, see Preliminary checks and how they affect subsequent tests.

The expected location list can include public and private locations.

Each entry for a public address in an expected location list can include one or more of:

●       country

●       region

●       city

●       ISP name

●       IP address

You do not need all of these for a useful comparison. If any of these fields are missing, comparisons are done just with the information provided.

For example, if the expected location list contains an entry with just the country, it matches any location within that country. If the list contains an entry with the country and region, it matches any location within that region of the country.
