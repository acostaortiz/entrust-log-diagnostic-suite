Configuring security risk policies

Use the risk tests to determine how to deal with users who are trying to access your system. Depending on the results, you can:

●       let a user in without further authentication if certain tests pass and none fail

●       present a second-factor authentication challenge if one or more tests fail

●       present a second-factor authentication challenge even if all tests pass

●       reject the user authentication attempt outright if certain tests fail

For example, your normal security policy might do the following:

●       reject the user if the IP blacklist test, the country blacklist test, or certificate validation fails

●       issue an authentication challenge if any other tests fail

●       admit the user without a challenge if no tests fail and machine or certificate authentication passes

By comparison, your enhanced security policy might do the following:

●       reject the user if any one of the location, velocity, IP blacklist, or country blacklist tests fail

●       issue a challenge if no tests fail and machine authentication passes, or if no tests fail and certificate authentication passes

The policy you set for the enhanced security level must provide equal or stronger security than the normal level policy. To ensure this, any rejection at the normal level also causes a rejection at the enhanced level. Conversely, a successful authentication at the enhanced level means that authentication at the normal level will also be successful.

By default, a user's authentication attempt is rejected at the normal security level if a user fails the IP blacklist, country blacklist, or certificate validation test. By default, a user's authentication attempt is rejected at the enhanced security level if any of the IP blacklist, country blacklist, velocity, or certificate validation tests fails.

An administrator with the applicable permissions sets the pass (authenticate) and reject criteria in the Policies pages of the Administration interface. For any results that do not meet either pass or reject criteria, the user is challenged. See Configuring risk-based authentication policies.

Any time a user is authenticated, challenged, or rejected, Entrust IdentityGuard writes a message to the audit log. You can set properties to control everything that goes to the audit log. See the tables in Audited event reference for details.
