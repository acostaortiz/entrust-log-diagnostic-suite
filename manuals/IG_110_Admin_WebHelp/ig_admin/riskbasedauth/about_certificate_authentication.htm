About certificate authentication

Certificate authentication uses certificates on the user’s computer to authenticate the user automatically.

There are two ways your application can implement certificate authentication:

●       challenge and response certificate authentication, in which the application looks for a certificate assigned to the user in Entrust IdentityGuard

●       risk-based certificate authentication, in which the certificates are automatically validated as part of risk-based authentication

This section discusses how to set up certificate authentication used with risk-based authentication. For information about challenge-response certificate authentication, see Certificate authentication.

You can use certificate authentication with IP/Geolocation and machine authentication or on its own, depending on the capabilities of the user application.

To use certificate authentication, you must set up the application to supply the user’s certificate. Two checks are performed to authenticate users with certificates:

●       Confirm that the certificate is registered to this user.

●       Confirm that the certificate is valid (not expired, revoked or inactive)

The Entrust IdentityGuard policies define whether to authenticate, reject, or challenge the user based on those checks. By default, the user is rejected if certificate authentication fails.
