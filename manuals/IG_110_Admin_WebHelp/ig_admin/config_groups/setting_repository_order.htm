IdentityGuard Server 11.0 Administration Guide

Set repository order

You can change the order of user repositories assigned to a group. This order can become important when you or another administrator creates users later.

When you create users, you also select a group. If the group has multiple repositories, you can select the repository in which to store the users’ information from the Repository list. This list also includes the option First Usable Repository.

The First Usable Repository option is designed chiefly for environments where multiple LDAP repositories are assigned to groups. When creating new Entrust IdentityGuard users, this option is useful for administrators who do not know in which LDAP repository the corresponding LDAP user record exists. If you select the First Usable Repository option, Entrust IdentityGuard searches each LDAP repository, in the order they were set on the Create Group page, until it finds a matching user.

If you have just database repositories and you select the First Usable Repository option, Entrust IdentityGuard creates the user record in the first database in the list.

The effect of the First Usable Repository option becomes more complicated when you have a mixture of LDAP and database repositories. If Entrust IdentityGuard cannot find the user in the first LDAP repositories in the list, it creates the user record in the first database in the list.

For example, assume you create a new user named User1 and select the First Usable Repository option. And assume the group’s repository list looks like this:

●       LDAP repository 1

●       LDAP repository 2

●       Database repository 1

●       LDAP repository 3

Entrust IdentityGuard does the following:

●       It searches LDAP repository 1 looking for User1.

●       If not found there, Entrust IdentityGuard searches LDAP repository 2 looking for User1.

●       If not found there, Entrust IdentityGuard looks no further and creates User1 in Database repository 1, even if User1 exists in LDAP repository 3.
