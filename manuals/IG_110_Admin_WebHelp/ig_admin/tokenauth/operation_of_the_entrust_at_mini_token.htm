IdentityGuard Server 11.0 Administration Guide

Operation of the Entrust AT Mini Token

An AT token is often referred to as a hybrid token. This is because the token dynamic password is generated using a combination of two elements, an event value and a time value, as shown below:

Event value (E) + Time Value (T) = Token Password

Or, to shorten it:

E + T = TP

Note: There is also a random data value added to each token password calculation: Event + Time + Random data = token password. For simplicity, and because it does not play a role in authentication drift, the random component is not included in this discussion.

A new event value is generated each time the user presses the token button. A new time value is generated automatically by the token every 128 seconds. The token password displayed to the user is a combination of the event value and the time value.

If the user presses the token button five times within the 128 second time window the TP calculation is:

E1 + T1 = TP1

E2 + T1 = TP2

E3 + T1 = TP3

E4 + T1 = TP4

E5 + T1 = TP5

If the user presses the button a sixth time after the 128 second time window has closed, and a new time value has been generated, the resulting token password calculation is:

E6 + T2 = TP6

Why does the token password still work for authentication even if the token button is pressed a number of times between logins?

The server is expecting a certain TP based on the last TP the user entered. This expected number is calculated as:

TP = (last event calculation + 1) + (current time calculation)

For example, if the user authenticated with E6 + T2 = TP6 at the last login, the Entrust IdentityGuard server expects E6+1 + T(current time) = TP7.

Two things can cause the user’s token password to be different than expected.

●       The user presses the token button multiple times between logins, changing the expected event value.

Note: To avoid the generation of token passwords through an inadvertent press of the button, the token button is designed so that it must be held down for approximately two seconds to generate a new TP.

●       The time value generated by the token may drift from the corresponding time value generated by the Entrust IdentityGuard server if there is a long period of time between authentications. (This is very uncommon.)

To account for event or time drift, the IdentityGuard server has a preset drift window of 10 TP values. A drift window is the variance from the expected TP value that the Entrust IdentityGuard server allows. A drift window of 10 means that the Entrust IdentityGuard server will accept a TP that is a combination of the next 10 expected event values plus the next 10 expected time values.

Note: The Entrust IdentityGuard administrator can lengthen the event value drift window, but security is reduced by doing this.

Each time a user authenticates successfully, the next anticipated TP and drift window are automatically reset to begin at this successfully authenticated TP.

If someone presses the button and steals token passwords, how long are they valid?

The length of time token passwords are valid is governed by the event value drift window and the time value drift window. Assuming that the initial drift window settings of 10 are maintained, the TP values will be accepted by the Entrust IdentityGuard server until either of the following conditions occur:

●       The OTP contains an event value that is 11 or more beyond the last login.

●       21.3 minutes has elapsed since the token was pressed to create the value.

The Entrust IdentityGuard server is expecting a TP that contains an event value generated within 10 presses of the token button since the last login. A TP generated after 10 presses (11 and up) contains an event value in the TP calculation that is outside the drift window, so it is not accepted.

The Entrust IdentityGuard server is expecting a TP that contains a time value that is within 10 time values of the current Entrust IdentityGuard server clock calculation. A new time value calculation is generated every 128 seconds. Therefore, assuming that the user presses the button during the first second of a new time value window of 128 seconds, the TP generated will be valid for a maximum period of 21.3 minutes. (128 seconds x 10) = 21.3 minutes
