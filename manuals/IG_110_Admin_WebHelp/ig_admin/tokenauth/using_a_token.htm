IdentityGuard Server 11.0 Administration Guide

Using a token

The user’s token device generates the dynamic token password (a number) that a user enters at the challenge generated by your application. Entrust IdentityGuard checks if the dynamic token password is valid and, if it is, authenticates the user.

Note: Each token password can be used just once. A token device generates a new dynamic password for every authentication challenge. 

For response-only tokens, the process is:

●       Entrust IdentityGuard asks for a generated token response.

●       For some hardware tokens, the user may have to enter a PIN into the token to unlock it.

●       The user presses the button on the token device.

●       The token generates a token password.

●       The user enters that number in the response field.

For challenge-response tokens, the process is:

●       Entrust IdentityGuard issues a challenge number and asks for a generated token response.

●       The user presses the button on the token device.

●       The token device may ask for a PIN to unlock the token. If so, the user enters the PIN.

●       The user enters the challenge number issued by Entrust IdentityGuard into the token.

●       The token device generates a token password.

●       The user enters that number in the response field.

In Entrust IdentityGuard, when authenticating with a token, a personal verification number (PVN) may also be required as part of the token response. A PVN is a number the user chooses. (See Personal verification number overview.) A PVN consists of a string of numeric characters that users must enter into the application with their dynamic token password when challenged by Entrust IdentityGuard. A PVN is available for use with several authentication methods, including tokens.
