IdentityGuard Server 11.0 Administration Guide

Create a role

Entrust IdentityGuard provides several general and several specialized built-in roles. To create a new role, you must have the

●       superuser role, or

●       a role that includes the roleCreate permission and the All policies, All groups, and All roles options enabled.

An administrator must be able to view the role being created. A new role is not yet in the administrator's role list. The All roles option makes it possible to view all roles, including those not yet created.

You may need to create roles in your Entrust IdentityGuard system so that you can delegate different tasks to different administrators. For example, you can create a help desk role that allows your help desk administrators to reset user shared secrets, unlock accounts, and assign cards using the Administration interface. To do this, you need a role that covers users in all user groups and that has at least the following permissions (and their dependencies): userSetSecret, userCardAssign, and userUnlock, along with the associated Get permissions.

When you create a new role, you can copy an existing role, give it a new name and adjust its scope and privileges. As an example, for the help desk role, start with the useradmin role, rename it and select the All groups option.

When creating a role, consider the following guidelines:

●       Role names must be unique.

●       Roles must have a list of permissions and permission dependencies.

●       You can create roles one at a time in the Administration interface.

●       You can create roles in the Master user shell by importing role information from a file. (Use the role create command. For detailed syntax, see the Entrust IdentityGuard Master User Shell Reference.)

To create a role in the Administration interface

1.      Log in to the Entrust IdentityGuard Administration interface as the administrator.

On the Windows computer where Entrust IdentityGuard is installed

●       Select Start > All Programs > Entrust > IdentityGuard > Administration Interface.

On UNIX or from a remote client

●       Enter the URL of your Administration interface web application in a Web browser. It has this form:

https://<hostname>:<port>/IdentityGuardAdmin

Where:

<hostname> is the host name you selected during configuration

<port> is the administration port you selected during configuration

If you cannot find the correct URL, see Locate your Administration interface URL.

You must log in as an administrator with the following permissions and options enabled:

●       roleCreate

●       All policies option

●       All groups option

●       All roles option

The user must have access to all policies, groups, and roles in order to modify roles.

2.      Click Roles on the menu bar.

3.      Click the Create Role tab.

4.      Enter a name for the new role in the Role Name field.

5.      From the Initialize from Role drop-down list, use the default Don’t Initialize From An Existing Role, or pick an existing role to copy settings from. If you choose Don’t Initialize From An Existing Role, the new role has no permissions or abilities until you modify the role to assign them.

6.      Optional. Enter comments that explain the purpose of the role.

7.      Click Create Role.

The View Role page appears and lists all role settings. Modify the settings to meet your requirements. (See Modify a role.)
