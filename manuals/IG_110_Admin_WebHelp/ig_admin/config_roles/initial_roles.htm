IdentityGuard Server 11.0 Administration Guide

Built-in roles

The Entrust IdentityGuard installation includes several default roles. These initial roles are built-in system roles and cannot be modified or deleted. You can copy and modify these roles to make variations.

Superuser role

This role is for the most privileged administrator, with every option, feature and permission enabled.

Permissions for the superuser role:

–  All permissions

–  All policies

–  All groups

–  All roles

Useradmin role

This role allows administration of users. It also includes permissions related to preproduced cards and unassigned tokens. It has an empty role list, an empty policy list, and the Administrator's own group option in the group list. The useradmin role does not have permission to manage roles or policies. It cannot grant administrator permissions to a user.

Auditor role

A user with the auditor role can view all data in the system, but not modify it.

Delegationadmin role

This role used to configure single sign-on to the Administration interface using SAML or smart credential authentication. For more information, see Create a delegation administrator.

Transactionadmin role

An administrator with this role can view and set token and smart credential parameters.

The transactionadmin role is used for the transaction administrator account of the Entrust IdentityGuard Self-Service Module. It includes permissions required to support the actions performed by the self-service transaction component, including biometric enrollment, soft token and smart credential activation, soft token transaction verification and smart credential identity assured operations.

Federationadmin role

The federationadmin role is used by the administrative account for Entrust IdentityGuard Federation Module. It allows the administrator to perform operations on user federation-related information and also to fetch information about the end user authenticating using Federation Module.

Smart credential enroller role

The Smart Credential Enroller role is to be assigned to an administrator who enrolls a user for a smart credential using either the Administration interface or Entrust IdentityGuard Enrollment Module. It allows the administrator to perform operations including creating the user, creating the user smart credential, and setting enrollment values for the smart credential. It does not allow the administrator to issue the smart credential.

Smart credential approver role

An administrator with this role can reject, approve, or edit a previously enrolled smart credential (edit is not set by default). The smart credential definition specifies whether approval for each enrollment is necessary.

The approver can approve the smart credential but can not enroll or issue the smart credential.

Smart credential issuer role

An administrator with this role can print and encode smart credentials after users have been enrolled and their smart credentials are approved and ready to be issued.

Smart credential print module role

This role is assigned to the administrative account used by Entrust IdentityGuard Print Module and is required when installing the Print Module. It handles communications between the Entrust IdentityGuard server and Print Module. It allows Print Module to perform the operations required to print and encode smart credentials, including fetching smart credential configuration information and performing operations to interact with the managed CA
