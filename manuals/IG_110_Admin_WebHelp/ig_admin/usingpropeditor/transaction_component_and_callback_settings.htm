IdentityGuard Server 11.0 Administration Guide

Transaction Component and Callback Settings

These properties specify how to connect to the transaction component on the Self-Service Module. This connection is required if you want to enable transaction verification (an optional feature of the Entrust IdentityGuard Mobile ST app) or identity-assured transactions (an optional feature of the Entrust IdentityGuard Mobile Smart Credential app). For more information, see Soft token transaction verification overview and “Using mobile smart credentials for security challenges” in the Entrust IdentityGuard Smart Credentials Guide.

Transaction Component URL

identityguard.transaction.url

Specifies the URL and port of the transaction component. Ensure you use the port that is used internally by Entrust IdentityGuard server to access the transaction component. By default, this port is 8449.

The URL has the following syntax:

https://<ssm.example.com>:8449/igst

where <ssm.example.com> is the host name of the Self-Service Module where the transaction component is enabled.

For failover and high-availability reasons, you may have several transaction components in your environment. If this is the case, enter the URL of each one, separated by a space. If the first transaction component in the list is not available, the next transaction component URL in the list is used, and so on, until a working transaction component URL is found. This URL continues to be used until it fails, at which point Entrust IdentityGuard tries to connect to the next URL in the list, and cycles through to the beginning of the list until a working URL is found.

Transaction Component Secret

identityguard.transaction.secret

Specifies the secret that is shared between the Entrust IdentityGuard server and the transaction component. You can use any secret of your choosing.

Record the Transaction Component Secret value. You must enter this secret into the Self-Service Module’s Configuration interface.

In the Properties Editor, click Encrypt to encrypt the secret. If you are editing the identityguard.properties file by hand, enter:

&identityguard.transaction.secret= <Your_secret>

The use of the ’&’ prefix causes the secret to be encrypted the next time Entrust IdentityGuard starts.

Transaction Connect Timeout

identityguard.transaction.connectTimeout

Sets the timeout (in milliseconds) after which a connection between the transaction component and the Entrust IdentityGuard server is deemed to have failed.

A value of means no connect timeout.

Default: 15000 (15 seconds)

Transaction Disable Hostname Verification

identityguard.transaction.disableSSLHostnameVerification

Host name verification is where the SSL client (in this case, the Entrust IdentityGuard server) verifies that the host name in the transaction component’s certificate matches the host name in the URL it is trying to connect to. For example, if Entrust IdentityGuard server is trying to connect to https://ssm.example.com:8449/igst, then ssm.example.com must appear in the transaction component’s certificate. If the names match, host name verification passes. If the names are different, host name verification fails.

The transaction component uses the same certificate as the Self-Service Module.

True – SSL host name verification is disabled.

False – SSL host name verification is enabled.

Default: False

Callback Connect Timeout

identityguard.callback.connectTimeout

Specifies the connection timeout (in milliseconds) when Entrust IdentityGuard connects to a callback URL to notify the client that a security challenge response has been received. A value of 0 means no connect timeout is used. If a value is not specified the default value is used.

Default: 5000 (5 seconds)

Callback Disable Hostname Verification

identityguard.transaction.disableSSLHostnameVerification

If set to true, SSL host name verification is disabled when connecting to the callback URL to notify the client that a security challenge response has been received.

Default: False.
