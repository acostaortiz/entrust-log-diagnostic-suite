IdentityGuard Server 11.0 Administration Guide

Challenge Cache Settings

These properties improve the performance of your Entrust IdentityGuard system by using a cache for challenges. The cache holds the challenge in memory and only writes it to the persistent repository after a specific period of time has elapsed. Normally, the authenticate request is received within this time period, and the challenge is then accessed from the cache.

Attention: Do not enable challenge caching in a replicated or load-balanced environment where you cannot guarantee a user's authentication requests will always be directed to the same Entrust IdentityGuard server.

If you want to enable challenge caching in a replicated or load-balanced environment, you must ensure “sticky sessions” (that is, an entire session is associated with one and only one Entrust IdentityGuard server).See Enabling cached challenges for more details and to view a snapshot of the properties.

Cache Challenges

identityguard.challenge.cache.enabled

Enables or disables challenge caching. Use the default setting (False) when using transaction verification with soft tokens (using the Entrust IdentityGuard Mobile Soft Token app).

Default: False

Challenge Cache Timeout

identityguard.challenge.cache.timeout

If caching is enabled, defines how long in seconds a challenge remains in the cache before it is flushed and written to the persistent repository. A setting of 0 means the challenges remain in the cache.

Default: 180 (3 minutes)

Challenge Cache Maximum Size

identityguard.challenge.cache.maxsize

If caching is enabled, controls the maximum size (in number of challenges) of the challenge cache. This property sets the maximum number of challenges that can be held in cache, after which the least used entry is written to the persistent repository.

The value of this property must be a non-negative integer. Setting this property to 0 sets the Challenge Cache Maximum Size to infinite.

If not set or set to an invalid value, the cache size defaults to infinite.

Challenge Cache Cleanup Schedule

identityguard.challenge.cache.cleanupSchedule

If caching is enabled, sets the number of milliseconds between checks to see if challenges should be written to the persistent repository. A setting of 0 means no cache cleanup occurs.

Default: 60000 (60 seconds)
