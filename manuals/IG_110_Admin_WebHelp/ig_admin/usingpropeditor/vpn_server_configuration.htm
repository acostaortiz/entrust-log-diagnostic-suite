IdentityGuard Server 11.0 Administration Guide

VPN Server Configuration

These properties set up your VPN server configurations. You can have multiple configurations, where each references a different VPN server or Entrust IdentityGuard Radius proxy port. This allows you to associate different VPN servers with different user groups, which in turn are mapped into different Entrust IdentityGuard groups using different authentication methods. Alternatively, you can have multiple VPN servers that are not group-specific, and which communicate with the same Radius proxy port or ports. In this case, each configuration can use a different form of first-factor authentication. For more details and to view a snapshot of the properties, see Configuring the Radius proxy for groups. With Entrust IdentityGuard Server 10.2 FP1 Patch 195848 or later, you can specify multiple hosts, IP addresses or CIDRs for a VPN instance, using a space separated list.

Typically, you create your VPN server setups using the Configuration Panel or a UNIX script, as described in the Entrust IdentityGuard Installation Guide. You can add new servers or change existing settings using these properties.

Note: Each VPN server configuration must be unique. Each instance must differ from all others either in its host name, Radius proxy port, or VPN Radius Attribute ID value.

Where it appears in properties in the following table, the {0} placeholder is replaced by the VPN server configuration instance name.

Note: All challenge and challenge retry messages must contain no more than 253 characters after all their placeholder parameters are replaced by real values.

 

VPN Host

identityguard.igradius.vpn.{}.host

This is the host of the VPN server. The entries in this field can be single host names or IP addresses, multiple host names for IP addresses, or ranges of IP addresses specified using Classless inter-Domain routing (CIDR) blocks, as described in RFC 4632. Entries in this field must be separated by spaces.

When multiple hosts are specified, they share the same configuration, including the same port (or no port) and VPN shared secret.

When the CIDR is specified, any VPN server whose IP address is included in the range of the CIDR will match the given VPN configuration, as it pertains to the host name match.

Example:

1.4.2./24

Note: Each VPN server configuration must be unique. Each instance must differ from all others either in its host name, Radius proxy port, or VPN Radius Attribute ID value.

Radius Proxy Port Used By VPN

identityguard.igradius.vpn.{}.igport

Optional. Specifies the Radius proxy port the VPN server is associated with. (See Radius Proxy Configuration (15).

Note: Each VPN server configuration must be unique. Each instance must differ from all others either in its host name, Radius proxy port, or VPN Radius Attribute ID value.

Radius Attribute ID Used to Identify the VPN

identityguard.igradius.vpn.{}.vpnattributeid

Specifies the Radius attribute ID of the initial Radius request message that is used to identify the VPN Server associated with this configuration (for example, 3 for CALLER-STATION-ID). If this setting is specified, you must also specify the associated properties:

–  The Type of the Radius Attribute ID Used to Identify the VPN

–  The Value of the Radius Attribute ID Used to Identify the VPN

The Radius Attribute ID is used to determine the VPN server configuration to use in addition to the VPN server host and Entrust IdentityGuard Radius proxy port. A Radius Attribute ID is not used by default. Each configuration should specify a unique VPN server, Entrust IdentityGuard Radius proxy port, and Radius Attribute ID (with its Type and Value expressions).

To determine which VPN server configuration to use, the following searches are performed, in this order:

a.      Search for matching host, port and Radius Attribute ID.

b.      Search for matching host and port.

c.      Search for matching host and Radius attribute ID.

d.      Search for matching host.

The first matching VPN server is used. If the Radius Attribute ID and expression values (type and value) can result in duplicate possibilities across different VPN server configurations, the selected configuration for a Radius request may be ambiguous.

Note: This feature can be used with external Radius servers only if the VPN requests always include the Radius Attribute ID. Otherwise, in some cases, where Radius sends reject messages for non-failure cases (for example, a password expiry using MSCHAPv2), the Radius Attribute ID used to identify the VPN configuration must be re-sent with the next Radius request. Otherwise, there is no way to identify the VPN configuration to use. Normally the Radius State ID attribute is used in subsequent requests. However, for a Radius reject message, a State ID cannot be used.

Note: Each VPN server configuration must be unique. Each instance must differ from all others either in its host name, Radius proxy port, or VPN Radius Attribute ID value.

Default: none.

The Type of the Radius Attribute ID Used to Identify the VPN

identityguard.igradius.vpn.{}.vpnattributetype

Specifies the type of Radius attribute comparison to perform to identify the VPN Server associated with this configuration. This setting is used if the associated attribute ID is specified.

There are 2 options: STRING and HEX. HEX should be used if the values from the Radius request message are sent in binary form.

Default: STRING.

The Value of the Radius Attribute ID Used to Identify the VPN

identityguard.igradius.vpn.{}.vpnattributeexpr

Specifies the value for the Radius attribute ID of the initial Radius request message used to identify the VPN Server associated with this configuration. This setting is used if the associated attribute ID is specified. The value can be in the form of a wildcard-based expression which gives it the ability to perform pattern matching (for example, *test* or A*D4), depending on the type. This value should be represented as a string or using hexadecimal characters (for example, AB1C2D3). All expressions are case insensitive.

Default: none

Entrust IdentityGuard User Group

identityguard.igradius.vpn.{}.group

Optional. Specifies the Entrust IdentityGuard user group associated with the VPN server instance.

You can configure a VPN server instance to apply to a specific group. This way, the Radius proxy can direct users in specific groups to different methods of first-factor authentication.

The VPN group property works as follows:

●        If the user ID received from the VPN client contains a group, that user ID is passed to Entrust IdentityGuard as is.

●        If the user ID received from the VPN client does not contain a group, the group is set to the VPN group property. If no group is set in the property, your VPN server configuration applies to all groups not explicitly associated with a VPN server.

For information about using this and other VPN property options, see Configuring the Radius proxy for groups.

VPN Shared Secret

identityguard.igradius.vpn.{}.secret

This is the VPN server shared secret. Select the Encrypt option to have the secret encrypted when saved.

VPN Application Name

identityguard.igradius.vpn.{}.applicationName

Specifies the application name sent to Entrust IdentityGuard in authentication requests. This value appears in audit and log messages. If no name is specified, the default name is used.

Default: Entrust IdentityGuard Radius/<vpnname>where <vpnname>is the name of this VPN definition.

VPN Character Set

identityguard.igradius.vpn.{}.charset

Specifies the character set used to decode user names sent by the VPN server and encode messages sent back to the server. Pick one of the options: UTF-8 or ISO-8859-1.

If not specified, the Radius proxy expects UTF-8. The character set is only a concern when extended (that is, non-ASCII) characters are part of the names.

Radius Proxy Converts Backslash

identityguard.igradius.vpn.{}.processbackslash

When enabled, converts group and user name pairs in the form “group\name” coming through the Radius proxy into the form “group/name.”

Default: False

Radius Proxy Converts At Sign

identityguard.igradius.vpn.{}.processat

When enabled, converts group and user name pairs in the form “name@group” coming through the Radius proxy into the form “group/name.”

Default: False.

Radius Proxy Removes Group for 3rd-party Radius

identityguard.igradius.vpn.{].stripgroupforradius

If this property is set to True, the group is stripped out of the user ID before the request is forwarded to a third-party Radius server for first-factor authentication. If not set, or set to False, no changes are made to the user ID.

Note: If you are using the MS-CHAPv2 protocol, this property setting may not have the desired effect depending on the Radius server implementation of MS-CHAPv2, because the user ID used by the client when it calculated the MS-CHAPv2 response must also be used by the third-party Radius when it validates the MS-CHAPv2 response.

Note: If set to True, this property works as intended only if group names do not include a backslash (\) or at-sign (@) character.

Default: False

Radius Proxy Removes Group for IdentityGuard

identityguard.igradius.vpn.{}.stripgroupforig

If this property is set to True, the Radius proxy strips the group out of the user ID before the request is forwarded to Entrust IdentityGuard server. If set to False, the group is kept in the user ID when the Radius proxy forwards the request to Entrust IdentityGuard server.

Set this property to True only if your domain group names and Entrust IdentityGuard group names do not match.

Note: If set to True, the VPN server must use the PAP protocol, and user names in Entrust IdentityGuard must be unique across all Entrust IdentityGuard groups.

Note: If set to True, this property works as intended only if group names do not include a backslash (\) or at-sign (@) character.

Default: False

Skip Second-Factor Authentication for Nonexistent Users

identityguard.igradius.vpn.{}.skipauth.noexist

Specifies how to deal with VPN users who do not yet exist in Entrust IdentityGuard. (This applies to access through a Radius server, not using external authentication.)

If set to True, the user can log in without being prompted for Entrust IdentityGuard authentication.

If set to False, the user login attempt generates an error.

Default: False

Skip Second-Factor Authentication for Users Without Active Grids or Tokens

identityguard.igradius.vpn.{}.skipauth.noactive

Sets how to deal with users who exist in Entrust IdentityGuard but who do not have an activated grid or token for second-factor authentication.

When set to True, a user who has never had an active grid or token can log in without being prompted for Entrust IdentityGuard authentication. This allows users to continue to authenticate before they receive or activate a grid or token.

If a user previously had an active grid or token but the grid or token has been deleted, and this setting is True, the user receives a failed authentication error. The user must complete a fallback second-factor authentication or contact the administrator. This prevents users or attackers from deleting grids or tokens for the purpose of skipping second-factor authentication.

If set to False, the user login attempt generates an error.

Default: False

Maximum Number of VPN Outstanding Requests

identityguard.igradius.vpn.{}.vpnrequests

Provides the size of the VPN state table; that is, the number of outstanding requests from the VPN.

VPN Request Timeout

identityguard.igradius.vpn.{}.vpnrequesttimeout.

Specifies the length of time (in seconds) that the Entrust IdentityGuard Radius proxy queues responses for previous requests. Responses are queued to handle any VPN requests that are retransmitted by the VPN server. This value should be set to a value larger than the retransmit interval set in the VPN server.

Default: 10 seconds

Use IP Risk-Based Authentication

identityguard.igradius.vpn.{}.allowriskbasedauthentication

Determines if the Radius proxy will apply risk-based authentication to users accessing Entrust IdentityGuard through a VPN server.

When you set Use IP Risk-Based Authenticationto True, Entrust IdentityGuard looks for the IP address in the IP Address Radius Attribute ID property. By default the IP Address Radius Attribute ID is set to TUNNEL-CLIENT-ENDPOINT (66).

Attention: For risk-based authentication to occur through the Radius proxy, first-factor authentication must be enabled through the Radius proxy. In other words, the First-Factor Authentication Method property (identityguard.igradius.vpn.{}.firstfactortype) must not be set to No First-Factor Authentication (NULL).

Also see Risk-based authentication overview for more information.

Default: False

IP Risk-Based Authentication Security Level

identityguard.igradius.vpn.{}.secondfactorsecuritylevel

If the Radius proxy is configured to use risk-based authentication (the Use IP Risk-Based Authentication property is True), this sets the security level to apply.

The choices are Normal or Enhanced.

IP Address Radius Attribute ID

identityguard.igradius.vpn.{}.ipaddressattributeid

This property specifies the Radius attribute ID to use to read the client IP address in Radius Access-Request and Access-Response messages.

The IP address encapsulated in the Radius attribute must be a dot notation value encoded as a string.

Default: TUNNEL-CLIENT-ENDPOINT (66)

First-Factor Authentication Method

identityguard.igradius.vpn.{}.firstfactortype

Determines which type of first-factor authentication to use through the Radius proxy. The choices are Radius, External, Entrust IdentityGuard Password, Entrust IdentityGuard Token or No First-Factor Authentication  where:

–  Radius indicates users are authenticated using a Radius server.

–  External indicates users are authenticated using an LDAP directory or a Windows domain controller. (See External First-Factor Authentication (18), and External authentication overview.)

–  Entrust IdentityGuard Password indicates users are authenticated using an Entrust IdentityGuard password. (Also see Password authentication overview)

–  Entrust IdentityGuard Token indicates users are authenticated using a token supported by Entrust IdentityGuard. If you choose this option, you cannot add any second-factor authentication. This is also called “one-step token authentication.” (Also see Token authentication overview)

–  Entrust IdentityGuard One-Time Password indicates that first-factor authentication will be performed using OTPs delivered out-of-band. (Also see Out-of-band one-time password overview.)

Note: When using Radius first-factor authentication with OTPs, the OTP Dynamic Refresh Enabled policy must be set to True to ensure that new OTPs can be delivered.

Note: If you use OTP for first-factor authentication, you cannot set OTP as a second-factor authenticator.

–  No First-Factor Authentication implies first-factor authentication has already occurred outside of Entrust IdentityGuard and the user is ready for second-factor authentication. In this case, second-factor authentication by some means is required.

Do not select No First-Factor Authentication if you want the Radius proxy to perform risk-based authentication (Use IP Risk-Based Authentication= True). For risk-based authentication to occur through the Radius proxy, first-factor authentication must be enabled.

identityguard.igradius.vpn.{}.radius

Specifies the Radius server associated with the VPN server, if applicable. The drop-down list includes any Radius servers you previously configured in the Radius Server Configuration pane.

This property applies only if the First-Factor Authentication Methodproperty specifies Radius. See Radius Server Configuration (16).

If you are using the group mapping feature, and you have configured your Radius servers by giving them Entrust IdentityGuard group names, use the default setting: User’s Group is Radius Server. For more information about using this feature, see Creating, modifying, and removing Radius servers.

Displaced Server

identityguard.igradius.vpn.{}.displacedRadius

If you are replacing an existing Radius authentication server with Entrust Identityguard Radius, use this property to specify the name of the Radius server being replaced.

Only Perform First-Factor Authentication

identityguard.igradius.vpn.{}.firstfactoronly

If this property is set to True, the user is authenticated after successful first-factor authentication and is not shown a second-factor challenge.

If First-Factor Authentication Method is set to No First Factor Authentication this property must be set to False.

If First-Factor Authentication Method is set to Entrust IdentityGuardToken, this property must be set to True. Users must enter the token response manually, Use of MST TVS token authentication (by which a user of the Entrust IdentityGuard Mobile Soft Token app selects Confirm to authenticate) is not supported for first-factor authentication.

MST TVS token authentication can be used only as a second-factor authentication method.

If this property is set to True, the Allowable Entrust IdentityGuard Second-Factor Authentication Methods property is disabled.

Default: False

Allowable Entrust IdentityGuard Second-Factor Authentication Methods

identityguard.igradius.vpn.{}.allowedsecondfactortype

This property specifies which second-factor authentication methods are valid through the Entrust IdentityGuard Radius proxy; that is, Entrust IdentityGuard chooses the second-factor authentication based on this property.

Select one or more of the following:

–  Grid

–  Token—If Token is used for first-factor authentication, second-factor authentication is disabled. This option now supports authentication with mobile soft tokens (using the Entrust IdentityGuard Mobile Soft Token app).

–  OTP—OTP is not allowed for second-factor authentication if it is used for first-factor authentication.

–  Q&A (Question and Answer)

Default: Grid, Token, OTP, Q&A (If you use OTP for first-factor authentication, the default is Grid, Token, Q&A.)

Note: If you are setting up multiple VPNs, they can have different second-factor types. That is, you can set up VPN1 with Grid, for example, and VPN2 with Token.

PVN Required

identityguard.igradius.vpn.{}.pvnrequired

This property can override PVN policy set by the Authentication Types Requiring a PVN policy attribute (see Personal Verification Number policies).

When set to True, a PVN is required during Radius authentication through VPN for any authentication method that supports PVN, regardless of how the policy is set.

When set to False (the default), the PVN policy setting determines if a PVN is required.

Use MST TVS for Token Authentication

Specifies whether mobile soft tokens (in the Entrust IdentityGuard Mobile Soft Token app) can be used for authentication challenges. Set to True to allow mobile soft token authentication challenges using online mode (by which users select Confirm in the app to authenticate).

This authentication method can be used only for second-factor authentication.

Default: False

MST TVS Online Fallback

Specifies whether the "classic" mode of mobile soft token authentication should be used for fallback authentication if a user does not respond to the online authentication challenge on the Entrust IdentityGuard Mobile Soft Token app within a certain time frame. With classic mode, the user manually enters the OTP generated by the soft token instead of selecting the Confirm button.

This property can be set only if Use MST TVS for Token Authentication is set to True.

Set to True to allow users to manually enter the OTP if they do not have an Internet connection (known as classic mode). If this property is set to False, no fallback authentication method is offered.

Default: False

Default MST TVS Online Token Challenge Summary Message

Use this property to set the content of the message displayed on a user’s mobile device for authentication using the Entrust IdentityGuard Mobile Soft Token app. If you do not specify a message, the default message is used. The message must not exceed 1024 characters.

This property can be set only if Use MST TVS for Token Authentication is set to True.

Default: "User {0} wants to authenticate." The placeholder {0} is used to insert the user’s Entrust IdentityGuard user ID.

TVS Callback Response Timeout

Specifies the time, in seconds, that Entrust IdentityGuard Radius waits for a response from Entrust IdentityGuard. This value should be less than the overall VPN timeout for a request to complete processing. If the challenge lifetime policy defined by Entrust IdentityGuard is smaller than this value, this value is set to the value in the policy.

Default: 60

Separate Challenge for PVN Update

identityguard.igradius.vpn.{}.pvnupdateseparatechallenge

When changing the PVN, this property sets whether the new PVN must be entered and confirmed with one prompt or two.

For first-factor token or OTP authentication: If this property is False, the user is prompted once, and must enter the new PVN twice. If this property is True, the user is prompted twice, and enters the new PVN once for each prompt.

For second-factor authentication supporting PVN (grid, token, and OTP): If this property is False, the user is prompted once for the second-factor challenge (including the old PVN), and must enter the new PVN twice, along with the challenge response. If this property is True, the user is prompted for the challenge response (which includes the old PVN). Then they are prompted twice more, and must enter the new PVN once for each prompt.

Default: False

Skip Second-Factor Authentication for Users That Have Been Authorized

identityguard.igradius.vpn.{}.skipsecondfactorifauthorized

Use Second-Factor Authentication for Users That Have Been Authorized in conjunction with Authorization expression. If True, users who have been successfully authorized against your authorization expression skip second-factor authentication.

For information about the default challenge messages and how to change them, see Customizing VPN challenge strings.

Authorization expression syntax and examples

When the Authorization expression property contains an expression, Entrust IdentityGuard performs an authorization check immediately after first-factor authentication (if second-factor authentication is disabled), or second-factor authentication (if second-factor authentication is enabled).

Define groups using the following syntax:

<attributename>(!=|=)"<attributevalue>"[(AND|OR)<attributename>(!=|=) "<attributevalue>"]*

where:

●       <attributename> is either:

–  an LDAP attribute name used to retrieve the LDAP group information

–  igGroup, if you are defining an Entrust IdentityGuard group

●       <attributevalue> is the name of the LDAP or Entrust IdentityGuard group

●       the exclamation point (!) is used to negate an expression

●       double-quotes ("") are used around names that include spaces

●       AND and OR are used to create authorization rules that require users to be members of more than one group (AND) or require users to be members of at least one of several groups (OR).

●       attribute names and values are case insensitive.

Examples

memberOf="cn=VPN Users*" 

This expression means a user is authorized if they belong to any LDAP group that has cn=VPN Users in the group name.

 

memberOf="cn=VPN Users 1" AND memberOf=cn=Administrators OR memberOf="cn=VPN Users 2*"

This expression means a user is authorized if they belong to the LDAP groups VPN Users 1 and Administrators, or to the group VPN Users 2.

 

memberOf="cn=VPN Users" AND memberOf=cn=Administrators OR igGroup=Group1

This expression means a user is authorized if they belong to the LDAP groups VPN Users and Administrators, or to the Entrust IdentityGuard group Group1.

 

memberOf!="cn=Desktop Users*"

This expression means a user is authorized if they are not a member of an LDAP group that has cn=Desktop Users in the group name.
