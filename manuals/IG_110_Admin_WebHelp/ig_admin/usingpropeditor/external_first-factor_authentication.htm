IdentityGuard Server 11.0 Administration Guide

External First-Factor Authentication

These properties let you set up external authentication. Typically, you would use external authentication as the first layer of a multifactor Entrust IdentityGuard authentication regime. When an instance is specified with an Entrust IdentityGuard group name, this sets the authentication resource to use for members of that group. This allows you to direct different groups to different authentication resources. For more information and to view snapshots of the properties, see External authentication overview.

Configuration Instances

Lists all current external authentication configurations. To create an external authentication instance for a specific Entrust IdentityGuard group, enter a unique group name in the empty field and click Add. From this point on, all other settings relate to that instance.

Attention: The group name is case-sensitive. For example, if your Entrust IdentityGuard group name is My Group, you must enter My Group into the Configuration Instances field, not my group or any other incorrect casing.

The Default instance is used for all users not assigned to a group for which a group-specific instance is provided, or when group-specific external first-factor authentication is not required.

To delete an instance, select it in the list and click Remove.

External First-Factor Authentication Method

identityguard.externalauth.impl

Sets the resource used for external authentication. Select an option from the drop-down list. The options are:

●        LDAP External Authentication

●        Domain Controller External Authentication

Kerberos Realm for Domain Controller Authentication

identityguard.externalauth.kerberos.realm

Domain controller authentication uses the Kerberos protocol. You must provide the fully qualified domain name of the server acting as the Kerberos realm or domain. Enter the server name in uppercase characters unless your Kerberos server indicates otherwise. For example: IGHOST.ENTRUST.COM.

Kerberos Realm Case Conversion for Domain Controller Authentication

identityguard.externalauth.kerberos.realmcaseconvert

Many Kerberos servers require realm names to be in uppercase letters, which Entrust IdentityGuard does by default. Set this to False to leave the case unchanged.

Default: True

Kerberos User ID Case Conversion for Domain Controller Authentication

identityguard.externalauth.kerberos.caseconvert

Kerberos authentication is case-sensitive. If the user enters an ID that does not match the case Kerberos expects, the authentication fails. Use this property to convert the case of the user ID.

Select the conversion option from the drop-down list:

●        No Conversion means leave the case as is.

●        Lowercase means switch the case to all lowercase.

●        Uppercase means switch the case to all uppercase.

●        User Principle Name (UPN) means switch the user ID to the form id@DOMAIN (for a domain controller).

Default: No Conversion

Expired Password Equals Successful Authentication (Kerberos)

identityguard.externalauth.kerberos.allowexpired

When set to True, first-factor authentication succeeds even if the password used has expired. Your Kerberos server must ensure the password is valid; that is, any password failure should not succeed, just valid but expired passwords.

Default: False

Expired Password Equals Successful Authentication (LDAP)

identityguard.externalauth.ldap.allowexpired

When set to True, first-factor authentication succeeds even if the password used has expired. Your LDAP directory server must ensure the password is valid; that is, any password failure should not succeed, just valid but expired passwords.

Default: False

Expired Password Allows Change (LDAP)

identityguard.externalauth.ldap.passwordchange

This setting controls what happens when a user tries to authenticate using an expired LDAP password. (An LDAP password can expire because an administrator has reset it, or because it has reached the end of its lifetime.)

When set to True, Entrust IdentityGuard indicates that a password change is required, and includes the password rules to which the new password must adhere.

When set to False, Entrust IdentityGuard indicates that a password change is required, but cannot be effectuated. Users must change their LDAP password through another means before Entrust IdentityGuard authentication can succeed.

Default: False

Note 1: If this setting is True, the Expired Password Equals Successful Authentication (LDAP) property must be set to False.

Note 2: Ensure that your LDAP and Entrust IdentityGuard password rules are synchronized to avoid scenarios where a password change is allowed by Entrust IdentityGuard but prohibited by the LDAP server. Turn off any LDAP password rules that cannot be enforced by Entrust IdentityGuard. For more information, see . details on password rules, see Configuring password authentication policies.

Note 3:If you are using Active Directory as your repository, and you want password change to work, then SSL must be enabled between Active Directory and the Entrust IdentityGuard server. For details on enabling SSL, see Secure the LDAP connection with SSL.

Note 4:If you are using ADAM as your repository, and you want password change to work, see configuration details in Enable password change with ADAM .
