IdentityGuard Server 11.0 Administration Guide

Customize the JavaMail out-of-band OTP template

Message templates are used in both email and SMS OTP delivery. These templates use Velocity syntax and they are used to format the messages used to deliver OTPs to users. You can find the template files:

●       on Windows

<$IG_HOME>\etc\templates\oob\

●       on UNIX

$IG_HOME/etc/templates/oob/

You can modify the templates to meet your needs.

For information about Apache Velocity syntax, see http://velocity.apache.org/engine/releases/velocity-1.5/user-guide.html.

Entrust IdentityGuard uses the values set in the Out-of-Band OTP Email Delivery Configuration properties, such as Email Delivery Subject, to fill in fields in the message.

All email messages use the template named in the Email Delivery Template File property. Entrust IdentityGuard includes an email template file that you can use. If you are installing Entrust IdentityGuard for the first time, the email template files are called:

●       igsample_email_template.txt 

●       igsample_email_template.html

Copy the template file before changing it for your application. You can customize the contents to add branding and standard messages or disclaimers. You must use UTF-8 as the character-encoding format for the email template.

You can use the optional HTML template to send both text and HTML messages if required. If you would like to send an HTML message to email clients able to read HTML, create a text template and an HTML template. Both are supplied when Entrust IdentityGuard is installed, as described above.

If you have both text and HTML templates, a MIME multi-part alternative message is sent with both text and HTML body parts. When the email message is received, character-based e-mail clients use the text template, while graphical e-mail clients like Microsoft Outlook can display the HTML formatted email message.

The template, which uses Apache Velocity for formatting, allows you to define placeholders that Entrust IdentityGuard replaces with the appropriate information when the message is sent:

●       $fullname — The user's full name (If the user account does not include a full name, this will be the user name.)

●       $username — The Entrust IdentityGuard user name (without the group name)

●       $otp — The one-time password generated

●       $otps — All of the one-time passwords

●       $newOTPs — All of the OTPs created during this operation

●       $oldOTPs — All of the OTPs existing before this operation

●       $operation — is one of:

–  CHALLENGE – The OTP delivery is being done as part of a challenge request.

–  AUTHENTICATE  – The OTP delivery is being done as part of the authentication.

–  ADMIN  – The OTP delivery is being done as part of a delivery request from an administrator

●       $expirydate — The expiry date of the one-time passwords

●       $dynamicRefresh — This value will return True if the dynamic refresh policy is enabled.

●       $transactionDetails — The details of the transaction that prompted the challenge

The $fullname and $otp placeholders are part of the default template:

Hello $fullname,

Your one-time password is $otp.

As an example, an OTP email to John Smith to deliver one OTP without transaction details could look something like this:

Hello John Smith,

Your One Time Password is 1A3D456H.

You can also define more complex scripting in the template to allow display of the transaction details and multiple OTPs. For example:

Hello $fullname,

 

#if($transactionDetails)A

Your transaction details are:

#foreach ($key in $transactionDetails.keySet())

  $key: $transactionDetails.get($key)

#end

 

#if($otps)

#if($otps.size() > 1)

If you agree with these transaction details, enter one of the following:

one-time passwords to confirm the transaction.

#foreach ($o in $otps)

  $o

#end

#if($expiryDate)

These one-time passwords expire on $expiryDate.

#else

These one-time passwords never expire.

#end

#else

If you agree with these transaction details, enter the one-time

password $otp to confirm the transaction.  Your one-time password

#if($expiryDate)

expires on $expiryDate.

#else

never expires.

#end

#end

#end

#else

#if($otps.size() > 1)

Your one-time passwords are:

#foreach ($o in $otps)

  $o

#end

#if($expiryDate)

These one-time passwords expire on $expiryDate.

#else

These one-time passwords never expire.

#end

#else

#if($expiryDate)

Your one-time password is $otp.  It expires on $expiryDate.

#else

Your one-time password is $otp.  It never expires.

#end

#end

#end
