IdentityGuard Server 11.0 Administration Guide

Worksheet for enabling out-of-band one-time password authentication

This section describes how to enable user authentication using one-time passwords that are delivered out of band in email, voice messages, or text messages (SMS). After you complete the procedures outlined in the worksheet, users will be able to receive one-time passwords through out-of-band channels to use for appropriate authentication scenarios.

This worksheet uses the following abbrieiations:

IG — Entrust IdentityGuard Administration interface
PE — Entrust IdentityGuard Properties Editor
SSM — Entrust IdentityGuard Self-Service Module

Before you begin, have this guide and the Entrust IdentityGuard Self-Service Module Installation and Administration Guide available.

You do not have to use Entrust IdentityGuard mechanisms to deliver the OTP. You can deliver them through a help desk, or develop your own OTP delivery solutions using the out-of-band delivery interface provided. For more information about creating your own solution, see the Entrust IdentityGuard Programming Guide for the Java Platform.

IG

4.      Configure settings for individual users:

  

·      Set OTP as an authentication for individual users

Enabling OTP authentication for individual users

·      Using the User Accounts pages of the Administration interface, ensure users have required contact information (email address or telephone number) for OOB OTP delivery.

In the user-registration process for your client application, the application should ask for an email address and one or more phone numbers (home, work, mobile). When you have this information, your application can deliver a one-time password by one or more out-of-band methods: email, SMS message, or automated voice message. See Configuring delivery mechanisms for one-time passwords .

IG

5.      Configure your client application to do the following:

·      Collect required user contact information as part of a registration process (email, standard and mobile phone numbers).

·      Challenge users for one-time passwords.

·      Deliver OTPs (if the user has no valid OTPs) using out-of-band communication (email, SMS or voice message).

·      Have the OTP entered by the user verified by the Authentication API.

·      (Optional) Send additional OTPs to users to replenish their OTP lists. (This action uses the One-Time Password policy setting Dynamic OTP Refresh Enabled. For more information, see Set policies for out-of-band OTPs.

For information about configuring your client application, see the Entrust IdentityGuard Programming Guide.

A fully automated OTP delivery mechanism is not an absolute requirement. In circumstances where one-time passwords are infrequently used, an Administrator can generate an OTP in the Administration interface and give it to the user directly by telephone, email, text message, or voice message.
