IdentityGuard Server 11.0 Administration Guide

Configure the SMS delivery mechanism

Use the Properties Editor to create an OTP delivery mechanism for delivering one-time passwords.

To configure an SMS OTP service

1.      Log in to the Entrust IdentityGuard Properties Editor.

Windows

a.      Select Start > All Programs > Entrust > IdentityGuard > Properties Editor.

b.      On the Log In page, enter your administrator name in Userid.

c.      Enter your password in Password.

d.      Enter a group name in the Group field.

e.      Click Log In.

f.        Complete the second-factor challenge, if presented.

UNIX

a.      Enter the URL of your Properties Editor web application in a Web browser. It has this form:

https://<hostname>:<port>/IdentityGuardPropertiesEditor

Where:

<hostname> is the host name you selected during configuration

<port> is the administration port you selected during configuration

b.      On the Log In page, enter your administrator name in Userid.

c.      Enter your password in Password.

d.      Enter a group name in the Group field.

e.      Click Log In.

f.        Complete the second-factor challenge, if presented.

2.      On the Table of Contents, click Out-of-Band OTP SMS Delivery Configuration.

3.      In the empty field below Configuration Instances, enter a unique service name. Click Add.

The pane expands to reveal other properties. Several are required fields.

You can configure more than one SMS service so that you can provide services for different user groups or languages. Give each instance a different name.

4.      For the SMS Delivery Class Name property, do the following:

●       Select either Clickatell or TeleSign if one of these is your SMS service provider.

●       If you want to use another SMS service provider, select Clickatell even though the service provider is not Clickatell.

●       If you plan to use a custom SMS Java class, select Custom and enter a new class name in the field that appears.

5.      Optional. Enter a service name in the SMS Delivery Configuration Display Name field. This display name appears in the Administration interface and can appear in your client application.

6.      For the SMS Gateway URL field, do one of the following.

●       For Clickatell, leave this field empty.

By not entering anything, the Clickatell SMS Gateway URL is used, namely:

https://api.clickatell.com/http/sendmsg?user=URL_USER_TAG&password=URL_PASSWORD_TAG&app_id=URL_APPID_TAG&to=URL_TO_TAG&text=MSG_TEXT&from=FROM_ID

where the uppercase values are replaced with ones that you specify in the Properties Editor.

Note: If you are sending a one-time-password through a proxy that requires basic authentication, specify the user name and password in the gateway URL. For example:

https://myuser:mypass@example.com/http/sendmsg?user=USERNAME&password=PASSWORD&api_id=API_ID&to=TO_PHONE&text=MSG_TEXT&from=FROM_ID

●       For TeleSign, enter NOT USED.

●       For another SMS provider, see Configuring the SMS Gateway URL for a SMS provider other than Clickatell or TeleSign.

7.      For the User Name field, enter one of the following:

●       For Clickatell, enter the Clickatell user ID you were assigned when you created your Clickatell account.

●       For TeleSIgn, enter the TeleSign user ID you were assigned when you created your TeleSign account.

●       For another SMS service provider, enter the relevant user ID for that service provider. (You must enter a user ID into the Clickatell User Name field even though the service provider is not Clickatell.)

8.      In the Password field, enter one of the following:

●       For Clickatell, enter the Clickatell server user password. Select the Encrypt option to have the password encrypted when it is saved.

●       For TeleSign, enter the TeleSign server user password. Select the Encrypt option to have the password encrypted when it is saved.

●       For another SMS service provider, enter the relevant server password for that service provider. (You must enter a password into the Clickatell Password field even though the service provider is not Clickatell.)

9.      For Clickatell API ID, enter one of the following:

●       For Clickatell as your SMS service provider, enter the API Identification listed under the API Connections on Clickatell Central. This ID must be created by Clickatell before Entrust IdentityGuard can use it.

●       For TeleSign, this property is not used.

●       For another SMS service provider, enter the API Identification for your service provider.

10.  In From label in the SMS message, do one of the following:

●       For Clickatell, enter the sender ID registered with Clicaktell for Entrust IdentityGuard.

●       For TeleSign, this property is not used.

●       For another SMS service provider, enter the sender ID registered with your SMS service provider for Entrust IdentityGuard.

11.  Under Separate Message Per One-Time Password, do one of the following:

●       For Clickatell, if you want all of the OTPs to be delivered in one SMS message, set Separate Message Per One-Time Password to False.If you want a separate SMS message for each OTP, set this property to True.

●       For TeleSign, this property is not used. TeleSign can send only one OTP in each message.

●       For another SMS service provider, check whether the provider has constraints on the number of OTPs sent before setting this property.

12.  The Include Transaction Details property allows you to set how the transaction details are sent.

●       For Clickatell, choose one of the following options:

–  First – Include the transaction details in the first SMS message, along with an OTP. Subsequent messages each contain only an OTP. This is the default setting.

–  Separate – Send the transaction details in the first message, followed by more messages, each containing an OTP.

–  All – Include the transaction details in each SMS sent. Each message contains the transaction details and one OTP.

●       For TeleSign, this property is not used.

●       For another SMS service provider, check what details can be included in transactions with your service provider.

13.  In the SMS Delivery Template File field, do one of the following:

●       For Clickatell, enter the location of the SMS message template. The template provided with Entrust IdentityGuard is suitable for both Clickatell and TeleSign. The default template can be customized. (Also see Customizing the SMS message template.)

●       For TeleSIgn, enter the location of the SMS message template. The template provided with Entrust IdentityGuard is suitable for use with TeleSign, however, consider editing the default template wording to accommodate the TeleSign limitation of one OTP per message.

Example of the modified file:

#if ($otp)

One-time password is $otp[0]

#end

#if ($expiryDate)

Expires: $expiryDate

#else

Never Expires

#end

●       For another SMS service provider, enter the location of the SMS message template. The template provided with Entrust IdentityGuard may be suitable for your SMS service provider.

The default template can be customized. (See Customizing the SMS message template.)

14.  Optional: For Prepend Digit, do one of the following:

●       For Clickatell, use the SMS Prepend Digit property to set a country code for long distance dialing. Use this property if the user contact information in the repository does not include the country code.

You can tailor this by Entrust IdentityGuard group if different groups of users require different prepend digits. As an example, if you have a North America group of users, you could set them up to use prepend digit of 1. Another group encompassing all European users’ records may include their country code. For this group, you would leave the SMS Prepend Digit blank.

●       For TeleSign, this property is not used.

●       For another SMS service provider, check details with your service provider.

15.  Under SMS Unicode Encoding, do one of the following:

●       For Clickatell, if the SMS message contains any characters outside of the Basic Latin character set (Unicode Latin-1 Supplement characters, for example), set the SMS Unicode Encoding property to True.The True setting imposes a shorter limit on SMS messages: messages containing more than 70 characters might be divided and sent as several messages. The default setting is False.

●       For TeleSign, set this property to False. TeleSign does not support Unicode. For more information, see http://docs.telesign.com/rest/content/verify-sms.html.

●       For another SMS service provider, check language encoding details with your service provider.

Attention: Sending Unicode messages to a network that does not support such messages will not generate an error. The message is lost, without any notifications that the message has not been delivered. You must verify with your SMS service provider that Unicode is supported for the user’s network before enabling this feature.

16.  Under SMS Message Fragmentation, do one of the following:

●       For Clickatell, set SMS Message Fragmentation to False if you want to prevent long SMS messages from being sent as multiple messages. If this property is set to False, and the message is too long to be sent as a single message, no message is sent, and an error is written to the log file.

If SMS Message Fragmentation is True, then do the following:

a.      In SMS Message Fragmentation Limit, enter the maximum number of messages to allow. The default is 5 fragments.

b.      In SMS Message Fragmentation Character Limit, enter the number of characters after which a message is split. The default is 160 characters, unless the SMS Unicode Encoding property is True, in which case the limit is 70.

For example, if an SMS message is 250 characters in total, and the SMS Message Fragmentation Character Limit is 100, then the message is split into 3 messages: the first two containing 100 characters each, and the last one containing 50 characters.

c.      In the SMS Message Fragmentation Split Characters, specify that characters that are used to decide where the a message is split. To specify more than one split character, separate each with a space. The following special characters are supported:

\s (space)

\t (tab)

\n (new line)

The default is to split at whitespace characters (spaces, tabs, and new lines). If the message does not contain a split character, the message is split at the Message Fragmentation Character Limit.

●       For TeleSign, this property is not used. TeleSign does not support message fragmentation. The maximum size of a TeleSign SMS message is 140 characters.

●       For another SMS service provider, check the message fragmentation details with your service provider and follow the advice for either Clickatell or TeleSign or other, as appropriate.

17.  Click Validate & Save.

18.  Log out of the Properties Editor and restart Entrust IdentityGuard and the Radius proxy after you make all property changes.
