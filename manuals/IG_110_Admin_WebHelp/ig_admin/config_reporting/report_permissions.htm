IdentityGuard Server 11.0 Administration Guide

Report permissions

The reports you can run, view, list, and delete depend on the permissions attached to your role. The contents of the reports also depend on your permissions. For example, if the administrator generating the report has access only to their group, then only data from that group is pulled into the report. Administrators with the superuser role can launch and view any report.

When you launch reports from the Master user shell, you can create and view any report because Master users have all permissions. Users with the superuser role can view reports created in the Master user shell using the Administration interface.

For the permissions needed to create, view, or delete reports, see Permissions quick reference. The report permissions appear in the following sections:

●       Audit permissions

●       Biometric permissions

●       Card permissions

●       Smart credential permissions

●       Token permissions

●       User permissions

●       User certificates permissions

●       User digital ID permissions

●       User smart credential permissions

The auditor role contains all of the report viewing permissions. The useradmin role contains all of the report permissions for the groups available to the user admin, except auditReport, so administrators with the useradmin role can get, view, list, create, and delete all report types for their groups, except audit reports.
