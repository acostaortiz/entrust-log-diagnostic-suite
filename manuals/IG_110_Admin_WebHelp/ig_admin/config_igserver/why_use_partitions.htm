IdentityGuard Server 11.0 Administration Guide

Why use partitions?

Partitions are generally used to overcome the problem of duplicate serial numbers or user numbers that can arise when your system includes multiple, replicated Entrust IdentityGuard systems, typically in different geographic locations.

Here is an overview of how replication and partitions work.

Suppose you have one Entrust IdentityGuard server in Toronto with a repository, and another Entrust IdentityGuard server in South America with another repository. Although the systems are separate, they share a single Users license, and a single Soft Tokens license. This is called the global policy (explained in greater detail later in Partitions and the global policy (licensing)).

The Toronto repository is replicated nightly to the South American repository, at which time the Entrust IdentityGuard calculates the total number of users and soft tokens created across both systems and updates the licenses accordingly. If users, grid cards, and soft tokens are created in both Toronto and South America during the day, then it is possible (and even likely) that there will be users created in Toronto who will have the same user numbers as those created in South America. Similarly, there will be cards created in Toronto that will have the same serial numbers as those created in South America. Finally, there may be soft tokens created in Toronto that have the same serial number as those created in South America. (Note that the chances of soft token duplication are low because soft token serial numbers are randomly generated and quite long. By contrast, user and card numbers are not random at all—they are incremented by one after each successive user or grid creation—making the chance of duplication very high.)

Duplicate user, card, or soft tokens present no problem during the day, because the user numbers and serial numbers are stored in separate Toronto and South American repositories. However, when the nightly repository replication occurs, this duplication results in a replication failure.

To avoid the problem of duplicate user numbers and serial numbers, you can use partitions, which allow you to allocate ranges of grid and user numbers to specific user groups. For example, Toronto users might be allocated user numbers 1 - 50,000, while South American users might be allocated user numbers 50,001 - 100,000.

Other than avoiding replication failure, partitions are also useful when you want to split users or cards serial numbers into different groups so they are generated in a more predictable way.
