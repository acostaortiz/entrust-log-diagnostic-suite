IdentityGuard Server 11.0 Administration Guide

Create partitions to avoid duplicate user numbers

To avoid duplicate user numbers that may results from repository replication, you must use partitions. Complete the following procedure to set up partitions for ranges of user numbers. The instructions use Toronto and South America as the example, with user numbers in the range of 1 to 50,000. You can use your own partition names and user number range.

To set up a partition to avoid duplicate user numbers

1.      Create two partitions:

●       Call the first partition TorontoPartition and allocate user numbers 1 to 50,000.

●       Call the second partition SouthAmericaPartition and allocate user numbers 50,001 to 100,000.

To create a partition:

a.      Log in to the Master user shell. See Using the Master user shell.

b.      Before creating the partition and allocating a range of user numbers, check what the next global user numbers are. Enter:

system get

Allocate user numbers starting at this number. In this example, the next global user number is 1.

c.      To create the partition and allocate the user numbers, enter:

partition create <name> [-comment <comment>] -userNumbers -min <min> -max <max>

Examples:

partition create TorontoPartition -comment "Toronto users" -min 1 -max 50,000

partition create SouthAmericaPartition -comment "South America users" -min 50,001 -max 100,000

2.      In the Entrust IdentityGuard Administration interface, do the following:

●       Create and associate the user group TorontoUsers with TorontoPartition.

●       Create and associate the user group SouthAmericaUsers with SouthAmericaPartition.

The result is that users created in the TorontoUsers group associated with the TorontoPartition get user numbers between 1 and 50,000 (the first user getting number 1, the second user getting number 2, and so on). Users created in the SouthAmericaUsers group associated with the SouthAmericaPartition get user numbers between 50,001 and 100,000 (the first user getting number 50,001, the second user getting number 50,002, and so on).

This scheme ensures that there is no overlap in user numbers.

For details on creating and modifying user groups, see Configuring groups.

3.      As you create users, you can add new ranges of user numbers to each partition. To save time and effort later, assign relatively large ranges of user numbers at the outset to avoid adding just a few more each time they run out.
