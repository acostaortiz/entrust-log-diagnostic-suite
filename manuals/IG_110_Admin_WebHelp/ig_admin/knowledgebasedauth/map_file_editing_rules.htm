IdentityGuard Server 11.0 Administration Guide

Map file editing rules

Follow these rules when editing the map file:

●       Do not user the following reserved characters: < > [ ] , = ; They have special meaning in the map file and should not be used as parts of word synonyms.

●       The map file accepts multiple substitutions or synonyms; that is, an entry can take the form “A = B C D”. This means that B, C and D are valid substitutes for A. It does not make B a substitute for C or D, however, or equate C and D. It is only A that is given synonyms in this entry.

●       All substitutions for a word must be listed on the right side of the equals sign (=), and a word may appear just once in the map file on the left side of the equals sign. For example, the following entries are incorrect and just the last one is used:

A = B C

A = D

●       You can have words appear on the right side of an entry in one case and be on the left side in a later entry. For example, the following is valid:

A = B C

C = B

●       Values on the left side of the equals sign can be just one word. For example, the following is invalid:

pass word = password

●       On the right side of the equals sign, each word is treated separately and spaces act as substitution delimiters. For example, this entry

password = pass word

is interpreted as “password = pass” and “password = word.”

You can also use commas as delimiters.

●       Do not edit or remove the [Protection] header and section, or the [Substitutes] header.

●       A <null> entry allows the word on the left side of the equals sign to be missing, but not the substitute words. For example, the entry

St. = street saint <null>

allows “St.” to be missing, but not “street” or “saint”, so the response “123 Saint James” matches the stored answer “123 Saint James St.”, but the response “123 James St.” does not match it.

●       If all words supplied in an answer equate to <null>, the effect is the same as requiring an exact match. For example, if you had these entries in the file

upper = <null>

street = <null>

dr. = <null>

and the user was prompted for their street name, which happens to be “Upper Street Dr.”, the only valid answer would be the entire address. A response of “Upper Street” would be rejected.

●       Invalid entries are ignored.

●       You can create a word map in any character set; that is, you are not restricted to the Latin-1 character set as long as the file is saved with UTF-8 encoding. The map file still works if saved in ANSI but it reverts to the local character set.

Note: You must restart the Entrust IdentityGuard Server service for your word map changes to take effect.
