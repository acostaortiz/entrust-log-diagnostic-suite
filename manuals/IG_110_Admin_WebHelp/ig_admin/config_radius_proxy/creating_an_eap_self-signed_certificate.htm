Creating an EAP self-signed certificate

If you want to use the Extensible Authentication Protocol (EAP) for wireless authentication, and you have configured the Entrust IdentityGuard server to use a Certification Authority (CA)-issued certificate, then you must reconfigure the Radius proxy to use a self-signed certificate for EAP. By default, the Radius proxy uses the Entrust IdentityGuard server’s certificate, known by the alias tomcat. For EAP to work correctly, a new, self-signed certificate with an alias of eap must be created in the existing Java keystore.

The reason you must create a self-signed certificate for EAP (as opposed to obtaining a CA-issued one) is because a CA-issued certificate often includes a certificate chain which may cause the certificate to exceed the message size limit imposed by the Radius protocol. Exceeding the size limit causes errors which are difficult to troubleshoot.

To create the EAP self-signed certificate

Note: The following procedure uses the Java keytool utility. For details on the keytool commands and options, see http://docs.oracle.com/javase/6/docs/technotes/tools/windows/keytool.html (Windows) or http://docs.oracle.com/javase/6/docs/technotes/tools/solaris/keytool.html (UNIX).

1.      On the Entrust IdentityGuard server where the Radius proxy is located, change to the keytool directory. The utility is located in <$IG_HOME>\jre<version>\bin (Windows)and $IG_INSTALL_DIR/jre<version>/bin (UNIX).

2.      Generate a new self-signed certificate using the Java keytool:

Attention: In the command below, you must use eap as the alias and entrust as the password.

keytool -genkeypair -keystore <path_to_keystore> -keypass entrust -storepass entrust -validity <validity_in_days> -dname "cn=<FQDN>" -alias eap -sigalg sha1WithRsa -keyalg rsa -keysize 2048

Where:

●       <path_to_keystore> is one of:

–  On UNIX: $IG_HOME/etc/keystore 

–  On Windows: <$IG_HOME>\etc\keystore 

●       <validity_in_days> is the number of days the certificate is valid.

●       <FQDN> is the fully qualified domain name of your server.

For example:

igserver.example.com

3.      Restart the Radius proxy.

You have create a new certificate. The new certificate will now be used for EAP, overriding the tomcat certificate.
