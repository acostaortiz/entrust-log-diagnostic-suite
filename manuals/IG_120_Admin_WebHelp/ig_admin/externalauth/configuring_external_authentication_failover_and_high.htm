Configuring external authentication failover and high availability (Kerberos)

Your organization depends on your authentication systems working, so it is important to set up your system to provide redundancy. Configure your servers to fail over to the redundant systems in case of failure by following the instructions in To set up failover when using Kerberos for external authentication.

For more information about failover and high availability, see Specifying multiple repositories.

For details about setting up failover and high availability when using an LDAP directory for external authentication, see To configure failover and high availability for a directory repository.

To set up failover when you use a domain controller for external authentication, add multiple KDC resources in the igkrb5.conf file.

The igkrb5.conf file, if it has been created, is located:

●       on UNIX in $IG_HOME/etc/

●       on Microsoft Windows in <$IG_HOME>\etc\

If the igkrb5.conf file does not yet exist, copy igkrb.sample to igkrb.conf.

igkrb.sample is located:

●       on UNIX in $IG_HOME/etc/

●       on Microsoft Windows in <$IG_HOME>\etc\

To set up failover when using Kerberos for external authentication

1.      Open igkrb5.conf in a text editor. It is located:

●       on UNIX in $IG_HOME/etc/

●       on Microsoft Windows in <$IG_HOME>\etc\

2.      Using Kerberos syntax, map each realm to at least two KDC resources.

Note: For Windows Active Directory domains, the KDC is the domain controller.

For example:

[realms]

ENTRUST.COM = {

       kdc = ig1.entrust.com

       kdc = ig2.entrust.com

   }

Make sure to enter the realm name in uppercase characters.

Note: The KDCs must be replicas of each other.

3.      Define how long in milliseconds that Kerberos waits for a KDC to respond before trying again. For example:

kdc_timeout=1000

4.      Define how many times Kerberos tries to contact a KDC before failing over to a backup. For example:

max_retries=3

5.      Save your changes.
