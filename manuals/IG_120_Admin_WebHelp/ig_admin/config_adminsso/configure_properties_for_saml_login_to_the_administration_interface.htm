IdentityGuard Server 12.0 Administration Guide

Configure properties for SAML login to the Administration interface

Several categories of Entrust IdentityGuard properties must be configured to enable SAML authentication to the Administration interface. The categories are:

●       Web Application Settings

●       SAML IDP Configuration

●       SAML SP Keystore Settings

●       SAML SP Keys Settings

To configure properties related to SAML authentication to the Administration interface

1.      Log in to the Entrust IdentityGuard Properties Editor.

Windows

a.      Select Start > All Programs > Entrust > IdentityGuard > Properties Editor.

b.      On the Log In page, enter your administrator name in Userid.

c.      Enter your password in Password.

d.      Enter a group name in the Group field.

e.      Click Log In.

f.        Complete the second-factor challenge, if presented.

UNIX

a.      Enter the URL of your Properties Editor web application in a Web browser. It has this form:

https://<hostname>:<port>/IdentityGuardPropertiesEditor

Where:

<hostname> is the host name you selected during configuration

<port> is the administration port you selected during configuration

b.      On the Log In page, enter your administrator name in Userid.

c.      Enter your password in Password.

d.      Enter a group name in the Group field.

e.      Click Log In.

f.        Complete the second-factor challenge, if presented.

2.      From the table of contents, click Web Application Settings (near the top) and configure the following properties:

●       SAML Single Sign-On Enabled — Set to True.

●       (Optional.) SAML Single Sign-On Login Auto-Redirect — Set to True if you want users to be redirected to the Federation Module’s SAML login page when they attempt to access the Administration interface. Set it to False to have a SAML Single Sign-On link appear at the bottom of the Administration interface’s login page. This link takes users to the Federation Module’s SAML login page. See How SAML login works with the Administration interface for details.

●       (Optional) Password Login Prompt — The default behavior (True.) is to have the password login prompt (user name and password text boxes) visible as a backup authentication method when a user cannot complete smart credential authentication. If you want to remove the password login prompt and have smart credential login as the only authentication method allowed, set this property to False.

3.      Also in the Web Applications Settings section, configure the following properties related to the Delegation Administrator you created in Create a delegation administrator.

●       Delegation Administrator User ID — Specify iginternalSAMLdelegate or whatever name you chose for the delegation administrator.

●       Delegation Administrator Password — Specify the password for the iginternalSAMLdelegate account. Select Encrypt to encrypt the password.

●       Delegation Administrator Password Length — Specify the maximum length of the password. This length is respected when the password is auto-updated. If you do not specify anything, the maximum length is the length specified in the Entrust IdentityGuard password policy.

●       Delegation Administrator Password Auto Update — Select True to have Entrust IdentityGuard generate a new delegation administrator password when the current one expires. If you set the password to Password Never Expires (when setting up the delegation administrator account), set the Delegation Administrator Password Auto Update setting to False.

●       Delegation Administrator Password Auto Update Interval — Specify the frequency, in seconds, with which the password is checked to see if it is close to its expiry. The password will be updated prior to expiry. The default is 3600 seconds (or 1 hour).

4.      Click Validate Only.

5.      From the table of contents, click SAML IDP Configuration (near the bottom), and configure the following properties:

●       Configuration Instances — Enter a name for the configuration.

Example: IDP Configuration.

●       IDP Metadata File Location — Specify the name and location of the Federation Module’s metadata file. For example, c:\IDPdata\idp.metadata.xml.

6.      If you have another Federation Module deployment with a metadata file that is different from the one you just specified, create another configuration instance, and specify the name and location of that metadata file.

Example:

You might specify another configuration instances called,

IDP Configuration 2

with a metadata file, here:

c:\IDPdata\idp2.metadata.xml

7.      Click Validate Only.

8.      Scroll to the next section in the Properties Editor, entitled, SAML SP Keystore Settings, and  configure the following properties:

●       SAML Keystore File Location — Specify the keystore file that contains the Entrust IdentityGuard Server’s SAML certificate and keys. See Generate a SAML certificate to be used by Entrust IdentityGuard Server for details. The default is <$IG_HOME>\etc\keystore. If you instead created a keystore dedicated to SAML keys, specify that keystore here.

●       SAML Keystore Password — Specify the password of the SAML keystore. If you are using Entrust IdentityGuard Server’s default keystore, <$IG_HOME>\etc\keystore, the password is entrust. If you created a new keystore dedicated to SAML keys, enter its password. Select Encrypt to encrypt the password.

●       SAML Keystore Type — Specify the format of the keystore used for the SAML keys. Supported types are: JCEKS, JKS, and PKCS12. The default is JKS, which is the type used for Entrust IdentityGuard Server’s keystore, <$IG_HOME>\etc\keystore.

●       Default Signing Key Alias — Specify the alias of the Entrust IdentityGuard Server’s SAML certificate and keys. This alias can be one of two things:

–  If you decided to re-use keys that already exist in the Entrust IdentityGuard keystore as your SAML keys, then use the alias tomcat.

–  If you decided to generate and import new SAML keys to be used by the Entrust IdentityGuard Server, use the alias that you used when you imported the keys. For example: igsaml. For details, see Generate a SAML certificate to be used by Entrust IdentityGuard Server.

9.      Scroll to the next section in the Properties Editor, entitled, SAML SP Keys Settings and configure the following properties:

●       Configuration Instances —  Enter the name for the Entrust IdentityGuard SAML keys, and then click Add. Example:

IG Server SAML Keys

●       Key Alias — Enter the same alias as specified under Default Signing Key Alias. Example: igsaml

This is the alias of the Entrust IdentityGuard Server’s SAML certificate and keys.

●       Key Password — Enter the password for the certificate specified under Key Alias. This password can be one of two things:

–  If you decided to re-use certificate and keys that already exist in the Entrust IdentityGuard keystore as your SAML keys, then use the password entrust.

–  If you decided to generate and import a new SAML certificate and keys to be used by the Entrust IdentityGuard Server, use the password that you specified when you imported the SAML certificate to the keystore using the keytool utility. If you did not specify a password for the certificate when you imported it, then enter the associated keystore password. If you are using the Entrust IdentityGuard Server’s default keystore, the password is entrust.

Select Encrypt to encrypt the password.

10.  Click Validate & Save.
