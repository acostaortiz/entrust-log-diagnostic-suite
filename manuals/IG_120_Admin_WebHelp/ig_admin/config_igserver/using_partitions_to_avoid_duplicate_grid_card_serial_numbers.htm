IdentityGuard Server 12.0 Administration Guide

Use partitions to avoid duplicate grid card serial numbers

To avoid duplicate grid card serial numbers that may result from repository replication, there are two solutions:

●       Pre-produce all grid cards in the primary Entrust IdentityGuard system (say Toronto). Ship all grid cards to the secondary location (say South America). If more grid cards are required, create them in Toronto and ship them to South America.

●       Set up partitions so that Entrust IdentityGuard administrators in Toronto and South America can create grid cards when they want.

The following instructions describe how to set up a partition so that grid card serial numbers are unique across all repositories. The instructions use Toronto and South America as the running example, with serial numbers in the range of 1 - 50,000. You can use your own partition names and serial number range.

To set up a partition to avoid duplicate grid card numbers

1.      Create two partitions and user groups as described in Creating partitions to avoid duplicate user numbers.

2.      Modify the partitions to allocate grid serial numbers:

●       Allocate grid serial numbers 1 to 50,000 to the first partition TorontoPartition.

●       Allocate grid serial numbers 50,001 to 100,000 to the second partition SouthAmericaPartition.

To modify a partition:

a.      On the primary Entrust IdentityGuard server, log in to the Master user shell. See Using the Master user shell.

b.      Before modifying the partition and allocating a range of grid numbers, check what the next global grid numbers are. Enter:

system get

Allocate grid numbers starting at this number. In this example, the next global grid number is 1.

c.      At the Master user shell prompt, enter

partition set <name> [-comment <comment>] -cardSerialNumbers -min <min> -max <max>

Examples:

partition set TorontoPartition -comment "grids for Toronto users" -cardSerialNumbers -min 1 -max 50,000

partition set SouthAmericaPartition -comment "grids for South American users" -cardSerialNumbers -min 50,001 -max 100,000

3.      Because you have associated the user group TorontoUsers with TorontoPartition and the user group SouthAmericaUsers with SouthAmericaPartition, the result is that users created in the TorontoUsers group associated with the TorontoPartition get grid serial numbers between 1 and 50,000 (the first user getting number 1, the second user getting number 2, and so on). Users created in the SouthAmericaUsers group associated with the SouthAmericaPartition get grid serial numbers between 50,001 and 100,000 (the first user getting number 50,001, the second user getting number 50,002, and so on).

This scheme ensure that there is no overlap in grid serial numbers.

4.      As you create pre-produced grid cards, you can add new ranges of grid numbers to each partition. To save time and effort later, assign relatively large ranges of serial numbers at the outset to avoid adding just a few more each time they run out.
