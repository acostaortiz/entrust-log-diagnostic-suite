IdentityGuard Server 12.0 Administration Guide

Limitations and restrictions

Operation of Entrust IdentityGuard in this scenario does impose some restrictions:

●       Second-factor authentication for administrators is not supported.

●       This feature is not used by the web-based Administration interface or any third-party integrations that use the Admin API. When these administration clients are used, you cannot run a completely session-free environment.

This implementation of the Web Services Security standard does not include the full standard, but only the portions required. If any required WSS elements are missing, or any unsupported elements are added, error messages are returned.

●       Entrust IdentityGuard supports the following standard elements in a WS-Security header: Timestamp and UsernameToken. Entrust IdentityGuard does not support digested passwords in the UsernameToken element.

●       Because only username and password can be passed into each Entrust IdentityGuard server, second-factor authentication for administrator login is not allowed if this feature is used.

●       For the same reason described above, changing an administrator's password cannot be combined with this feature. To change an administrator's password, the existing changePassword call should be used, supplying the administrator's ID, and old and new passwords.
