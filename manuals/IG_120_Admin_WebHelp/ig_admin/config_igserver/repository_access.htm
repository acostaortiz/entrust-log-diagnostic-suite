IdentityGuard Server 12.0 Administration Guide

Repository access

In the future, your organization may bring other subsidiaries in to this system to work in the same way as Dallas does. These other subsidiaries have requirements similar to those of Entrust IdentityGuard Dallas, but have no need to access the data for Dallas. For example, if Entrust IdentityGuard Jamaica is added to the mix, Entrust IdentityGuard Jamaica needs to know about some of the Toronto-based data (policies, for example), but has no need to access the data for Entrust IdentityGuard Dallas. However, Entrust IdentityGuard Toronto is still used to define groups for Entrust IdentityGuard Dallas that specify Dallas repositories and groups for Entrust IdentityGuard Jamaica that specify Jamaican repositories. These group definitions are visible to all Entrust IdentityGuard instances, so Entrust IdentityGuard Dallas can see groups that reference Jamaican repositories.

If Entrust IdentityGuard cannot find a definition of the repository it finds:

●       Entrust IdentityGuard writes a warning message to the logs during start up, noting the undefined repository.

●       Entrust IdentityGuard returns an error when it attempts to access data in groups for which the repository is undefined.

Your organization must define operational procedures to ensure that your servers do not access user data in such groups in places where the repository is not defined. As an example, Entrust IdentityGuard Jamaica should not try to access users in a group that points to the Entrust IdentityGuard Dallas database.
