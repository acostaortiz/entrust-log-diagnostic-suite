Running multiple load-balanced Entrust IdentityGuard servers

In a multi-server environment, it may not be possible to guarantee that all requests from a client application are made to the same Entrust IdentityGuard server. Almost all requests to the administration service must be authenticated, so a session-based authentication mechanism that relies on all client requests being made to the same server is not sufficient in such an environment.

To allow this scenario, Entrust IdentityGuard allows the inclusion of a user name and password in each call to each server to allow the administrator to be recognized by any server to which their requests may be sent.

Note: This operation does have a performance impact.

This functionality uses the Web Services Security (WSS) standard and requires that you do some programming in your client applications.

For information and examples of code for programming this functionality, see the Entrust IdentityGuard Programming Guide.
