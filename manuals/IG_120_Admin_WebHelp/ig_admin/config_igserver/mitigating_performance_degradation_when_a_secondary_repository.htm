IdentityGuard Server 12.0 Administration Guide

Mitigate performance degradation when a secondary repository is unavailable

If your Entrust IdentityGuard system uses multiple search bases or multiple repositories, you will see a performance degradation when a secondary search base or repository becomes unresponsive. To mitigate the performance impact, Entrust recommends that you configure a timeout for any secondary repository or search base. If the repository does not respond within the timeout window, the Entrust IdentityGuard Server tries the next repository or search base.

The timeout allows services to continue to operate, with limited functionality, until the underlying issue with the search base or repository is addressed.

Note: The Entrust IdentityGuard system does not allow any user to authenticate while the principal repository is down.

While it is operating with a secondary repository unavailable, the Administration interface provides limited functionality, and the following operations work:

●       find user accounts, except users on the unavailable repository

●       list unassigned cards and tokens

●       list assigned cards and tokens, except cards and tokens assigned to users on an unavailable repository

●       create cards, including cards for a group on an unavailable
repository

●       assign a card

●       list smart credentials

●       list unassigned smart credentials

●       list certificates

●       list digital IDs

The following operations do not work unless all repositories are available:

●       token load

●       smart credential load

●       user smart credential create or modify

●       user federation

●       repository update following a key update

To mitigate performance degradation when a secondary repository is unavailable

1.      Start the Entrust IdentityGuard Properties Editor. (See Log in or out of the Properties Editor.)

2.      On the Table of Contents, click JDBC Database Settings or LDAP Directory Server Settings, depending on which you are using, a database or a directory, to store user data.

3.      Set the Skip Repository During Search if not Available setting to True.

4.      Set the timeout interval (number of seconds) after which the unresponsive repository will be skipped. Set it to a low number to improve performance.

Using the Properties Editor, set or modify one of the following properties, depending on the type of repository used in your implementation. The following examples set the timeout to two seconds:

●       For IBM DB2, Microsoft SQL Server, or Oracle Database, under JDBC Database Settings, set the Database Login Timeout property to 2.

●       For PostgeSQL, add ?loginTimeout=2 to the JDBC Driver URL property (under JDBC Database Settings), to the end of the URL.

Example:

jdbc:postgresql://IGserver2:5432/identityguard?loginTimeout=2

●       For MySQL, add ?connectTimeout=2000 to the JDBC Driver URL property (under JDBC Database Settings), to the end of the URL.

Example:

identityguard.jdbc.url

●       For Microsoft Active Directory, Microsoft AD LDS, Novell eDirectory, or IBM Tivoli, set the LDAP Connection Timeout property (under LDAP Directory Server Settings) to 2000.

5.      Click Validate & Save.

6.      Log out of the Properties Editor and restart the Entrust IdentityGuard Server service after making all property changes.
