IdentityGuard Server 12.0 Administration Guide

Configure and administer WatchdataQRO tokens

WatchdataQRO tokens support only challenge-response operations.

To support token authentication with WatchdataQRO tokens, you must complete the following configuration steps:

1.      Configure Watchdata as a token vendor. See Configure a token vendor.

2.      If you have uninitialized WatchdataQRO tokens, create separate groups in which to store uninitialized and initialized token seeds. This helps prevent accidental assignment of an uninitialized token to a user. See Create groups for initialized and uninitialized tokens.

3.      Load the WatchdataQRO token data file. The procedure is the same as for other hardware tokens, except for the groups into which you load the token data if you are using uninitialized tokens.

4.      Configure token policies as described in Configuring token policies. There are no special policies for WatchdataQRO tokens.

5.      Configure self-registration for WatchdataQRO tokens.

6.      Configure self-administration for WatchdataQRO tokens.

7.      Initialize a WatchdataQRO token. Perform this procedure only if you have uninitialized tokens.

8.      If you are assigning tokens to users manually through the Administration, complete Assign WatchdataQRO tokens to users. (If you are using Self-Service Module, the tokens are assigned automatically, as described in the preceding self-service configuration procedures.)

9.      Deliver the tokens and initial PINS to users.

After the configuration is complete and users begin to use their WatchdataQRO tokens, most token administration actions are the same as for other tokens, with the following exceptions:

●       Unlock a WatchdataQRO token

●       Synchronization of tokens does not apply to this type of token as it does not have a clock or event counter.
