IdentityGuard Server 12.0 Administration Guide

Token set overview (using multiple tokens)

By default, a user account can have only one current token. To change this behavior so that a user can have any number of current tokens, you must assign each token to a different token set.

This topic describes how token sets work, and how they can be used.

How token sets work

After tokens have been assigned to a token set, tokens within the same set are related, and move through state transitions together, while tokens in different sets move through their state transitions independently. For example, if Alice has a current token in the ’GroupA Token’ set, and she loses this token, then you can assign her a new, pending token, also in the ’GroupA Token’ set. The pending token then moves to the current state when Alice first uses it to authenticate, and the current (lost) token moves to the canceled state. While these state transitions are occurring, Alice might have another token within a different set (for example, ‘Home Token’) that remains unaffected.

Why users might need multiple tokens

A single Entrust IdentityGuard user account might need multiple current tokens because:

•  the account is shared by multiple people, and each person needs their own token

For example, if the user account is used by a husband and a wife, you might call the husband’s token ‘John Token’, and the wife’s token, ‘Alice Token’.

•  the user wants to log in from different devices, and each device needs its own soft token

For example, if a user called Bob has two tokens, one on his phone and another hardware token, you might call the phone token ‘Bob’s Phone Token’, and the hardware token ‘Bob’s Hardware Token’.

How temporary PINs and PVNs work with multiple tokens

Temporary PINs and PVNs are issued for each account, not per token. This means that if two people share an account, such as a husband and a wife, then they can both log in with the same temporary PIN and must use the same PVN (if PVNs are enabled).

Using token names to restrict authentication

Another use for token sets is to restrict authentication. For example, you can set up your client application to allow authentications only from tokens within specific sets. For details on setting up your application to restrict authentications based on token sets, see the Entrust IdentityGuard Programming Guide for your platform language (.NET or Java).

Enabling multiple tokens per user through the token policy

By default, user accounts have only one token set. To allow multiple token sets, set the Maximum Number of Token Sets per User token policy, as described in Configure token policies.

Specifying a token set

A token set can be specified in any of the following ways:

–  through the Administration interface

To specify a token set when you assign or create the token, see Assign tokens to users (hardware tokens) or To create and activate a soft token using manual information entry (soft tokens).

To specify a token set after the token has been assigned, see Create or rename a token set.

–  through the Master User Shell

See the Entrust IdentityGuard Master User Shell Command Reference for details.

–  in bulk, for multiple users

See Assign tokens to users in a bulk operation, ensuring that your bulk file includes the set data item. For more on creating bulk files, see Create a bulk file.

–  through Self-Service, by the end-user

See the Entrust IdentityGuard Self-Service Module User Guide for details.
