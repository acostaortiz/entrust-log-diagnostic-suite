Instructions

Reset new tokens when they are created or activated

To avoid having token drift issues with new tokens, enable the Reset Token When Token is Created or Activated policy. This policy resets the time or event counter, or both (depending on whether you are using time-based or event-based tokens) on first authentication after the token is assigned to a user (for hardware tokens) or when it is created and activated (for soft tokens).

To configure token policies

Increase the allowable event or clock drift window within which users’ token responses are valid

By default, Entrust IdentityGuard automatically accommodates token event drift of up to 10 events, and clock drift up to 5 minutes. If it is common for your users’ event-based tokens to have the buttons pressed multiple times between authentications, or if it is common for your time-based tokens’ clocks to drift more than 5 minutes from the actual time, then you can set Entrust IdentityGuard to automatically correct for token drift greater than 10 events or 5 minutes. With a larger event or clock window, the need to synchronize tokens is reduced. (For more on synchronization, see the next table cell.)

To configure the size of the drift that is accommodated automatically

Fix token drift by synchronizing the token to the server

By default, if the token event drift exceeds 10 events, or the clock drift exceeds 5 minutes, then the token can no longer be used for authentication. To fix this problem, an administrator can synchronize the token. During a synchronize operation, the token’s event count or clock is synchronized with the one on the Entrust IdentityGuard server.

To fix minor drift by synchronizing the token

Fix token drift that I could not fix through a sync operation

By default, when an administrator synchronizes a token, Entrust IdentityGuard searches 100 future events, or an amount of time before and after the current time to find a token response that matches what the user entered. If the drift exceeds these amounts, the Synchronize Token operation does not work.

To fix this problem, you have two options:

·      Option 1: Increase the window of time or the number of events that Entrust IdentityGuard searches during a synchronize operation, and then try the synchronize operation again (this option works for tokens and soft tokens).

·      Option 2: Delete the token and create a new one (this option works for soft tokens only).

For Option 1, see To fix large drift by increasing the size of the event or clock window.

For Option 2, see Delete a token.
