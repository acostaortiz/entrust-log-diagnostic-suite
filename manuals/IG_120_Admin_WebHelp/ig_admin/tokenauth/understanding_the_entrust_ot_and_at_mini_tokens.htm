Understanding the Entrust OT and AT Mini Tokens

For each box of Entrust Mini Tokens you receive, you also receive an SDS file that contains data for each of the tokens in that box. After you load the SDS file into Entrust IdentityGuard, you can assign the tokens to users. The SDS file contains data used to calculate the token response.

For both the AT and OT tokens, if the token button is pressed more than 10 times without using a code for authentication, the token can no longer authenticate to Entrust IdentityGuard; it is out of synchronization.

Entrust IdentityGuard has a several ways to deal with tokens that are out of synchronization.

●       Increase the default event window: An administrator can reset the token (without supplying a token response from the user). This does not actually reset the token but will increase the default event window from 10 to 30. The next authentication attempt from the user would now allow a window of 30 events.

●       Reset the token: An administrator can reset the token, and also supply the token password received from the user. Entrust IdentityGuard will search for the token password value based on a pre-defined event window specified in the entrusttoken.conf file in the etc directory of the Entrust IdentityGuard installation. The parameter is resetEventWindow. This parameter sets the size of window to use when searching for a valid token password when performing a reset with the token response.

For more information, see Correct token drift (synchronizing a token).
