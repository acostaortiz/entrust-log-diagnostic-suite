Built-in key store management interface and alerting )

For installations that use the embedded Tomcat Java application server, this release simplifies the tasks related to managing certificates needed by Entrust IdentityGuard.
More...

These tasks include switching from a self-signed to a CA-signed certificate, updating certificates that are nearing expiry, and managing third-party certificates. In the Administration interface, the feature also warns you when certificates are nearing expiry or have expired.

Support for user access groups

This feature allows customers more options when they are trying to configure access control by group membership. More... 

Previously they could use only Entrust IdentityGuard groups. A new User Data policy, Maximum Number of User Access Groups, lets you specify the number of groups that users governed by the policy can belong to, and lets you specify the group names. The policy setting can be overridden for specific users, if required.

Send push authentication challenges to Entrust IdentityGuard mobile apps from the Administration interface

Typically, mobile soft tokens and mobile smart credentials receive authentication challenges from Web sites. This feature allows an Entrust IdentityGuard administrator to send a challenge to a user's mobile soft token or smart credential app on demand from the Administration interface. More...

This way, push authentication can be used in new scenarios, for example, to grant someone access to a building (like a badge) or to verify the identity of someone calling a help desk to reset a password or obtain account information.

Anonymous smart credential security challenges

This feature provides options for users to respond to smart credential security challenges without first entering a user name. More...

In the traditional security challenge feature, users browse to a protected web application, enter their user names and receive push notifications on their mobile devices. With anonymous security challenges, the web application no longer needs to prompt for a user name. Instead, it displays a QR code that the user scans and responds to with the smart credential app. Alternatively, users with physical smart credentials can authenticate  anonymous challenges using Entrust Entelligence Security Provider for Windows (version 10.0 Patch 206124 or later). After responding to the anonymous security challenge, the web application knows which user completed the challenge. This feature requires Entrust IdentityGuard Self-Service Module 12.0 and the Entrust IdentityGuard Mobile Smart Credential app version 3.1.

New properties support this feature:

Transaction Component and Callback Settings  - new property: Transaction Component External URL

Authentication Audit and Error Settings There are no new audits specifically for this feature, but administrators can get information about users who have authenticated using anonymous security challenges by enabling the Audit Successful Authentications setting.

For more information, see "Anonymous smart credential authentication" in the Entrust IdentityGuard Smart Credentials Guide.

Enhancements to detecting risk for adaptive authentication 

Entrust IdentityGuard uses device reputation data collected by using iovation SureScore™ to track whether that device has been involved in fraud or suspicious activity elsewhere. This integration adds another level of confidence that the user and device requesting authentication are legitimate.

Support for new Entrust Datacard branded hardware tokens )

This release expands support to a new set of Entrust Datacard hardware tokens comparable to existing Entrust tokens. More...

Entrust Datacard OT Token: An OATH-compliant, time-based token that is comparable to the Entrust Mini-token OT.

Entrust Datacard AT Token (coming soon): An OATH-derivative, event and time hybrid token that is comparable to the Entrust Mini-token AT.

Entrust Datacard CR Token (coming soon): An OATH-compliant, time-based token with support for OATH OCRA challenge/response and signature modes. It has a keypad and is PIN-protected. It is comparable to the Entrust Pocket Token and Entrust Flexi Token.

The new Entrust Datacard tokens are supported with the OATH token vendor configuration.

Support for TruCredential for smart card layout

Datacard TruCredential is the Entrust Datacard card enrollment and layout system. Entrust IdentityGuard makes use of TruCredential smart card design templates and layout editing features for those customers who want to design their own printable smart cards. More... n

New Entrust IdentityGuard installations should use Entrust Datacard TruCredential, which is sold, installed, and licensed separately from Entrust IdentityGuard. TruCredential replaces IDWorks (sales to be discontinued by mid-2017) and AlphaCard (for which no new licenses are available). Although IDWorks and AlphaCard will be supported for installed systems, consider switching to TruCredential for next-generation features and long-term support.

See "Smart cards" the Entrust IdentityGuard Smart Credentials Guide and more guidance in the Entrust IdentityGuard Print Module User Guide.

Support for issuing Windows TPM virtual smart cards

This release introduces support for issuing digital IDs to Microsoft Windows virtual smart cards running in the Trusted Platform Module (TPM) hardware available on some Microsoft Windows-based computers. Users derive the new credential from existing smart cards.

For more information, see "Derived smart credentials" in the Entrust IdentityGuard Smart Credentials Guide.

More secure activation of mobile soft tokens using Android Samsung TEE )

A new secure transfer activation mode allows Samsung Android devices to import the soft token seed in an encrypted form directly into the Samsung KNOX Trusted Execution Environment (TEE). This feature protects the soft token seed against compromised Android devices during the activation process. This feature requires Entrust IdentityGuard Self-Service Module 12.0, the Entrust IdentityGuard Mobile Soft Token app version 3.2 and a compatible Samsung device.

Enable activation and use of soft tokens in a TEE

Users could see a request to accept a TEE license, but otherwise they see no difference. There are no related updates in the help or user guide for the Entrust IdentityGuard Mobile Soft Token app.
