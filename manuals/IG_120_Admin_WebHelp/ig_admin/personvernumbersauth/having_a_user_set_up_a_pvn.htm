IdentityGuard Server 12.0 Administration Guide

Having a user set up a PVN

Using the Administration API, you can design your application so that new users supply their own PVN. The API applies the PVN rules set by policy. This removes the requirement for administrators to get involved in PVN creation and distribution and keeps the PVN confidential.

Note: The Radius proxy does not support the creation of new PVNs. If users access your application through a VPN, administrators must assign users their PVNs. PVN updates are supported through PAP only. (For details, on Radius protocols, see the Entrust IdentityGuard Installation Guide.)

Users who do not have a PVN when first challenged to supply one, can assign themselves a PVN. In order to do this, the user must first successfully pass the second-factor authentication challenge.

Consider the following scenario:

●       A user is required to provide a PVN value as part of grid authentication; however, one was not assigned by an administrator. The user is prompted to compose a numeric value of a specified length to use as the PVN.

●       During authentication, the user enters that number in the New PVN and Confirm PVN fields and enters the requested grid coordinates. Entrust IdentityGuard verifies the entries as follows.

–  If the grid response is correct and if the new PVN is valid, the user is assigned the new PVN value and the grid authentication succeeds. From then on, the user must provide a PVN with all future grid authentications.

–  If the grid response is incorrect, the new PVN is not assigned and the grid authentication fails. The user must try again.

–  If the grid response is correct but the new PVN value was not numeric or not the correct length, the new PVN is not assigned and the grid authentication fails. The user must try again.

This scenario applies to the token and OTP authentication methods as well.
