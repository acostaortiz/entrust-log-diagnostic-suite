Overview of the X-Frame-Options Directive settings

The X-Frame-Options Directive setting help to mitigate the risk of user interface redress attacks, also known as "clickjacking" on Entrust IdentityGuard administrative applications. Such attacks maliciously attempt to frame Web content to trick users into performing undesired actions by clicking on a concealed link.

To prevent this type of attack, an HTTP header directive named X-Frame-Options is used to either prevent all framing, prevent framing by external sites, or allow framing only by a specific site.

The X-Frame-Options token value, DENY, is applied to the Entrust IdentityGuard Administration interface and the Properties Editor by default. This stops any Web page from including these administrative Web applications inside a frame, which in turn helps prevent clickjacking.

If you want to run these administrative applications within frames, for example, as part of an administrative portal, you can change the default setting, as described in the procedures that follow.

However, you cannot eliminate this HTTP directive setting altogether. It must be one of DENY, SAMEORIGIN, or ALLOW-FROM. For more information about the X-Frame-Options Directive, see http://tools.ietf.org/html/rfc7034.
