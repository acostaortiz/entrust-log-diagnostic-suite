IdentityGuard Server 12.0 Administration Guide

Allow inexact answers

To allow for variations in user responses, you can create a word map file and apply its content to all user responses to questions. To allow for inexact answers and to use the word map file, select the Inexact Match Allowed for an Answer policy under the Knowledge-Based Q&A policy category. (See Configuring knowledge-based question policies.)

Whether this policy is selected or not:

●       case (“dr. jones” and “Dr. Jones” are both accepted.)

●       spacing (Additional spaces before and after do not cause failure.)

When this policy is selected (enabled), Entrust IdentityGuard allows differences in:

●       punctuation (“Dr.” and “Dr” are both accepted.)

Punctuation is removed before the comparison is made.

●       Special characters (“déjà vu” or “fiancé” are accepted as “deja vu” or “fiance”.)

Entrust IdentityGuard applies a character map to translate special characters to equivalent alphabetic characters.

When this policy is enabled, all special characters are ignored; symbols like @ and # are removed before the answer is checked. Encourage users to create answers containing only alphanumeric characters.

Attention: Any questions entered before upgrades from Entrust IdentityGuard 8.1 always requires exact answers regardless of the policy settings or the contents of the word map file. The comparisons are still case-insensitive, but leading and trailing spaces are ignored.

Plan to tune up the word map over time. Each time you uncover a common error, add it to the word map. See Edit the word map file.

Note: You must restart the Entrust IdentityGuard Server service for your word map changes to take effect.
