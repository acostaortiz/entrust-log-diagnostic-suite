IdentityGuard Server 12.0 Administration Guide

Heartbeat traps or ping traps

You can enable “heartbeat” pings and “heartbeat” traps, either separately or together.

If heartbeat pings are enabled, and heartbeat traps are not, each service generates a ping at intervals specified by the identityguard.snmp.heartbeat.interval property. If any one of the pings fails, an audit is generated.

If heartbeat traps are enabled, and heartbeat pings are not, a trap is sent at each interval specified in the identityguard.snmp.heartbeat.interval property. No pings are attempted.

The first heartbeat occurs only after the first interval period has expired. That is, when you start the server you must wait the duration of the interval period to see the first heartbeat. If the interval is too short, and the server startup is not yet compete, the server may not be ready to accept connections—this may cause a heartbeat ping failed trap.

Note that you might also see a heartbeat ping failed trap in the case of momentary network delays or similar problems, so it is recommended that you watch for multiple heart beat failure messages over some time period before concluding that there is a problem with the service.

Note: There is a possibility that some audits might not be trapped during system startup if they occur before the TrapManager has been initialized. Check the audit files for any audits that could occur during system startup.

If both heartbeat pings and heartbeat traps are enabled, each service generates a ping at each interval specified by the identityguard.snmp.heartbeat.interval property. The heartbeat traps are sent only when the ping is successful. If any of the pings fails, failure audits are generated. If SNMP Audit traps are also enabled, a trap is also sent on ping failure.

The URLs set in the following properties are used to direct the ping for each service.

●       identityguard.adminservice.url

●       identityguard.authservice.https.url

●       identityguard.webadmin.url

●       identityguard.preditor.url

Note: For the heartbeat ping feature to work, the SSL version of the authentication service must be running.

The audit trap and service heartbeat functionality is configured in the Properties Editor (see SNMP Settings).
