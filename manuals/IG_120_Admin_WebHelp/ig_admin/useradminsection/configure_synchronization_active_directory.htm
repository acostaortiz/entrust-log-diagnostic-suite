IdentityGuard Server 12.0 Administration Guide

Configure synchronization with Active Directory

Complete the following procedure to configure synchronization of Entrust IdentityGuard user information stored in a supported database with user account information in an Active Directory user repository. The following procedure describes how to set required properties in three properties categories.

To configure synchronization of Active Directory and Entrust IdentityGuard user accounts

1.      Log in to the Entrust IdentityGuard Properties Editor.

Windows

a.      Select Start > All Programs > Entrust > IdentityGuard > Properties Editor.

b.      On the Log In page, enter your administrator name in Userid.

c.      Enter your password in Password.

d.      Enter a group name in the Group field.

e.      Click Log In.

f.        Complete the second-factor challenge, if presented.

UNIX

a.      Enter the URL of your Properties Editor web application in a Web browser. It has this form:

https://<hostname>:<port>/IdentityGuardPropertiesEditor

Where:

<hostname> is the host name you selected during configuration

<port> is the administration port you selected during configuration

b.      On the Log In page, enter your administrator name in Userid.

c.      Enter your password in Password.

d.      Enter a group name in the Group field.

e.      Click Log In.

f.        Complete the second-factor challenge, if presented.

2.      From the table of contents, click LDAP Sync Container Mapping Settings (near the top) and configure the following properties:

Note: The container mappings are defined for the Entrust IdentityGuard system and can then be used with an LDAP directory instance configured for Active Directory synchronization.

●       Configuration Instances — Enter a configuration name in the empty field and click Add to configure a new LDAP synchronization container mapping. The instance name must not contain spaces or commas and should not be set to ROOT.

●       Name — Enter the exact name of a container defined in the Active Directory instance that you will use for Entrust IdentityGuard account synchronization. The name is relative to the context prefix defined in the LDAP URL property in LDAP Directory Server Settings. You do not need to enter the full URL. You can specify only one container, although it can include multiple levels (RDNs).

Example:

If the LDAP URL is

ldap://myldaphost.com:389/dc=AnyCorp,dc=com

you can enter

ou=Marketing.ou=people

Tip: If you are unsure about this value, it can be found in the ADSI Edit when connected to the Active Directory instance, as follows:
a. Select the container with the users you want to sync in the Active Directory instance, then right-click and select Properties.
b. In the Container Properties window, locate the distinguishedName attribute, double-click it.
c. In the String Attribute Editor, copy the container DN under Value, and then paste it into the Name field in Entrust IdentityGuard.

Note: If the value contains any non-ASCII characters, they must be encoded using the RFC2253 standard string format. You can use a UTF conversion tool such as the one found at this location: http://macchiato.com/unicode/convert.html. Output should be specified at UTF-8, Base 16.

3.      From the table of contents, click LDAP Directory Server Settings (near the top) and configure the following properties related to this feature:

Select a property to see its description

Configuration Instances

Lists all current LDAP directory configurations. Initially, a default configuration exists if you selected a directory repository during installation.

To create a new instance, enter a unique name in the empty field and click Add.

When you create a second or subsequent LDAP repository, it inherits the property values defined for the default LDAP repository.

To delete an instance, select it in the list and click Remove.

  

LDAP URL

identityguard.ldap.url

Provides the URL used to connect to the LDAP directory. This can include a port number and initial context prefix to bind to. Encode spaces in the URL as %2. All lookups are relative to the given context prefix.

Syntax:

<ldap_server_URL>:<port>/<search_base>

Where:

<ldap_server_URL> is the URL to your LDAP directory, including the ldap:// or ldaps:// prefix

<port> is the LDAP port. The port is optional if you are using the default port (389 for LDAP; 636 for LDAPS)

<search_base> is the search base to connect to. For more information, see Using a search base.

For example

ldap://myldaphost.com:389/ou=People, dc=AnyCorp,dc=com

binds to port 389 on the computer myldaphost, with ou=People,dc=AnyCorp,dc=com as the context prefix.

You can enter multiple URLs separated by spaces as part of a high-availability setup. For the default instance, the initial value is set during configuration.

LDAP Vendor

identityguard.ldap.vendor

Sets the type of LDAP repository being used to store users. This setting is required if users that are disabled in the LDAP repository are to be automatically suspended in Entrust IdentityGuard. The LDAP directory vendor is also required if you want to be able to automatically extract user contact information directly from the repository.

Note: When you select an LDAP vendor, you enable features that let you manage disabled and expired user accounts (if supported by the selected vendor). To explicitly disable the these features, you must set the Repository Data policies to False. For more information, see Repository Data policies.

Note: If you are using the Active Directory synchronization with an Entrust database feature (which means that the LDAP Directory Specific Usage property is set to SYNC), Active Directory is the only supported vendor.

The choices are:

–  Not specified

–  Active Directory

–  ADAM/AD LDS

–  CA Directory

–  eDirectory

–  OpenLDAP

–  Oracle

–  Red Hat

–  Sun ONE

–  Tivoli

–  UnboundID

–  Custom

Default: Not specified

 Active Directory is the only choice officially supported for this feature.

Directory Administrator

identityguard.ldap.principal

Names the user entity binding to the LDAP directory set during configuration, for example:

cn=Directory Manager

This user must be able to add and remove object classes and attributes from all entries in the repository.

Default: If you are setting up a custom Configuration Instance and you do not specify this property, it defaults to the value used by the default Configuration Instance.

  

Directory Administrator Password

identityguard.ldap.credentials

Provides the password of the directory administrator entered during configuration. By default, the password is encrypted.

Depending on your directory password policies, this password might expire and need to be updated. See Update the directory password.

Default: If you are setting up a custom Configuration Instance and you do not specify this property, it defaults to the value used by the default Configuration Instance.

LDAP Sync and User Enrollment Search Filter

identityguard.ldap.sync.filter

This setting is used for any Active Directory synchronization request, not just for enrollment. If user synchronization is used or user enrollment is enabled, this property is used to locate potential users in the directory, in particular, when synchronizing Entrust IdentityGuard users or creating new ones during enrollment. This filter is used only when Entrust IdentityGuard users are stored in a database repository.

This setting is optional.

If user enrollment is enabled, this filter is used to locate potential user entries in the LDAP repository when creating new Entrust IdentityGuard users.

If the Add User Object Class property is True, the base filter used by Entrust IdentityGuard is:

(&(<useridattribute>=*) (!(objectclass=entrustIG*)))

If the Add User Object Class property is False (which is the default when used with Active Directory), the base filter used by Entrust IdentityGuard is:

(&(<useridattribute>=*) (!(entrustIGUserInfoMac=*))(!(entrustIGGlobalPolicy=*))(!(objectclass=group)))

Your filter, which is combined with the base Entrust IdentityGuard filter, could be something like:

objectclass=inetOrgPerson

For details about creating filters, see Create a user synchronization custom static filter.

Note: If there is an error in this filter, user enrollment is disabled, however, synchronization  continues. The filter is not used for synchronization..

Default: filter not used

 (optional)

Paging Supported

identityguard.ldap.supportsPaging

Allows paging of enrollment entries in the Administration interface display.

If you are enabling User Enrollment on an Active Directory repository, set this property to True.

Otherwise, leave this property set to False.

Default: False

 True (paging is supported in Active Directory)

Disabled Account Attribute

identityguard.ldap.accountDisabledAttribute

Sets the LDAP directory attribute and value to interpret as meaning the user is disabled.

Choose one of the following options. See Suspend disabled and expired LDAP users for more information about how these options are interpreted.

–  Vendor Default, use the default mapping for the directory specified in LDAP Vendor, if a default exists.

–  ibm-pwdAccountLocked (Tivoli), use the IBM Tivoli way of determining if a user is disabled.

–  loginDisabled (eDirectory), use the eDirectory way of determining if a user is disabled.

–  msDS-UserAccountDisabled (ADAM/AD LDS), use the ADAM/AD LDS way of determining if a user is disabled.

–  nsAccountLock (Sun ONE/Red Hat), use the Sun ONE way of determining if a user is disabled.

–  orclIsEnabled (Oracle), use the Oracle way of determining if a user is disabled.

–  userAccountControl, use the Active Directory way of determining if a user is disabled.

–  Custom, specify an attribute and value to interpret as meaning the user account is disabled. This field contains an attribute and value in the following form: attribute;value_meaning_disabled

Where:

attribute is the name of the LDAP directory attribute to check to find out if the user is disabled. The attribute name is not case sensitive.

value_meaning_disabled is optional. If provided, it is the value of the attribute that means the user is disabled. If the attribute is multi-valued, the first value returned is checked for a match. If this value matches the <value_meaning_disabled> parameter in this property, the user is treated as being disabled.

Also, if value_meaning_disabled is not provided, the existence of the named attribute is interpreted as the user being disabled.

Default: Vendor Default

 Vendor Default. Only Active Directory attributes are officially supported for this feature.

Expired Account Attribute

identityguard.ldap.accountExpiredAttribute

Sets the LDAP directory attribute and value to interpret as meaning the user is expired.

Choose one of the following options. See Suspend disabled and expired LDAP users for more information about how these options are interpreted.

–  Vendor Default, use the default mapping for the directory specified in LDAP Vendor, if a default exists.

–  accountExpires (AD/ADAM/AD LDS), use the AD/ADAM/AD LDS way of determining if a user is expired.

–  loginExpirationTime (eDirectory), use the eDirectory way of determining if a user is expired.

–  orclActiveEndDate (Oracle), use the Oracle way of determining if a user is expired.

–  Custom, specify an attribute to interpret as meaning the user account is expired.

When you select Custom, you must enter an attribute, which is the name of the LDAP directory attribute to check to find out if the user account is expired. The attribute name is not case sensitive, but it must have a GeneralizedTime syntax.

Note: If this property is not used, and the directory vendor configured for the search base has no rules for determining whether the user is expired, then all users will be treated as not being expired.

 Vendor Default. Only Active Directory attributes are officially supported for this feature.

If the Full Name Attribute property is not set, then no full name mapping is applied.

If you are using the Active Directory synchronization feature with an Entrust IdentityGuard database, user the Active Directory displayName attribute.

 Enter the Active Directory displayName attribute.

Apply Contact Info Mappings

identityguard.ldap.applyContactInfoMappings

Specifies a comma-separated list of LDAP contact information mappings to apply to this LDAP instance. The mappings are case-sensitive.

The mappings are applied in the order in which they are listed in the property, so choose their order carefully.

For example, if multiple contact information mappings map to the same contact information label, only the first mapping is applied. Contact information mappings are defined in the LDAP Contact Info Mapping Settings properties group.

Note: It is recommended that you configure the mail and telephoneNumber contact info mappings. When the mappings are configured, you can enter mail,telephoneNumber for this setting.

For more information, see Map contact info from an LDAP directory.

 (optional) It is recommended that you configure the mail and telephoneNumber contact info mappings. When the mappings are configured, you can enter mail,telephoneNumber for this setting.

LDAP Directory Specific Usage

identityguard.ldap.subtype

Identifies a special usage for this LDAP directory.

Options are:

–  NONE – Use for all cases except when this LDAP directory is used for synchronizing users with an Entrust IdentityGuard database.

–  SYNC – Use this option when the LDAP directory is used for synchronization of an Active Directory repository with an Entrust IdentityGuard database

Note: Currently, the only supported vendor for user synchronization is Active Directory. Other values can be used, but they are not officially supported.

Note: If this property is set to SYNC, then the Repository setting Sync Repository Implementation Class  must be set to Directory Synchronization with IdentityGuard Databases. The directory can be used only for synchronization and not any other purpose.

Default: NONE

 SYNC. When this property is set to SYNC, then the Repository setting Sync Repository Implementation Class  must be set to Directory Synchronization with IdentityGuard Databases.

LDAP Sync Unique User ID

identityguard.ldap.sync.uuid

Note: Only the default value for this property is officially supported in this release.

Specifies the LDAP user attribute used to uniquely identify the user being synchronized from this LDAP directory.

This value is used in conjunction with the User ID Attribute (identityguard.ldap.userid), which is used to map the LDAP user to the Entrust IdentityGuard user name.

Values other than the default can be used, but they are not officially supported. To specify another value, enter the value followed by an optional semi-colon type (binary or string), for example: sAMAccountName;string or someBinaryAttr;binary.

Note: This property is used only with the Active Directory synchronization feature.

Default: objectGUID

  

LDAP Sync Audit Successful Notifications

identityguard.ldap.sync.audit.success

Sets whether Entrust IdentityGuard generates audit messages when a successful LDAP sync notification with a user occurs. Set to true to have the system generate these audit messages.

Note: This property is used only with the Active Directory synchronization feature.

Default: False

 (optional)

LDAP Sync Background Thread Enabled

identityguard.ldap.sync.notifications.enabled

Specifies whether to propagate updates from this LDAP directory to Entrust IdentityGuard using a background thread.

The Active Directory notification mechanism uses AD Notify (also known as LDAP persistent searches).

All Active Directory notification updates for users that are synchronized in Entrust IdentityGuard are applied, including the sync last date. This is true regardless of whether the actual data that Entrust IdentityGuard is synchronizing has been changed. When new Active Directory users are added, Entrust IdentityGuard produces a new audit message.

Note: When using the Active Director synchronization feature, the Entrust IdentityGuard primary server should have this property enabled to allow synchronization to be handled in the background. This property should not be enabled on replica servers if their Entrust IdentityGuard databases replicate information between the primary and replica servers.

Note: If this property is not enabled, user synchronization occurs only when users are created and on-demand by an administrator.

Note: This property is used only with the Active Directory synchronization feature.

Default: False

 True

LDAP Sync Apply Container Mappings

identityguard.ldap.sync.applyContainerMappings

Specifies a comma-separated list of LDAP container settings to apply to this LDAP instance. The mappings are case-sensitive. They represent LDAP containers that will receive notification updates for this LDAP directory instance.

The list of containers is based on the mappings selected. LDAP sync container mappings are defined in LDAP Sync Container Mapping Settings. Notification updates from the LDAP directory are sent only for the mapped containers, not for all entries of this configured LDAP searchbase.

An Entrust IdentityGuard background thread is used to process the notification updates.

The default is an empty setting, which means that a container mapping is not selected and the root container of this LDAP directory configuration is used. If the root container of this LDAP directory configuration itself requires notification updates (in addition to other containers within root), the container mapping name ROOT should be included as an entry in the comma-separated list.

Note: This property is used only with the Active Directory synchronization feature.

Default: no value

 Active Directory notification must be configured explicitly for each container.

The following properties are also used by this feature, but their default settings are appropriate for most implementations. Select a property to read its description.

Primary Directory Server Maximum Reconnect Interval

identityguard.ldap.ha.maxrestoretimeout

Sets the maximum time in hours between attempts to reconnect to the primary directory (the first directory URL defined) when the current in-use directory is not the primary. Use this as part of a high-availability setup.

Default: 24

Directory Server Connection Test Interval

identityguard.ldap.ha.testInterval

In a high-availability setup where directory connections are pooled, this sets the time in seconds to wait between tests to see if a directory connection is still valid. A setting of means the directory is tested each time it is pulled from the pool.

Default: 0

SSL LDAP Connection

identityguard.ldap.sslEnabled

Specifies if you are using a secure (SSL) connection to the directory. If set to True, make sure the URL in the LDAP URL property refers to a secure port (such as 636).

Default: False

Disable SSL Host Name Verification

identityguard.ldap.disableSslHostnameVerification

If you are using a secure (SSL) connection to the directory, set this to False. This should be True only for debugging purposes because True creates a security risk.

Default: False

Enable SSL Block Ciphers

identityguard.ldap.enableSslBlockCiphers

Determines whether or not to use SSL block ciphers. If False, SSL connects to LDAP using stream ciphers. Set this property to True if your directory server doesn't support stream ciphers for SSL.

Default: False

LDAP Connection Timeout

identityguard.ldap.connecttimeout

Sets the time in milliseconds to wait for a directory connection operation to complete before returning an error.

Default: 3000 (3 seconds)

LDAP Search Timeout

identityguard.ldap.searchtimeout

Sets the time in milliseconds to wait for a directory search operation to complete before returning an error. A setting of means no timeout occurs.

Default: 3000 (3 seconds)

LDAP Maximum Search Limit

identityguard.ldap.sizelimit

Sets the maximum number of LDAP entries to return in a single search operation.

Set this property to a value that is less than or equal to your Server Administrative Size Limit.

Default: 1000

Connection Pool Maximum Size

identityguard.ldap.connectionpool.max

In a high-availability setup, sets the maximum number of connections that can be kept in the LDAP directory connection pool.

An Entrust IdentityGuard service does not open more connections to the directory than this value.

Default: 50

Connection Pool Maximum Wait Time

identityguard.ldap.connectionpool.maxWait

Sets the maximum time in milliseconds to wait when attempting to get a directory connection from the pool.

Default: 30000 (30 seconds)

Idle Connection Minimum Close Time

identityguard.ldap.connectionpool.minIdleCloseTime

Sets the minimum number of milliseconds a pooled connection can be idle before being closed. This property works closely with the Idle Connections Check Time property.

Default: 180000 (3 minutes)

Idle Connections Check Time

identityguard.ldap.connectionpool.closeSchedule

Sets the number of milliseconds between each check for idle LDAP directory connections. Connections idle longer than the value set by the Idle Connection Minimum Close Time property are closed at each check.

A setting of means connections are never closed when idle.

Default: 180000 (3 minutes)

Include Subseconds with Generalized Time

identityguard.ldap.GeneralizedTimeWithSubSecs

Some LDAP directories do not support generalized time attributes that contain subseconds (1ths of a second), while other directories require them. If this value is set to True, generalized time is formatted with subseconds. Make sure this to False for a Novell eDirectory. The correct setting is made during installation.

Default: True

LDAP Sync Number of Worker Threads

identityguard.ldap.sync.numthreads

Specifies the number of worker threads that handle LDAP sync updates during background synchronization from this LDAP directory.

Note: This property is used only with the Active Directory synchronization feature.

Default: 5

LDAP Sync Maximum Updates Queue Size

identityguard.ldap.sync.maxupdatesqueuesize

Specifies the maximum number of LDAP sync updates that can be queued during background synchronization from this LDAP directory. When the queue is full, the oldest updates are deleted.

Note: This property is used only with the Active Directory synchronization feature.

Default: 10000
