IdentityGuard Server 12.0 Administration Guide

Roles overview

Entrust IdentityGuard includes several built-in roles that you can assign to new administrators after the initial installation or upgrade. By associating roles with administrators, you define what operations they can perform in your organization’s Entrust IdentityGuard system. (You also assign roles to the administrator used by client applications to access the Administration API.)

During system testing or for a moderate-sized deployment, the initial roles may be all you need. When deploying Entrust IdentityGuard in organizations with many users, you may want to define additional administrator roles tailored to your unique situation.

You create and manage roles using the Roles pages of the Administration interface. When an administrator logs in to the Administration interface, the interface only displays operations that the logged in administrator has permission to perform with their assigned roles. When a client application accesses the APIs directly, it can access only those API classes and methods that its administrative permissions allow.

You should create your initial policies and groups, if needed, before you create your initial roles. See Initial administration workflow. If you need custom roles, create them before you create new administrators (or edit those administrators later to assign the new roles).
