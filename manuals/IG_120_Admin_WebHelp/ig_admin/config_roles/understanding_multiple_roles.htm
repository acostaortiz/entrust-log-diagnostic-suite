IdentityGuard Server 12.0 Administration Guide

Understanding multiple roles

The roles discussion in Understanding roles applies to administrators who have a single role. While this is most often the case, it is possible to assign multiple roles to an administrator. Do this if you want one administrator to have different permissions for different sets of users within the system. For example, you may want an administrator who can view all users in the system, but can only modify users in a particular group. You would do this by creating two roles and assigning them to the administrator:

●       Role 1 would allow viewing of all users.

–  It would have a list of permissions that allows viewing of users, and any other data that should be viewable. This would include userGet, and may include userCardGet and others.

–  The list of groups would be set to the All groups value.

–  The role list may or may not be empty, depending on whether or not you want to allow viewing of administrators as well as users.

●       Role 2 would allow modification of users in a particular group. Use the useradmin role as a template.

–  It would have a list of permissions that allows modifying users.

–  The list of groups would be set to just the group of the users that can be modified.

While multiple roles result in very flexible administration capabilities, using them introduces complexity in terms of figuring out which operations an administrator can perform and what they can perform them on.

Some complicated rules come in to play when an administrator (operation administrator) with multiple roles tries to perform an operation on a target administrator with multiple roles. In this case, the operation administrator must have a single role that:

●       grants the relevant permission for the operation being performed

●       has a group list that includes the target administrator's group

●       has a role list that includes all of the target administrator’s roles

For example, suppose the operation administrator has two roles A and B. Role A has a role list which grants access to roles X and Y, and role B has a role list which grants access to roles X and Z. If the target administrator has roles Y and Z, then the operation administrator cannot operate on the target administrator. While the operation administrator does have a role that grants access to role Y and a role that grants access to Z, the operation administrator does not have a single role that grants access to both Y and Z.

These conditions (permissions, groups and roles) must be satisfied by a single role, not by a collection of assigned roles.
