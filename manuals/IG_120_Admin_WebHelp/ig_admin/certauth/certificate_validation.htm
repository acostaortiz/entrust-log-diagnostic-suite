IdentityGuard Server 12.0 Administration Guide

Certificate validation

There are two basic tests to be met in determining whether certificate authentication passes; the certificate must be valid, and the certificate must be registered to the user.

In the case of RBA certificate authentication, the RBA policy settings determine the conditions that define successful authentication—and whether the certificate must be valid or registered or both.

These two tests can be used together or separately.

Certificate validation follows these rules:

●       It must be a certificate.

●       The certificate must be in its validity period.

●       Depending on policy, the certificate may have to be issued by a registered CA certificate. If this policy is set, and the certificate was not issued by a registered CA certificate, validation fails.

●       If a registered CA certificate is found, it must be in the active state and must be allowed for the user as defined by the Certificate policy Allow User Certificates Signed by Registered CAs.

●       Depending on policy, self-signed user certificates may not be allowed. If this is true and the certificate was self-signed, validation will fail.

●       If the certificate was issued by a registered CA certificate, the certificate signatures must be valid up to the root.

●       If the certificate was issued by a registered CA, all of the CA certificates up to the root CA must be in their validity period.

●       CA certificates must have the keySignature key usage set.

●       Non-root CAs must have the basicConstraints extension set to true.

●       User certificates must have the digitalSignature or nonRepudiation key usage set.

●       If the registered CA certificate defines LDAP or OCSP (Online Certificate Status Protocol) parameters, the user certificate and CAs must not be revoked according to that revocation source.
