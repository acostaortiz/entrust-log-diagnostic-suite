To configure the policies governing certificate authentication, complete the following procedures:

●       To set the authentication types policies for certificate authentication

●       To set the certificate authentication policies

To set the authentication types policies for certificate authentication

Note: Perform this procedure only if you are setting up explicit certificate authentication. You do not need to do  it if you are using certificate authentication as part of risk-based authentication.

1.      Log in to the Entrust IdentityGuard Administration interface as the administrator.

On the Windows computer where Entrust IdentityGuard is installed

●       Select Start > All Programs > Entrust > IdentityGuard > Administration Interface.

On UNIX or from a remote client

●       Enter the URL of your Administration interface web application in a Web browser. It has this form:

https://<hostname>:<port>/IdentityGuardAdmin

Where:

<hostname> is the host name you selected during configuration

<port> is the administration port you selected during configuration

If you cannot find the correct URL, see Locate your Administration interface URL.

or other login scenarios, see

2.      Click Policies.

3.      From the list of policies that appears on the List Results screen, select the policy to modify.

4.      On the View Policy screen, select Authentication Types from the Policy Category drop-down menu.

5.      Check that Certificate appears in the list of authentication types for Normal Security Authentication Types and Enhanced Security Authentication Types.

6.      If Certificate is not in the list, click Edit Policy.

7.      Select Certificate in the Not Included list.

8.      Click the right arrow between the Not Included and Included list boxes to move Certificate to the Included list box.

9.      Click Save Changes.

Hash Algorithm

Sets the hash algorithm used by the client when calculating the response to a certificate challenge.

The choices are:

–  SHA-256

–  SHA-1

–  MD5

Default: SHA-256

Note: This policy is used only for explicit certificate authentication.

Challenge Size

This is the length of the challenge in bytes.

Default: 32 bytes

Note: The minimum value allowed for this policy is 32, and the maximum is 1000.

Note: This policy is used only for explicit certificate authentication.

Disable Challenge Retention

Enable this setting if you want to replace the certificate challenge (namely, the data to be signed by the user) each time a challenge is requested. Users who answer (sign) a challenge incorrectly will have a new challenge presented to them for the next attempt.

Deselect it if you want to retain the challenge for the duration of the Certificate Challenge Lifetime. Users who answer a challenge incorrectly will have the same challenge presented to them for all subsequent attempts until they are locked out or until the challenge lifetime is exceeded. After the challenge lifetime is exceeded, a new challenge is presented.

Default: No

Certificate Challenge Lifetime

Set it to Unlimited to have the certificate challenge last an unlimited amount of time.

Set it to a number of seconds to limit the lifetime. If it is not answered in the lifetime, a new challenge is generated.

Default: Unlimited

Update Lockout for Replaced Challenge

When set to Yes, the lockout count is increased when a certificate challenge is replaced because:

–  a user does not answer a certificate challenge in the allotted time (as defined by the Certificate Challenge Lifetime setting) causing a new challenge to be requested by the client application

–  a user restarts the client application without answering the certificate challenge, causing a new challenge to be requested by the client application

When set to No, the lockout count is not increased in the above-mentioned scenarios.

Note: The lockout count is always increased when a user enters an incorrect challenge response, regardless of how you configure this setting.

Default: Yes

Allow Identity Assured Authentication

Specifies whether security challenges for authentication can be delivered to the mobile smart credential app.

For more information, see "Mobile smart credentials" in the Entrust IdentityGuard Smart Credential Guide.

Default: Yes

Allow Identity Assured Transaction Verification

Specifies whether security challenges for transactions can be delivered to the mobile smart credential app.

For more information, see "Mobile smart credentials" in the Entrust IdentityGuard Smart Credential Guide.

Default: Yes

Allow Identity Assured Signing

Specifies whether security challenges for digital signing can be delivered to the mobile smart credential app.

For more information, see "Mobile smart credentials" in the Entrust IdentityGuard Smart Credential Guide.

Default: Yes

Disable Certificate Policy OID Check

Specifies whether Entrust IdentityGuard checks the policy certificate object IDs (OID) in a certificate.

By default, when Entrust IdentityGuard performs certificate validation against a smart credential digital ID (when a user performs a smart credential login to Self-Service or an Identity Assured operation), it checks to ensure that the certificate contains one of the PIV OIDs associated with the card holder digital ID. This ensures that the card digital ID is not being used for these operations.

Set this policy to Yes to disable this check. Disabling the check is required when, for example, Entrust IdentityGuard is configured so that the PIV OIDs are not included in the card holder digital IDs of the users.

Default: No

Allow Self-Signed User Certificates

Specifies whether self-signed certificates can be registered against a user. Self-signed certificates do not have corresponding CA certificates, so validation does not include revocation checking.

Default: No

Allow User Certificates Signed by Unregistered CAs

Specifies whether non-self-signed certificates can be registered when they are not issued by a Registered CA.

Default: No

Allow User Certificates Signed by Registered CAs

Specifies a list of Registered CAs from which signed user certificates are allowed. If this policy is used, a user can have only certificates issued by the Registered CAs selected (highlighted) in this list.

This list of CA certificates is active only if Allow User Certificates Signed by Any Registered CA is not selected.

Allow User Certificates Signed by Unmanaged CAs

When set to Yes, this policy setting permits certificate authentication as part of risk-based authentication (RBA) with user certificates signed by unmanaged CAs.

When enabled, this policy setting has the same effect as the following 3 settings.

–  Allow Self-Signed User Certificates = No

–  Allow User Certificates Signed by Unregistered CAs = No

–  Allow User Certificates Signed by Registered CAs = No registered CAs are allowed

When set to No, this policy setting overrides the 3 settings described previously, so certificate-based RBA requires that users have certificates signed by a Managed CA and is not permitted with user certificates signed by unmanaged CAs.

Default: Yes

Allow User Certificates Signed by Managed CAs

Specifies a list of Managed CAs from which signed user certificates are allowed. If this policy is used, a user can have only certificates issued by Managed CAs that are selected (highlighted) in the list.

This list of CA certificates is active only if Allow User Certificates Signed by Any Managed CA is not selected.

Maximum Number of Certificates Per User

Use this policy to place an upper limit on the number of number of certificates each user can have.

You might want to limit the number to limit the repository space each user requires for their certificates.

Default: 10

Automatically Delete Old User Certificates

Enable this policy to automatically delete the least recently used certificates when new user certificates are registered during authentication.

Certificates are deleted only if the user already has the maximum number of certificates allowed when the new one is added.

When certificates are deleted, deletions start with the least recently used expired certificates, followed by the least recently used certificates that have not expired.

Default: Yes

8.      Click Save Changes.
