Note: Grids, tokens, temporary PINs, and one-time passwords can also include a personal verification number. Second factor authentication using a mobile soft token does not use a PVN or a PIN (however, the app may be protected by a PIN if any of its soft token identities requires one). Only PAP supports PVN updates.

Instead of a grid or token response, a user can enter a temporary PIN.

You can choose NULL to skip first-factor authentication. However, it is recommended that if you choose NULL, an application-specific first-factor method is used to perform first-factor authentication. For example, configure the VPN server to perform first-factor authentication.

Only PAP supports password updates. Only PAP supports the cell replacement feature of Entrust IdentityGuard grids, one-time passwords, and temporary PINs; CHAP and MS-CHAP do not. The cell replacement feature allows certain characters to replace other characters. For example, “x” can replace “X”, and “B” can replace “8.”

For knowledge-based authentication, only a single question and answer are valid through the Radius proxy. The answer must be an exact match for CHAP and MS-CHAP.

You can also configure mutual authentication with the serial number replay feature of grids and tokens; image replay is not supported through the Radius proxy.

The Entrust IdentityGuard Mobile Soft Token app can be used for second-factor authentication. The app receives an authentication challenge and the user can respond by selecting Confirm in the app (if the device is connected to the Internet, which is online mode) or by entering the security code generated by the app (classic mode).
