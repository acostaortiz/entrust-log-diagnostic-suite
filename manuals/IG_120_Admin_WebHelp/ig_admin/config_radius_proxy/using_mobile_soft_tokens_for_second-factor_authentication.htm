Using mobile soft tokens for second-factor authentication

Users can perform second-factor authentication using mobile soft tokens (in the Entrust IdentityGuard Mobile ST app) in two ways:

●       by manually entering the OTP generated by the app in the requesting Web page (this is sometimes called "classic mode"), or

●       by selecting the Confirm button on an authentication challenge (this is sometimes called "online mode"). For online mode, Entrust IdentityGuard uses a form of transaction verification and make use of the Mobile Transaction Verification Service. In this case, the authentication challenges do not include any transaction details.

Note: To perform authentication transactions, mobile soft tokens require a Transaction Verification with Soft Tokens license (in addition to the Soft Tokens license). For more information, see Managing licenses.

The online mode of mobile soft token authentication uses the following properties, which are described in the context of procedures later in this section.

●       Radius Proxy configuration properties:

–  Radius Proxy Callback Host 

–  Radius Proxy Callback Port 

–  Callback Queue Check Interval 

–  Number of Callback Worker Threads 

For these properties, default settings will be appropriate for most implementations. For details about these properties, see Configuring the Radius proxy configuration, Step 5

●       VPN Server Configuration properties:

–  Use MST TVS for Token Authentication – Set to True to use this type of second-factor authentication.

–  MST TVS Online Fallback – Set to True by default when the previous property is True.

–  Default MST TVS Online Token Challenge Summary Message – You can enter a custom message or use the default message.

–  TVS Callback Response Timeout - You may need to adjust the value of this property based on the timeout constraints imposed by the VPN server you are using.

For more information about configuring these properties, see To configure VPN connections, Step 33.
