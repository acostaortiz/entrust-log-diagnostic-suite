Reading VPN challenge strings

The token challenge string is the most complex because it is the only one to use all eight parameters. This section explains the token challenge string by breaking the message syntax into its component parts. After you understand the token challenge string, the other three challenge string types are easy to understand. See also

●       Token challenge string

●       Grid challenge string

●       OTP challenge string

●       Q&A challenge string

The message is constructed in the order in which the parameters are organized. The parameters work together to build meaningful sentences.

The syntax and default content for the token message is:

Enter

{3, choice, 0#| 1# your PVN and}

{4, choice, 0# a response from your Entrust IdentityGuard Token| 1# your temporary PIN}

{5, choice, 0#|1# with serial number {0} or {1} or your temporary PIN|2# with serial number {0} or {1}|3# with serial number {0} or your temporary PIN|4# with serial number {0}}

{7, choice, 0#.|1# using the token challenge {2}.}

{6, choice, 0#|1# You must also update your PVN twice in succession.}

This is how to interpret it:

●       Parameter 3 deals with a PVN. If a PVN is required, it must be entered first, so parameter 3 begins the message. It has two choices:

0 - 0 indicates that no PVN is required. For the default token message above, no text is displayed.

1 - indicates that a PVN is required. In the default token message above, the following text is displayed: “your PVN and”. (This makes sense when combined with the rest of the parameters.)

●       Parameter 4: There are two choices:

0 - the user has a token, so begin to ask for the user to enter token information.

1 - the user does not have a token, so ask for a temporary PIN instead.

●       Parameter 5 continues the message creation where parameter 4 left off. It has five choices:

0 - the user only has a temporary PIN, so display no text.

1 - the user has two tokens (current and pending), and a temporary PIN, so ask the user to enter a response from a token with one of two serial numbers or to enter a temporary PIN.

2 - the user has two tokens (current and pending), but no temporary PIN, so ask the user to enter a response from a token with one of two serial numbers.

3 - the user has either a current or pending token and a temporary PIN, ask the user to enter a response from the token matching the given serial number or to enter a temporary PIN.

4 - the user has either a current or pending token, and no temporary PIN, so ask the user to enter a response from the token matching the given serial number.

●       Parameter 7 applies to challenge-response tokens only. It has two choices:

0 - there is no token, or the token is only a response-only token, so end the sentence with a period

1 - the token is a challenge-response token, so present the token challenge supplied by Entrust IdentityGuard, and end the sentence with a period.

●       Parameter 6 deals with PVN updates. It has two choices:

0 - a PVN is required for authentication, but does not need updating. The message is complete.

1 - a PVN is required for authentication and it needs updating, so ask the user to enter a new PVN value twice.

●       Parameters {0}, {1}, and {2} are used as placeholders for token-related values.

There are many possible messages that Entrust IdentityGuard can generate for tokens using the default syntax.

Here are two scenarios:

●       Assume the user is new and has a temporary PIN, no token and no PVN. In this case, the message would be brief:

Enter your temporary PIN.

●       Assume the user has two challenge-response tokens (current and pending), a PVN that needs updating, but not a temporary PIN. In this case, the message would span two sentences and include substitutions for serial numbers and the token challenge:

Enter your PVN and a response from your Entrust IdentityGuard Token with serial number 0753886898 or 0753886899 using the token challenge 52535488. You must also update your PVN twice in succession (PVN size: 6).
