IdentityGuard Server 12.0 Administration Guide

Digital ID policies

These policies set the parameters for digital IDs.

Digital IDs, which include one or more certificates can be used in the following ways:

●       They can be encoded on mobile devices to allow VPN access and digital signing. For more information, see Mobile-enrollment-for-digital-IDs.

●       They can be encoded on physical or software (mobile) smart credentials to enable a number of usage scenarios—from certificate authentication to Web-based applications to signing of authentication, transaction and digital signing challenges with mobile smart credential.

Cancel Digital IDs When User is Deleted

When set to Yes, this policy indicates to revoke the certificates in the user’s digital ID if the user is deleted from Entrust IdentityGuard. After certificates are revoked, they can no longer be used for cryptographic operations such as authentication and securing email. (New certificates can be generated for the user, if need be.) You can revoke certificates through Security Manager Administration.

Default: Yes

Deactivate Digital ID in CA When Digital ID is Deleted

Indicates whether Entrust IdentityGuard automatically deactivates a user's digital ID after the user is deleted from Entrust IdentityGuard.

After a digital ID is deactivated, it can no longer be used for cryptographic operations such as authentication and securing email.

Default: No

Remove Digital ID From CA When Digital ID is Deleted

Indicates whether Entrust IdentityGuard automatically removes a user's digital ID after the user is deleted from Entrust IdentityGuard.

After a digital ID is removed, it cannot be restored.

Default: No

Maximum Number of Digital IDs per User

Indicates the maximum number of digital IDs a user is allowed to have. You may want to allow users to have multiple digital IDs if they have multiple devices, such as a mobile device, a laptop, and a smart card. These devices would each need a separate digital ID for network access. For secure email digital IDs, the user’s digital ID must be shared across devices so that each device can decrypt the same email.

Default: 6

Maximum Number of Client Types per Digital ID

A client type is any piece of information set by an Entrust IdentityGuard client and passed to Entrust IdentityGuard server. For example, the Self-Service Module sets the client type to a particular brand of mobile device. This policy can then limit the number of devices on which a single digital ID can be enrolled.

The client type values set by the Self-Service Module are: android, blackberry, blackberryTablet, iOS, windowsPhone. These values are listed in the Device Type Value property, available in the Self-Service Module’s Configuration interface, under Properties > Digital ID Device Type Settings.

Default: 3

Allow All Digital ID Configs

Select this option to allow all Digital ID configurations to be available for this policy.

Clear this option if you want to use only specific Digital ID configurations you select in the Allowed Digital ID Configs list.

Default: Yes

Allowed Digital ID Configs

This policy indicates which digital ID configurations can be used by Entrust IdentityGuard. Generally, set this to All Digital ID Configs, unless you want to restrict digital ID configurations to specific groups of users. If this is the case, you must set up different user groups (say Mobile and Smart Credential), and create separate policies for each. One policy would have the mobile digital ID configuration enabled, while the other would have the smart credential digital ID configuration enabled.

Default: All Digital ID Configs.
