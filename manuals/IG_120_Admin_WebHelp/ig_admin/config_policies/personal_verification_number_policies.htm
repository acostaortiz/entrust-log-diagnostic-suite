IdentityGuard Server 12.0 Administration Guide

Personal Verification Number policies

These policies enable and control PVNs.

Where a policy does not require a PVN for an authentication method, this can be overridden for authentication through VPN if the PVN Required property is enabled (see VPN Server Configuration (19)).

Personal Verification Number (PVN) Length

Sets a value between 1 and 255 for the length of the PVN.

Default: 4

PVN Lifetime

Sets a PVN lifetime to force users to update their PVN at the next login once the PVN lifetime is achieved.

Set a lifetime value in days.

Default: unlimited (the PVN never expires)

Note: The PVN lifetime is applied to all PVNs created the policy change is made. You must use a bulk operation to apply the policy change to PVNs created before the update, see Managing PVNs in bulk.

Authentication Types Requiring a PVN

This lists all the authentication methods for which users can be asked to provide a PVN. It can be one or more of: GRID, OTP, TOKEN (Response-Only), TOKEN (Challenge and Response).

Where:

–  GRID authenticates with a card.

–  OTP presents out-of-band authentication (a one-time password provided to the user).

–  TOKEN (Response-Only) authenticates using a dynamic password generated by a response-only token.

–  TOKEN (Challenge and Response) authenticates using a dynamic password generated by a challenge-and-response token.

If an authentication method is not in the "Included" list, the PVN is optional. That is, if you ask for PVN on your login page and the user supplies one, it will be validated. However, if the login page does not ask for a PVN (or it asks for one but the user does not provide it), the authentication will still succeed.

If you use different kinds of tokens (for example, hardware tokens and soft tokens), you can require PVNs for some types and not for others. To do so, use the All Token Vendors Require a PVN and Token Vendors Requiring a PVN options.

All Token Vendors Require a PVN

When this option is selected, all users must enter a PVN to use their tokens.

Select this option to have the use of all tokens protected by a PVN. This setting is recommended for hardware tokens and for software tokens that do not use a PIN as an additional layer of protection.

Clear this option if you want the PVN requirement to apply only to tokens from specific vendors that you select in the Token Vendors Requiring a PVN list. Typically, PVNs are not used to protect Entrust IdentityGuard soft tokens (mobile or desktop) because the soft tokens are already protected by a PIN.

Default: Yes

Token Vendors Requiring a PVN

From the list, select the token vendors for whose tokens you want users to enter a PVN. This option is editable only when All Token Vendors Require a PVN is set to No (check box is cleared).

Change Required on Administrator Reset

This determines if the administrator can enable or disable the PVN Change Required option for a user. Select it to always force the user to update the PVN when the administrator creates a new one. Disable it to allow the administrator to choose to force an update or not (see Forcing PVN updates).

Default: Yes
