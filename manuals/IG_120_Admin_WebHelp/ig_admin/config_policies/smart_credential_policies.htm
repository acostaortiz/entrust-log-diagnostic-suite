IdentityGuard Server 12.0 Administration Guide

Smart Credential policies

The smart credential policies define how smart credentials are handled in the IdentityGuard system.

Unassign Smart Credential When Deleted

When you remove a user, or remove the smart credential object from their user account, this parameter determines whether their smart credentials are deleted or unassigned.

Yes indicates their smart credentials are unassigned, and No indicates their smart credentials are deleted. When a smart credential is unassigned, its serial number is returned to the pool of unassigned serial numbers, where it is available for re-encoding. If you delete a smart credential, the smart credential serial number becomes permanently available.

Note: For mobile smart credentials, this setting is ignored because the smart credential is always deleted (never unassigned). Upon deletion of a mobile smart credential, a license is freed up for use by someone else.

Default: Yes

Cancel Non-Shared Certs When Smart Credential is Deleted or Unassigned

If the user has two smart credentials with the same first name and last name, those different smart credentials may share the same encryption certificate.

This setting specifies whether shared certificates should be canceled (revoked) when a smart credential is deleted or unassigned. The options are:

Yes — Cancel non-shared certificates; do not cancel the shared ones.

No — Do not cancel non-shared certificates.

Default: Yes

Cancel All Certs When Smart Credential is Deleted or Unassigned

Specifies whether all certificates associated with the smart credential should be canceled (revoked), even the ones that are shared with other smart credentials.

Yes — Cancel all certificates, even the shared ones.

No — Do not cancel all certificates.

Default: No .

Delete Digital IDs When Smart Credential is Deleted

Specifies whether Entrust IdentityGuard digital IDs should be deleted when a smart credential is deleted

Default: No

Move Smart Credentials To User's Group During Assignment

When smart credentials are loaded, they are assigned to a particular group. When assigning the smart credentials to users, the smart credential’s group and the user’s group may not match.

Select this policy to automatically move smart credentials from their current group to the group of the user during assignment.

When this policy is set to No, a mismatch of the user group and the smart credential group results in an error message.

Default: No

Maximum Number of Smart Credentials per User

Specifies the number of smart credentials a user is allowed.

Default: 3

Smart Credential ID Prefix

Each smart credential has an ID. Each smart credential ID is prefixed with two uppercase letters.

This policy specifies the two uppercase letters used to prefix each smart credential ID. If you use smart credentials for ePassports, the first two characters are associated with a country.

Default: ET

Allow All Smart Credential Definitions

Select this option to allow all smart credential definitions to be available for this policy.

Clear this option if you want to use only specific smart credential definitions you select in the Allowed Smart Credential definitions list.

Default: Yes

Allowed Smart Credential Definitions

Specifies all the smart credential definitions that can be assigned to a user.

You might want to use this setting if you have different groups of users that need different smart credentials. For example, one group might need PIV smart credentials, while another group might need X509 smart credentials. In this case, you would create two Entrust IdentityGuard groups, and assign separate policies to each, called ’PIV policy’ and ’x509 policy’, for example. The PIV policy would have Allowed Smart Credential Definition set to the PIV definition, while the X509 policy would have it set to the X509 definition. The result is that when administrators enroll a user through the Enrollment Module (or Administration interface) and specify the user’s group, they will only be presented with the PIV or X509 definition corresponding to the selected group.

If no smart credential definitions exist, this policy defaults to All Definitions.

Default: All Definitions

Auto Register Smart Credentials in Physical Access Control System

Specifies whether smart credentials are automatically registered in the PACS at the same time they are encoded.

If Yes, smart credentials are automatically registered in the configured PACS when the smart credential is encoded. If No, an administrator must manually register the smart credentials in the PACS.

For information about using smart credentials with PACS, see "Physical smart credentials" in the Entrust IdentityGuard Smart Credentials Guide.

Default: Yes

Auto Suspend Smart Credentials in Physical Access Control System

Specifies whether smart credentials are automatically suspended in a physical access control system (PACS) when you delete a smart credential (or a user with a smart credential) from Entrust IdentityGuard.

If Yes, smart credentials are automatically suspended in the configured PACS. If No, an administrator must manually suspend smart credentials in the PACS.

For information about using smart credentials with PACS, see "Physical smart credentials" in the Entrust IdentityGuard Smart Credentials Guide.

Default: Yes

Allow Software Smart Credentials

Specifies whether smart credentials can be stored on software, or if smart credentials must always be stored on a hardware device such as a token or card.

If Yes, smart credentials can be stored on software. If No, smart credentials must always be stored on a hardware device.

Default: Yes

Smart Credential Soft Token Vendor

Specifies the vendor for smart credential soft tokens that can be assigned to a user.

Default: No default

Mobile Smart Credential PIN Prompt

Specifies when the Mobile Smart Credential app prompts for a PIN.

Select Session to have the PIN prompt displayed only when the user opens the Mobile Smart Credential app. The app can be used until it is closed or the app session reaches the Mobile Smart Credential Session Timeout threshold.

Select Transaction to have the PIN prompt displayed whenever the user fetches a challenge using the Mobile Smart Credential app. For example, if the user fetches an authentication challenge, and subsequently fetches a transaction challenge, they will be prompted for their PIN twice.

Default: Session

Mobile Smart Credential Session Timeout

The time, in minutes, after which a user must re-enter a PIN to resume using the app. When the timeout is reached, the app will not lock; instead, the user will be required to re-enter a PIN the next time they fetch any kind of challenge, be it an authentication, security, or transaction challenge. This setting only takes effect if Mobile Smart Credential PIN Prompt is set to Session.

Default: 5

Mobile Smart Credential Allow Unsecured Device

This setting applies only to mobile smart credential on iOS or Android devices.

Specifies whether smart credential identities can be created and used on unsecured devices. A device is considered to be unsecured if it has been rooted (Android) or jailbroken (iOS).

In previous releases, the mobile smart credential app would not run on unsecured mobile devices. With  Entrust IdentityGuard Server Release 11.0 or later and app version 3.1 or later, the app always starts, but a user cannot activate new identities on an unsecured device unless this policy is set to Yes. For more information, see "Set policies for mobile smart credentials" in the Entrust IdentityGuard Smart Credentials Guide.

Default: No

Mobile Smart Credential Allow Fingerprint Authentication

Applies only to mobile smart credentials on iOS devices that support Touch ID.

Specifies whether smart credential authentication can be authorized using the iOS Touch ID feature (fingerprint authentication) instead of a PIN.

Default: No

Change PIN After OTA Activation

Specifies whether the Entrust IdentityGuard Mobile Smart Credential app prompts users to change their PIN after they activate the smart credential over the air (OTA).

Default: No

Expiry Notification Enabled

Specifies whether Entrust IdentityGuard will send email notifications to users when certificates in their smart credentials are nearing expiry. This policy can be set independently for different groups of users. End users cannot override this group policy.

Default: Yes

Minimum Time Between Expiry Notifications

Specifies the minimum time, in minutes between emails sent to users to remind the of imminent expiration of a particular smart credential.

Default: 1440 minutes (1 day)

Number of Expiry Notifications

Specifies the maximum number of notifications sent to user whose smart credential is nearing expiry and must be re-encoded. The minimum is 1 notification and the maximum is 1000. The last message is a special final notification message that states "This is your final notification."

Note: If an Administrator increases the number of notifications after a user has received a final notification, the user may receive further notifications.

Note: End users might receive further notifications regarding a certificate of a different type after the smart credential was updated. For example, it the smart credential update creates new verification certificates, they might be notified about an encryption certificate approaching expiration.

Default: 3

Expiry Notification Certificate Lifetime Percentage

Specifies the percentage of the certificate lifetime that must elapse before an expiry notification is sent to a smart credential user. The value must be between 1% and 100 percent.

Note: The renewal period never begins sooner than 100 days before expiration, regardless of the certificate lifetime. For example, for a certificate with a lifetime of 365 days, after 70% of the lifetime elapsed (256 days), 30% of the lifetime would remain (109 days). However, the notifications are not sent until only 100 days of the certificate lifetime remain.

Note: After their smart credential has been updated, an end user might continue to receive expiry notifications if the update did not create a new encryption certificate. To prevent that, increase the expiry notification certificate lifetime percentage from its default of 70%, so that the encryption certificate will have entered its update period before any expiry notification for the verification certificates is issued.

Default: 70

Allow Server Side Smart Credentials

Specifies whether smart credentials in the form of an Entrust profile (EPF) or Roaming profile can be imported into Entrust IdentityGuard and then managed with Entrust IdentityGuard. Server-side smart credentials can be used for Identity Assured operations (authentication challenges, transaction verification and digital signing). For more information, see the Entrust TruePass to Entrust IdentityGuard Migration Guide.

Default: No

Allow Registered Smart Credentials

Specifies whether smart credentials in the form of an Entrust profile (EPF) or plastic smart card can be registered with Entrust IdentityGuard. The smart credential continues to be managed outside of Entrust IdentityGuard, but it can be used for Identity Assured operations (authentication challenges, transaction verification and digital signing). For more information, see the Entrust TruePass to Entrust IdentityGuard Migration Guide.

Default: No
