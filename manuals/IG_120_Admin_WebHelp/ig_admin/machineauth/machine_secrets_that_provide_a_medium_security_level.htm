Machine secrets that provide a medium security level

In this scenario, the client machine stores a machine secret indefinitely and returns it during each authentication.

Enable the policy attribute for creating a machine nonce but not for the sequence nonce. Have the application supply at least one set of application data. The following table shows the machine secret settings for this level of security.

Machine Secret Policy

Value

Sequence Nonce Required

Not set

Machine Nonce Required

Set

Application Data Elements Required

1

With these settings, this is what happens:

●       When a user first registers for machine authentication, the application generates and passes the application data to Entrust IdentityGuard as part of a machine authentication request. Entrust IdentityGuard generates a machine nonce to create the machine secret. It stores the machine secret and application data in the repository and returns a copy of the machine secret (machine nonce only) to the application. The application stores the machine secret on the client computer.

●       The next time the user logs in, the application passes the stored machine secret and newly generated application data to Entrust IdentityGuard as part of a machine authentication request. Entrust IdentityGuard compares them to those stored in the repository. If they match, machine authentication succeeds.

During authentication, Entrust IdentityGuard expects a machine nonce and application data. Failure to provide these causes an error. Failure also results from too much bad application data, though this can be moderated by the Bad Application Data Elements Allowed policy.

You can leave application data out of this scenario (that is, just use the machine nonce) but that provides a lower level of security.
