IdentityGuard Server 12.0 Administration Guide

Unassigned, deleted, valid, active, expired, and superseded grids

Other terminology related to states is described below.

For readability, ‘grid card’ is used to refer to any of the authenticator types. Where distinctions must be made, the specific authenticator type is mentioned.

The following table describes grid card state terminology.

Term

Definition

Active

An active grid card is one that is in the Current or Pending state.

Deleted

A deleted grid card is one that an administrator has deleted from the system. Deletion removes the grid card completely from Entrust IdentityGuard. It cannot be re-assigned.

Expired

An expired grid card is one whose expiry date has passed.

When an authenticator expires, it is not automatically placed in the Canceled state; an administrator must cancel it manually.

superseded

A superseded grid card is a grid card in the Current or Hold state whose owner has been issued a newer grid card in the Pending state. As soon as the newer, pending grid card is used for authentication, it becomes current and the superseded grid card is canceled.

A user can continue to use a superseded grid card for a period of days set by policy. This period takes effect the moment a grid card becomes superseded by a pending grid card. For more information see Card policies.

Note: Tokens and soft tokens do not have a superseded date.

Unassigned

Though this is not considered a state, the administrator can unassign grid cards or tokens. (Soft tokens cannot be unassigned; they can only be deleted.) Unassigning a grid card or token from a user moves it back into the preproduced pool of grid cards (or into the list of unassigned tokens). An unassigned grid card or token can be assigned to the same user again or to another user.

Valid

A valid grid card is one that has not yet expired or been superseded.
