IdentityGuard Server 12.0 Administration Guide

Administrator overview

Administrators manage the day-to-day activities of application users.

When you install Entrust IdentityGuard for the first time, you are given the option to create the first administrator. This administrator is created with the superuser role. This administrator can create other administrators and new roles. The superuser can also assign any role to any administrator.

If you do not create an administrator during installation, you must create at least one administrator using the Master user shell. Assigning this administrator the superuser role allows that administrator to create other administrators and assign them any built-in role or new role. For information about creating the first administrator with  the user create command, see the Entrust IdentityGuard Master User Shell Reference ).

You should create your initial policies, groups and roles, if needed, before you create administrators other than the first administrator. See Initial administration workflow.

Any existing administrator with the appropriate permissions can create another administrator. When you create administrators, you assign each of them one or more of the existing roles. Every capability administrators have or do not have is governed by their assigned roles. (See Entrust IdentityGuard roles overview.) The roles specify:

●       what permissions the administrator has

●       what groups of users the administrator can manage

●       what policies the administrator has access to

●       a list of other roles the role has access to—this controls which roles and which other administrators the administrator can manage

Administrators authenticate themselves to the Administration interface and the Properties Editor using a user ID and their default password. If you want administrators to log in using their LDAP repository password instead, you can configure the First-Factor Authentication Type to be External. See Administration policies.

Entrust IdentityGuard allows administrators and users to have multiple passwords for authentication. This facilitates the use of named passwords for different access points; however, the Administration interface accepts only the default password. (See Password authentication overview for more on named passwords)

You can also assign second-factor authentication methods, a card, for instance, if you have enabled multifactor authentication for administrators (see Basic policy settings). Password requirements applied to administrators are derived from the password policy settings of the administrator’s group. Also seeConfiguring password authentication policies.

Entrust IdentityGuard administrators can access the Administration interface and manage users, cards, tokens, policies, roles and many other features through it. Entrust IdentityGuard administrators can also access the Properties Editor (if they have the propertiesSet permission).

Client applications also use administrator accounts to log in to Entrust IdentityGuard to access its Administration API. These administrator accounts need to be created and managed.

Note: An administrator user ID consists of both the name and the group the administrator belongs to. If you do not choose a group name and the user name is unique, Entrust IdentityGuard finds the correct group; otherwise it returns an error.

Administrators cannot perform the following tasks; these require a master user working in the Master user shell:

●       initialize Entrust IdentityGuard

●       upgrade Entrust IdentityGuard

●       bind or unbind the master keys

●       update master keys

●       view or set the next card serial number

●       view or change partition information

●       view or change audits-to-database parameters
