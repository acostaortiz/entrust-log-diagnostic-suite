IdentityGuard Server 12.0 Administration Guide

Audits to Database Configuration

You can configure a new database, or use an existing database, to contain the audit data generated by operations performed in Entrust IdentityGuard. You can choose to send all your audit data to the database, or just a subset.

Because this kind of data can grow to unmanageable levels very quickly, you can also set the parameters for an audit removal routine that automatically archives old audit data.

For more information about setting up a database for collecting Entrust IdentityGuard audits, see Configure an audit database.

Audit Database Name

identityguard.audit.database.name

The name of the database to which to write audits. If there is no name, audits are not written to a database.

There may be multiple databases being used for other Entrust data. You can set up your audits to go to one of the databases used for other Entrust IdentityGuard data, or a database set up specifically to store the audits.

Default: No database

Write Audits to Database

identityguard.audit.database.enabled

If True, audits are logged to the database.

Set this property to False to prohibit writing audits to a database, or to discontinue writing audits to a database.

Default: False

Note: If you would like to continue to be able to read audits from your database, but you want to stop writing new audits to the database, leave Audit Database Name set to your audit database name, and set Write Audits to Database to False.

Audit Database Filter

identityguard.audit.database.filter

A comma-separated list of audit codes that will be written to the database. If no value is specified, or if there are errors in this list, all audits are logged.

This filter can be one audit code or a range of audit codes. Some examples:

•  -100 (all audit codes <= 100)

•  200-300 (all codes between 200 and 300)

•  1000- (all audit codes >= 1000)

•  -100, 200-300,1000- (all audit codes <= 100, between 200 and 300 inclusive, or >= 1000)

All audits that match any one of the specified filter values are written to the database.

Note: Do not use the “AUD” audit code prefix in the filter expression. It must contain only numeric values.

Audit Queue Is Blocking

identityguard.audit.database.blocking

Entrust IdentityGuard maintains a queue of audits waiting to be written to the database. This setting controls the behavior of this queue.

If True, requests to Entrust IdentityGuard are blocked until space becomes available in the audit queue.

If False, the oldest audit in the queue is removed when the queue is full. This frees up space in the queue, ensuring that requests to Entrust IdentityGuard are not blocked.

Default: True

Audit Removal Enabled

identityguard.audit.database.cleaner.enabled

If True, audits older than the age specified in Audit Removal Age property are automatically deleted.

If you do not turn on the cleaner by setting this property to True, then the rest of the properties in this table are unavailable in the Properties Editor.

Default: False

Audit Removal Interval

identityguard.audit.database.cleaner.interval

The interval, in hours, between checks for old audit records to delete.

The audit cleaner is run for the first time after the Audit Removal Interval has elapsed.

Note: This counter restarts at system startup.

This property must be a positive integer. If an invalid value is specified, the default is used.

Default: 24

Audit Removal Age

identityguard.audit.database.cleaner.age

The age (in days) of the oldest records you want to keep in the audit database. Older audits will be deleted.

This property must be a positive integer. If an invalid value is specified, the default is used.

Note: The Audit Removal Interval counter restarts at system startup, so you may have audits that are older than you expect in your database if Entrust IdentityGuard was restarted just before a cleaning, for instance.

Default: 180 (approximately 6 months)

Audit Removal Export Enabled

identityguard.audit.database.cleaner.export.enabled

If True, audits being removed are exported to an archive directory.

Default: True

Audit Removal Export Directory

identityguard.audit.database.export.dir

When you delete the old audit records from your database, Entrust IdentityGuard archives them. You can delete them later, when you are sure you do not need them.

This property is the path name of the directory to which the deleted audit records are exported.

If you do not specify a path, Entrust IdentityGuard exports the deleted records to the following default location:

•  On Windows <$IG_HOME>\export\audits

•  On UNIX $IG_HOME/export/audits
