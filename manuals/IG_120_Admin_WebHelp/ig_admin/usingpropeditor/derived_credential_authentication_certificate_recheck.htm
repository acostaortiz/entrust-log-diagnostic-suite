IdentityGuard Server 12.0 Administration Guide

Derived Credential Authentication Certificate Recheck

These properties control the feature that checks the revocation status of the PIV Authentication certificate that is used to authenticate a user when that user creates a derived mobile smart credential. The certificate is validated before the derived mobile smart credential is created, but these properties enable Entrust IdentityGuard to perform periodic rechecks. If a recheck finds that the certificate has been revoked, Entrust IdentityGuard can use these property settings to revoke the Digital ID in the derived mobile smart credential and delete the smart credential from Entrust IdentityGuard.

For information about configuring this feature, see "Configure rechecking of certificate revocation status" in the Entrust IdentityGuard Smart Credentials Guide.

Derived Credential Authentication Certificate Recheck Enabled

identityguard.derivedcredential.recheck.enable

This property enables or disables the Derived Credential Authentication Certificate Recheck. Set to True to have Entrust IdentityGuard check whether certificates issued by a managed CA have been revoked and then take action as configured in the other properties in this section. The default is False.

Revoke Digital ID

identityguard.derivedcredential.recheck.revoke

This property specifies whether the Digital IDs in the derived smart credential will be revoked if the certificate that authenticated the user when the derived smart credential was created is subsequently revoked. If True, the Digital IDs will be revoked. The default is False.

Delete Derived Smart Credential

identityguard.derivedcredential.recheck.delete

This property specifies whether the derived smart credential will be deleted from Entrust IdentityGuard if the certificate that authenticated the user when the derived smart credential was created is subsequently revoked. When a smart credential is deleted, Entrust IdentityGuard policy determines whether the Digital IDs will be revoked. If True, the derived smart credential will be deleted. The default is False.

Maximum Recheck Period

identityguard.derivedcredential.recheck.maxdays

This property specifies the maximum number of days after a derived smart credential has been issued during which IdentityGuard will delete the derived credential or revoke its Digital IDs if a recheck finds that the PIV Authentication certificate has been revoked. After the configured number of days, Entrust IdentityGuard only audits the fact that the certificate is revoked.

Note: This property has no effect on a derived credential before it has been issued. This value must be seven days or more. The default is seven days.

Start Time

identityguard.derivedcredential.recheck.start

This property specifies the local time of day at which the Derived Credential Authentication Certificate Recheck will start, using a 24 hour clock (hh:mm:ss). By default the recheck operation begins at midnight.

Stop Time

identityguard.derivedcredential.recheck.stop

This property specifies the local time of day at which the Derived Credential Authentication Certificate Recheck stops, using a 24 hour clock (hh:mm:ss). By default, it stops at 06:00:00 (hh:mm:ss).

Wait Time

identityguard.derivedcredential.recheck.days

This property specifies the number of days the Derived Credential Authentication Certificate Recheck process waits before it repeats the search for invalid derived smart credential authentication certificates. The default is 1 day. If set to zero, the recheck runs continuously between the configured start and stop times.

Priority

identityguard.derivedcredential.recheck.priority

This property specifies the priority at which the Derived Credential Authentication Certificate Recheck will run. The options are: Normal Priority, Maximum Priority, and Minimum Priority. The default is Minimum Priority.

Maximum Rate

identityguard.derivedcredential.recheck.maxrate

This property specifies the maximum rate at which Entrust IdentityGuard fetches users from its repository to recheck whether their derived mobile smart credential authentication certificates have been revoked by the issuing CA. The rate can be set to a value that corresponds to the capabilities of the repository. The default value processes users at a rate no greater than 10 per second, on average.
