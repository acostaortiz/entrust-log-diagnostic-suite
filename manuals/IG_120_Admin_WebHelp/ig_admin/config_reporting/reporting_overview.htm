IdentityGuard Server 12.0 Administration Guide

Reporting overview

Reporting is a powerful tool that you can use to get information about your Entrust IdentityGuard deployment. It is designed to zoom in on current information about specific groups of users, audits, or authentication types, based on search criteria and the personal queries feature. Reporting makes use of the same data repositories used by your production IdentityGuard system.

Entrust IdentityGuard allows you to create reports to help you get a snapshot of your current repository details. Use the built-in report templates to create reports for all the Entrust IdentityGuard data types. No database is required (except for creating audit reports). You can generate reports to display detailed information about users, authentication methods, and audits.

Reports and their associated report information files are stored in the file system used by the Entrust IdentityGuard server. This means that the reports are not included in Entrust IdentityGuard backups, so you must set up your own procedures for backing up the report storage directories.

You can generate reports from the Administration interface and from the Master user shell. From the Master user shell, you generate reports using options in the list command. See the Entrust IdentityGuard Master User Shell Command Reference for detailed information about Master user shell command syntax.

You can view reports from the Administration interface or directly from the file system.

Report permissions

The reports you can run, view, list, and delete depend on the permissions attached to your role. The contents of the reports also depend on your permissions. For example, if the administrator generating the report has access only to their group, then only data from that group is pulled into the report. Administrators with the superuser role can launch and view any report.

When you launch reports from the Master user shell, you can create and view any report because Master users have all permissions. Users with the superuser role can view reports created in the Master user shell using the Administration interface.

For the permissions needed to create, view, or delete reports, see Report permissions.

The auditor role contains all of the permissions required to view reports (get, list and view ). The useradmin role contains all of the report permissions for the groups available to the user administrator, except auditReport, so administrators with the useradmin role can get, view, list, create, and delete all report types for their groups, except audit reports.

Report templates

Reports are generated in PDF or CSV format, depending on the report template you choose. To see a list of all reports that Entrust IdentityGuard can generate, in the Administration interface, click Reports.

You set up the report search criteria in the Administration interface or Master user shell and generate one of these reports.

Report information

Each time you generate a report, Entrust IdentityGuard also produces a report information file. The report information file includes data such as the report run date and time, the number of records processed, and so on.

You can view the report information in the Administration interface or by opening the XML file in the report directory.

Report information files are stored in the same folder as the reports. The file extension of the report information files is md.xml. The report information file name is a concatenation of the report name plus a timestamp.

The location of these files is set in the Properties Editor property, Report Output Directory. The default location is:

●       On Windows: <$IG_HOME>\reports

●       On UNIX: $IG_HOME/reports

Note: The same Entrust IdentityGuard instance must be used to create the reports and manage and view the reports. That is, reports are not replicated or accessible across Entrust IdentityGuard instances unless you are using a file system that is shared across your Entrust IdentityGuard instances.
