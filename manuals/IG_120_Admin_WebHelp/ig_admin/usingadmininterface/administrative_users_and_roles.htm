IdentityGuard Server 12.0 Administration Guide

Administrative users and roles

To Entrust IdentityGuard, anyone who accesses the system is a user. The only difference between a regular user and an administrator is that the latter is assigned one or more administrative roles. Those roles give an administrator a set of permissions and a scope of operations (access to groups of users, for example) that a regular user does not have.

Roles can be specific to one or more groups of users, therefore, the scope of an administrator’s authority may be limited to just some of your users. Roles can be limited to a subset of all policies, therefore, the list of tasks an administrator can perform may also be limited.

If an administrator cannot perform a task, the related features of the Administration interface are hidden or unavailable.

When you install and initialize Entrust IdentityGuard for the first time, you are asked to create the first administrator. You can do this during installation or later, as a master user. For more information about creating the first administrator as a master user, see the Entrust IdentityGuard Master User Shell Reference.

The first administrator has the superuser role. This way, the first administrator can create additional administrator accounts with any roles. After their accounts are created, administrators can log in to the Administration interface.

When you upgrade Entrust IdentityGuard, your previously defined administrators remain intact and available. You may need to adjust their roles to add permissions related to new features.
