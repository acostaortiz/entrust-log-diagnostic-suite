Entrust® IdentityGuard Server Release 13.0

Documento de Referencia Oficial de Notas de la Versión, Novedades, Requisitos de Sistema y Errores Conocidos

DOCUMENT ISSUE 1.0 — DIC 2020

1. Nuevas Características y Mejoras (New Features)

Integración con CAs adicionales a través de Entrust CA Gateway (IDG-12004)

IdentityGuard 13.0 se integra con Entrust CA Gateway, permitiendo el uso de cualquier Entidad Certificadora (CA). Se ha certificado formalmente la integración con Microsoft Active Directory Certificate Services (Microsoft CA).

Migración de Framework CXF 3.3.5 en reemplazo de Axis 1.4 (IDG-2451)

Se reemplazó Axis 1.4 por Apache CXF 3.3.5 para resolver vulnerabilidades de seguridad. Nota de Compatibilidad: CXF utiliza WSS4J 1.6 en lugar de WSS4J 1.5.x, lo que requiere actualizar clientes WS-Security antiguos.

Visualización Mejorada de Cuentas y Autenticadores Bloqueados (IDG-13095)

La consola de administración resalta las fechas de desbloqueo automático en ROJO si están vigentes (bloqueado) o en VERDE si ya expiraron (desbloqueado).

Soporte para HTTP Strict Transport Security - HSTS (IDG-12030)

El Editor de Propiedades permite activar HSTS para proteger contra ataques de degradación TLS (SSL stripping). Al activarse, las cabeceras HTTP fuerzan HTTPS en el navegador.

2. Cambios Importantes y Compatibilidad Descontinuada

⚠️ ATENCIÓN SOBRE PLATAFORMAS DESCONTINUADAS:
  • Plataformas UNIX Descontinuadas: Se elimina el soporte para Solaris y AIX. Entrust IdentityGuard 13.0 se ejecuta exclusivamente en Linux (RHEL 7.x/8.x 64-bit) y Windows Server (2012 R2, 2016, 2019 64-bit).
  • Servidores de Aplicación Descontinuados: Se elimina el soporte para IBM WebSphere y Oracle WebLogic. Solo se soporta el servidor embebido Apache Tomcat 8.5.57 con AdoptOpenJDK 11.0.8_10 (64-bit).
  • Herramientas Retiradas: Se retiraron los ejecutables legados igclean.exe e igcustomize.exe.

3. Correcciones de Errores Relevantes (Fixed Issues)

  • IDG-10081 / IDG-11135: Corregido el mensaje engañoso "Connection test failed Cause: null" al verificar el RDN de políticas en Active Directory durante la instalación en Windows.
  • IDG-13119: Restricción corregida para que el comando Authenticate Smart Credential solo permita credenciales móviles push y no tarjetas físicas de plástico.
  • IDG-13117 & IDG-12118: Corregida la verificación de bloqueo en comandos de administración para tokens Soft y Smart Credentials tras ventanas de auto-desbloqueo.
  • IDG-12029: Corregido el manejo de la política "Disable Challenge Retention" en tokens Challenge/Response (TOKENCR).
  • IDG-11476: Agregado registro detallado de logs si la contraseña del keystore SAML o clave privada es incorrecta en el inicio del servicio.

4. Errores Conocidos y Remediaciones Técnicas (Known Issues)

IDG-14962: Fallo al Inicializar Réplica desde Backup Completo

Síntoma: Al crear un nodo Réplica en Windows usando un backup completo del nodo primario, la inicialización falla.
Solución: Utilizar siempre un backup parcial generado desde el nodo primario para inicializar réplicas.

IDG-11176 / IDG-13717: Excepción en Linux por Fuentes Faltantes (AdoptOpenJDK 11)

Síntoma: Fallos al generar informes y Smart Credentials en Red Hat Linux.
Solución: Ejecutar en terminal como root: yum install fontconfig y reiniciar el servicio identityguard.

IDG-11529: Errores de Conexión a Base de Datos tras Actualización a Java 11

Síntoma: Incompatibilidad del driver JDBC tras migrar a AdoptOpenJDK 11.
Solución: Actualizar los drivers JDBC de la base de datos (p. ej. Microsoft SQL Server Driver o Oracle JDBC) compatibles con Java 11.

IDG-15116: Error de Flujo de Certificado en Credenciales Móviles PIV/PIV-I

Log: Caused by: com.entrust.idcard.encode.EncodingException: Invalid 'key backup' certificate stream policy setting...
Solución: Habilitar la opción "Archive subject's encryption private key" en la plantilla PIV de Microsoft CA o seleccionar la plantilla PIV-C.

IDG-14983: Fallos en Entrega OOB SMS por TLS 1.2

Síntoma: Fallo al enviar SMS de un solo uso (OTP) si la pasarela externa requiere TLS 1.0/1.1.
Solución: Entrust 13.0 exige TLS 1.2 por defecto. Configurar el gateway externo para soportar TLS 1.2 o degradar la versión según la Guía de Administración.
